# 工作表：對「情境對比縮窄法」本身做分析

說明：以下以筆記中的方法（抽象、一般解法、瓶頸、縮窄、差異配對、調整、泛化、硬湊檢驗、目標一致）為工具，分析對象是該方法本身。第 9 步是以推理做的拿掉檢驗，筆記中並無實證 ablation，結論屬推論。

## 1. 起點（待驗證假設）
H0：「這個方法是：先把具體問題抽象成一般類別，拿一般解法當基線，找出具體情境與一般情況的差異，用差異補上基線的瓶頸，得到情境調整解。它最適合『一般解法可用但在此情境下不是最佳』的問題。」
這是假設，不是定論（筆記三也要求把初始描述當假設）。

## 2. 抽象：它屬於哪一類方法？
類別：「以既有解為基線、依情境做適配的問題重構與解法調整方法」，即基於基線的情境適配式創意問題解決。
更上位：問題界定／重表徵（problem reformulation）。

## 3. 一般解法：這一類有哪些既有方法？
| 方法 | 做法 |
|---|---|
| 案例推理 CBR | 檢索相似案例，依差異修改 |
| 類比推理 | 從遠域類比借結構 |
| TRIZ | 矛盾矩陣與發明原則 |
| 一般問題重述 reframing | 換角度重述問題 |
| 資源導向推理（如資源盤點） | 列出可用資源再組合 |
| 分解／規劃 | 拆成子問題逐個解 |
| 問題診斷（五個為什麼等） | 追根因 |
| 直接 LLM／CoT／Self-Refine | 直接生成並自我修正 |
| 設計定著緩解 | 刻意跳出原有方案 |

## 4. 瓶頸：各方法的限制
- CBR：只比案例相似度，不要求明確指出「差異」去對應「瓶頸」；容易照搬。
- 類比：結構映射不保證能解決具體瓶頸，且常無基線可比。
- TRIZ：偏技術矛盾，不吃情境中的在地資源與基礎設施。
- Reframing：沒有約束，容易換說法而不換內容，也可能漂移目標。
- 資源推理：不知道哪個資源與哪個瓶頸相關，列了不一定用得上。
- 分解／規劃：沿用原問題表徵，不質疑問題設定。
- 診斷：找出根因但不產生調整後的方案。
- 直接 LLM：傾向給一般解，忽略具體情境的獨特條件。
共同限制：沒有一個機制同時要求「有基線、有可名的瓶頸、有可驗證的情境差異、差異真的對得上瓶頸」。

## 5. 向下縮窄：沿不同維度加條件，看何時開始比既有方法好
維度：人、地點、時間、行為、限制、在地資源。
| 層級 | 條件 | 是否優於既有方法 |
|---|---|---|
| P0 | 山區無人機搜尋（一般） | 否，一般解（固定基地）已夠好 |
| P1 | 加「地點：有深入山區的運輸線」 | 開始出現可用差異 |
| P2 | 再加「基地與搜索區距離是主要耗損」 | 是，瓶頸與差異同時成立 |
| 反例 | 只加「人：高中生」「時間：夏天」 | 否，沒有新資源或新限制進入問題 |
結論：開始優於既有方法的情境，是「既有解仍可用，但存在可命名的瓶頸，且情境中有可重新詮釋的資源」。重點是既有解非最佳，而不是失效。

## 6. 差異與配對
| 情境特點 | 補上的方法元素 | 補上的限制 |
|---|---|---|
| 一般解法已存在 | 一般解法基線 | 直接 LLM／reframing 沒有比較對象 |
| 瓶頸可命名 | 瓶頸分析 | 資源推理不知用在哪 |
| 情境與一般類別有可指認差異 | 情境差異比較 | CBR／類比不要求差異 |
| 差異是資源、基礎設施或約束 | 差異到瓶頸的配對（含資源重詮釋） | 類比與 TRIZ 配不到在地條件 |
| 目標固定 | 目標一致檢查 | reframing 的目標漂移 |

## 7. 調整：為該情境調整的版本
1. 固定原始目標 G。
2. 把初始問題當假設，抽象成一般問題類別。
3. 取一般解法作基線，列出基線瓶頸 L。
4. 比較具體情境與一般類別，列出差異 D（新約束、被忽略的約束、可用資源、改變的假設）。
5. 配對：D 是否能消除或降低 L；不能就換維度再縮窄。
6. 依配對結果調整基線，必要時重新詮釋資源。
7. 以「拿掉差異後方案是否仍成立」檢查硬湊；以 G 檢查目標一致。
8. 通過後才交給下游執行。

## 8. 向上泛化：求 P*
逐步移除條件（沿用筆記的鐵路例子，並推廣到其他例子）：
- 「阿里山、林業鐵路、無人機搜救」→「有鐵路深入山區的搜救」：仍優（差異＝可移動深入路線）。
- →「有固定運輸路線深入搜索區的搜救」：仍優。
- →「有可移動補給載具的廣域搜救」：仍優。
- →「基地與作業區距離是主要損耗的任務」：仍優（泛化到物流、巡檢）。
- →「一般山區無人機搜尋，無任何可重新詮釋的資源」：優勢消失。
- 非搜救的例子（SRE「加機器」、Coding「優化 function」、Support「退款壞了」）：表面問題是假設，真正瓶頸在情境差異中；方法在「基線可名＋情境差異可查」時仍有用，但此時它接近診斷，優勢變小。
P*：一般解法已存在且可用，但在具體情境下因某個可命名瓶頸而非最佳，且該情境含有可重新詮釋的資源、基礎設施或約束，足以對上瓶頸的任務。邊界：差異無法對上瓶頸、或根本沒有基線時，優勢消失。

## 9. 硬湊檢驗：逐一拿掉元素（在 P* 上比既有方法如何）
| 拿掉的元素 | 拿掉後 | 判定 |
|---|---|---|
| 一般解法基線 | 沒有比較對象，無法判斷「更好」，退化成 reframing／直接生成 | 核心 |
| 瓶頸 L | 差異沒有對應目標，退化成資源盤點 | 核心 |
| 情境差異 D | 退化成直接 LLM 或對一般解加標籤 | 核心 |
| 差異到瓶頸的配對（含資源重詮釋） | 退化成類比或 CBR，差異只被列出不被使用，即硬湊 | 核心 |
| 調整（依配對改解法） | 只有分析沒有方案，變成診斷 | 核心 |
| 目標一致檢查 | 方案可能漂移成解另一個問題；在 P* 上可能得到「更新穎但沒解原問題」的解，對有效性是退步 | 核心（防護） |
| 抽象成一般類別 | 難以得到基線，但已有基線時可直接用；可併入「基線」元素 | 併入基線 |
| 向下逐步縮窄的迴圈 | 直接比較具體與一般也能找到 D；只是搜尋策略 | 非核心（可選） |
| 向上泛化迴圈 | 不影響在 P* 上的解，只決定 P* 邊界 | 非核心（範圍工具） |
| 形式化的 U 與 Advantage 計算 | 筆記自述未解（U 如何定義） | 非核心（未驗證） |
骨架：基線、瓶頸、情境差異、配對、調整、目標一致（6 個）。

## 10. 目標一致性
第 1 步問「方法是什麼、最適合什麼問題」。結論給出骨架（第 9 步）與 P*（第 8 步），並寫出不適用情形，與 H0 對應，且 H0 的「非最佳而非失效」「初始描述是假設」兩點都保留。限制：筆記無實證，P* 與核心判定為推理結論。
