# 雲端驗證計畫（先寫計畫，再執行）

日期：2026-11-07。基準版本：0dbea6a。執行者：Codex。

原目標：驗證 thinking/19 所列的 A（需求偏移、逐步確認、session 管理）與 B（審不完、事後發現故障、AI 大量寫規則）。

## 資料可得性與可完成的範圍

- 雲端沒有使用者原電腦的 Claude JSONL；先前執行 validate_problem.py 已因缺資料結束。
- Personal Context 檢索也沒有取得相關歷史原始對話或工具 trace。
- 本輪自主完成兩部分：量測器的受控校準，以及目前可見對話的個案核對。
- 不把模擬紀錄冒充歷史對話；不從缺資料推出事件為零；不宣稱估計了實際發生率。
- 本輪不能完成歷史用量 A/B 的群體比較，亦不執行付費模型評分。

## 事先固定的量測與判準

1. 對 validate_problem.py 的變更指令判定、規則寫入判定與文字訊號各建正反例；期望值在執行前固定。
2. 指令都是資料字串，不會執行。變更意指指令確實要求改變系統；只讀、dry-run、語法檢查不算。
3. 檢查整體 CLI 對明確有時間的有效紀錄、無資料、跨期、重複紀錄、混合時間缺失、工具失敗的行為。
4. 保存每例輸入、預期、實際與錯誤。不因看過結果而刪除失敗案例。
5. 這是針對邊界的刻意取樣；通過率只能代表這組案例，不能代表真實準確率。
6. 原量測器不修改，避免校準時更改受測對象。這輪輸出是採用與修正決策的證據。
7. 執行 repo 交接指定的 guard 回歸及 kit 檢查；它們與 A/B 是否成立是不同問題。

只記錄可核對的原句與助理行為，區分觀察與解釋。不替片段補造時間、工具 trace 或 session 並行資訊。這是個案，沒有隨機抽樣、獨立盲評或介入對照。
