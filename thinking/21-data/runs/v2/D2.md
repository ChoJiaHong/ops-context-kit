### Analysis
Diverge (26 candidates): 1 wrong kube context or AWS profile; 2 agents hold the human's full admin credentials; 3 two sessions mutate one release, state or host; 4 overlapping edits across worktrees; 5 prefix-based permission rules miss pipes, scripts and ssh payloads; 6 approval prompts scattered across windows; 7 secrets read into context and transcripts; 8 "done" declared before sync or rollout succeeds; 9 imperative fixes reverted by GitOps or never codified; 10 no undo for kubectl patch or host edits; 11 long tasks lose position after compaction or crash; 12 safety hooks fail open; 13 memory files go stale; 14 CLAUDE.md, AGENTS.md and Cursor rules diverge; 15 huge plan/log output floods context; 16 cannot find which session changed X; 17 audit logs show the human, not the session; 18 polling waits burn tokens; 19 freezes and on-call state invisible to agents; 20 parallel sessions duplicate investigations; 21 repeated corrections never become rules; 22 multi-repo changes need ordered PRs; 23 review bottleneck for agent PRs; 24 topology rediscovered every session; 25 tool-version mismatch; 26 worktree bootstrap cost (terraform init, helm dependencies).

Converge. The situation's distinctive mix is live, shared, high-blast-radius targets plus many concurrent, lightly watched sessions; problems that exist because of that mix rank highest. Dropped as largely solved: 25 (mise/asdf), 23 (Atlantis, Argo CD diff previews), 26 (worktree managers), 18 (background tasks), 14 (symlinks, rule-sync tools), 15 (output-to-file truncation, partly). Dropped as lower value: 20, 21, 22, 24; 13, because stale facts usually fail loudly on the first command; 19 becomes an input to the classifier's policy. Merged: 1+2+17, since one credential broker fixes blast radius, wrong target and attribution together, and 16 mostly falls out of that attribution; 3+4 into one lease registry keyed by resource, whether touched live or in code. Most survivors share one substrate, a deterministic parser mapping a command to (verb class, targets, environment); building it once makes leases, approvals, pre-images and ownership checks cheap. Ranking: prevent irreversible harm first (1, 5, 3, 7), then make "done" trustworthy (8, 9), then attention (6), recovery (11, 10), and guard reliability (12), last only because it protects the others rather than adding capability.
### Items
I1: Every parallel agent runs with the engineer's full admin credentials and a shared global kubeconfig/AWS profile, so one session's context switch or mistake hits the wrong cluster or account, and audit logs cannot tell which session did it. || Session credential broker. A SessionStart hook reads the scope declared at launch (AGENT_SCOPE=staging:payments:write). A local broker mints short-lived credentials: STS AssumeRole with a scoped session policy and RoleSessionName=agent-<session-id>; an ephemeral ServiceAccount agent-<session-id> with a RoleBinding plus TokenRequest token; Vault dynamic secrets. It writes session-private KUBECONFIG/AWS_CONFIG_FILE containing only that target, exported via CLAUDE_ENV_FILE. Elevation is an MCP request the human approves (TTL 15 minutes). SessionEnd revokes everything; cloud and kube audit logs name the session.
I2: Permission rules match command prefixes, so `kubectl apply -f`, pipes into xargs, `bash script.sh`, `ssh host '...'`, loops and Makefile targets either slip through or get blanket-denied, and rules ignore which environment a command actually targets. || Infra-aware command classifier as a PreToolUse hook. It parses Bash with a real shell parser (mvdan/sh), recursing into `bash -c`, ssh payloads, xargs, loops, and referenced scripts or Makefile targets; `-f` manifests are opened for kinds and namespaces. Each simple command maps through a per-CLI verb table (kubectl, helm, terraform, aws, gcloud, systemctl) to read/mutate/destroy, with its target resolved from flags, env and kubeconfig. A policy matrix (verb by environment) returns allow, ask or deny; anything unparseable asks.
I3: Parallel sessions on one project collide: two run `helm upgrade` on the same release, one restarts a deployment another is debugging, or both change the same Terraform resource in separate worktrees, discovered only at merge or during an outage. || Resource lease registry: a SQLite-backed service shared by all sessions. Targets from the classifier (cluster/namespace/kind/name, Helm release, state-file+address, host) become lease keys. A mutating call acquires a lease tagged with session id and task; if another session holds it, the hook denies with 'held by session 7 (rotate certs) since 14:02'. Edits to .tf or values files take soft leases on the resources they define and warn overlapping sessions via additionalContext. Leases expire on SessionEnd or missed heartbeat.
I4: Infra work constantly reads secrets—`kubectl get secret -o yaml`, `terraform output`, `vault read`, env dumps, `.tfvars`—so credentials enter model context, provider logs and local transcripts; deny-rules on file paths miss command output. || Secret placeholder filter. A PreToolUse hook rewrites Bash commands (updatedInput) to run under pipefail through `sieve`, which detects Kubernetes Secret data, base64-wrapped credentials, PEM blocks, cloud keys, JWTs, Terraform sensitive outputs and high-entropy strings, stores them in the OS keyring per session, and prints placeholders like {{sec:prod/db/password#a1f3}}. When a later command contains a placeholder, the hook substitutes `$(sieve get a1f3)`, so the agent uses values it never sees. A SessionEnd transcript scan is the backstop.
I5: Agents declare 'done' when the PR merges or `helm upgrade` returns, but Argo/Flux sync, rollout, canary analysis or the next scheduled Terraform plan fails minutes later, after the session has ended and nobody connects the failure to it. || Outcome watcher. A Stop hook inspects the session's tool log for deploy-type actions (push to a GitOps path, helm upgrade, terraform apply, kubectl rollout) and registers watch specs: Argo app health/sync for the touched path, rollout status, post-apply `terraform plan -detailed-exitcode` returning 0. A daemon polls them out of band for up to N minutes; on failure it runs `claude -p --resume <session-id>` with the failure evidence so the original context diagnoses it, and notifies the human.
I6: Agents fix things imperatively—`kubectl patch/scale/edit`, `ssh` edits to config files—on objects owned by Argo/Flux or Ansible; the fix is silently reverted by self-heal, or survives as undocumented drift the repos never learn about. || Ownership guard with a codify-or-justify gate. Before a mutating kubectl call, the PreToolUse hook fetches the target and reads ownership markers (argocd.argoproj.io/tracking-id, Flux kustomize labels, meta.helm.sh/release-name, managedFields managers), then asks with 'owned by Argo app X (repo/path), selfHeal on: this will revert'. For hosts it checks a generated list of Ansible-managed paths. At Stop, any imperative mutation without a matching IaC diff in the session blocks completion until codified or justified in the summary.
I7: With eight sessions open, permission prompts sit unseen in background windows for minutes, while the engineer rubber-stamps whichever prompt is in front of them, with no sense of which pending action is risky. || Cross-session approval inbox. Instead of returning 'ask', the PreToolUse hook posts the call (session task, cwd, command, classifier verdict, target environment, diff or plan summary) to a local queue and long-polls for a decision, with the hook timeout raised to an hour. A TUI/menubar lists pending items from all sessions sorted by risk, then wait time; read-only and dev items can be batch-approved, while prod mutations require typing the context name. Approvals can become session-scoped rules.
I8: Long multi-step operations (drain-upgrade-uncordon across 30 nodes, multi-stage migrations) break on compaction, crashes or handoff; the next session trusts a stale todo list or the summary, not actual infrastructure state, and repeats or skips half-done steps. || State-checked runbook ledger. Before executing, the agent writes the plan as a YAML ledger in the repo: each step has an action plus precondition and postcondition shell checks (`kubectl get node n7 -o jsonpath='{.spec.unschedulable}'`). `ledger done 12` succeeds only if the postcondition passes. On SessionStart or resume, a hook re-runs every check against live state and injects 'steps 1-11 verified; 12 half-done: node drained, kubelet not upgraded; continue at 12b'. Other agents run `ledger status`.
I9: Imperative changes made during debugging or incidents—`kubectl patch/scale/delete`, edited files on remote hosts, `aws` CLI updates—have no recorded prior state, so reverting an agent's half-right fix means reconstructing what was there from memory. || Pre-image journal. For each classified mutation, the PreToolUse hook first snapshots the targets: `kubectl get -o yaml` (stripped of status/resourceVersion), `helm get values/manifest` with revision, `ssh host 'cat path; stat'` for files the payload writes, or the matching `aws describe-*`. Snapshots go to ~/.agent-journal/<session>/<seq>/ with the command. `agent-undo <session> [--to seq]` replays inverse operations in reverse order, showing a diff against live state first and refusing if live state no longer matches the recorded post-image.
I10: Safety hooks fail open: a missing jq, Python venv change, slow API call hitting the timeout, or a malformed settings merge makes the guard error out non-blockingly, and the agent keeps executing with no visible sign protection is gone. || Guard harness. Every guard runs under `guardrun`, which converts crashes, invalid JSON and its own deadline (set below the hook timeout) into deny (exit 2). A SessionStart canary reads the merged hook configuration, feeds each PreToolUse hook synthetic payloads for known-bad probes (`kubectl --context prod delete ns x`, `terraform destroy`) and expects deny; any pass turns the statusline red and arms a dependency-free sh fallback hook that denies mutations. The same corpus runs in CI on agent-config changes.
