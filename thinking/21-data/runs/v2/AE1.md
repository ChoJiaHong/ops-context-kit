### Analysis
Evidence themes: quota and cache drain (about a dozen issues), unreliable long tasks (regressions, hangs, lost history, compaction), permissions that misparse compound bash, multi-account switching, and juggling parallel windows. For an ops engineer each is amplified because agent actions land on shared, stateful, external systems rather than a local file tree.

1. Isolation stops at the filesystem. Worktrees, subagents and sandboxes isolate files. Infra risk lives in kube contexts, cloud profiles, Terraform state, Helm releases, GitOps-owned objects and SSH hosts. Nothing binds a session to a target, nothing coordinates parallel sessions on the same live resource, and permission rules match strings, not meaning (a delete hidden in ssh host 'sh -c ...').

2. Trust in delegated work. The engineer cannot watch twenty sessions. Agents claim success without evidence, approvals are given on one plan while a different one is applied, and after compaction or handoff the agent forgets what it already changed. The evidence that instructions are ignored (comment verbosity, banned words) says the fix is deterministic checks in hooks, not more CLAUDE.md prose.

3. Token economics. Infra commands produce enormous low-signal output. With short cache TTLs and many parallel sessions, this is a large and controllable share of quota burn; shaping output at the source beats any after-the-fact usage report.

4. Secrets and fleets. Ops agents touch credentials and many hosts daily; transcripts persist locally; SSH loops hang on prompts.

Existing partial answers: session managers (claude-squad style), static allowlists, Terraform state locks (held only during apply), Atlantis-style plan/apply (CI only), OPA/conftest (files, not live commands), ccusage-style reports (after the fact), Ansible (output not shaped for agents). The gaps sit where agent intent must be joined to live infrastructure state at the moment of a tool call.

Ranking: probability x blast radius first (wrong target, concurrent mutation, unchecked commands), then silent partial work (evidence, plan binding, journal), then daily cost and friction.

Design choice: every tool is a hook (PreToolUse with updatedInput/deny, Stop with block, SessionStart context injection), a small local daemon over a Unix socket, or an MCP server where state is needed. CLI wrappers placed first on PATH give Codex and Cursor sessions the same protections, and the verb/target classifier from I3 is a shared library reused by I1, I2 and I6.
### Items
I1: Kubeconfig current-context, AWS_PROFILE and gcloud config are global: a human or another session switches them and an agent silently runs against prod or the wrong account. Multi-account switching is a top request. || Session target pinning. A SessionStart hook reads a target declaration (env var or .task/target file) and writes a session-private KUBECONFIG copy, AWS profile and CLOUDSDK_CONFIG directory, exported via CLAUDE_ENV_FILE. A PreToolUse hook denies context-switching commands (kubectl config use-context, --context/--profile naming other targets) and anything resolving outside the pin. The statusline shows the pinned target, red for prod. Wrappers on PATH give Codex/Cursor the same behavior.
I2: Parallel sessions (worktrees isolate only files) mutate the same cluster namespace, Helm release, Terraform state or host concurrently; state locks cover only seconds of apply, not the minutes between an agent's plan and its apply. || Local daemon "infra-lease" plus PreToolUse hook. The hook maps each command to resource keys (kube context/namespace, Helm release, Terraform backend+workspace, SSH host). Mutating commands need a lease, reads do not; a lease starts at the first plan/diff and lasts until SessionEnd, explicit release or an idle TTL. Conflicts are denied with a message naming the holding session, its task and last command, so the agent waits or switches work.
I3: Permission rules match command strings, so compound commands, ssh host '...', sh -c, xargs, kubectl exec hide destructive actions, while harmless cd && chains trigger prompts. Rules cannot express "read anything, mutate only staging." || PreToolUse policy engine. Parse the command with tree-sitter-bash, recursively unwrap ssh, sh -c, xargs, env, sudo, kubectl exec and heredocs into simple commands. Classify each with a per-CLI verb table (kubectl get=read, apply=mutate, delete=destroy; terraform plan/apply/destroy; helm; aws by Describe/Get/List prefixes) and attach its resolved target. Evaluate a policy file (class x environment -> allow/ask/deny); unparseable constructs default to ask. Deny messages name the offending component.
I4: On long delegated tasks agents report "deployed and healthy" after partial work or without checking; the human cannot watch dozens of sessions and finds gaps later. Instructions to verify are ignored like other CLAUDE.md rules. || Done-gate. At task start the human or agent writes acceptance checks to .task/checks.yaml as runnable probes: kubectl rollout status, argocd app health, terraform plan -detailed-exitcode returning 0, curl endpoints, PromQL thresholds. A Stop hook runs them itself; any failure returns decision=block with the failing output, forcing the agent to continue. Checks are frozen after human review so the agent cannot weaken them; passing output becomes an evidence report attached to the PR.
I5: Humans approve a terraform plan or helm diff, then the agent runs a fresh apply that differs (state moved, files edited, -auto-approve). Approval attaches to a chat message, not to the exact change. || Plan-binding gate. A PreToolUse hook rewrites terraform plan to write -out=<task>.tfplan and requires helm diff before helm upgrade, renders a summary (changed addresses, destroys highlighted) and records its SHA-256. The human approves that hash from a CLI or phone notification. terraform apply is denied unless it names an approved plan file with matching hash; helm upgrade passes only if a re-run diff hashes identically.
I6: After compaction, crashes, rate-limit stops or handoff to another session, nobody knows exactly which hosts, resources and files were already changed; the agent repeats or skips steps, and rollback is guesswork. || Mutation journal. A PreToolUse hook snapshots each mutation's target first (kubectl get -o yaml, helm get values, terraform state pull, remote file checksum); PostToolUse appends command, target, exit code and snapshot path to an append-only per-task JSONL outside the transcript. SessionStart with source compact or resume, and any new session joining the task, gets an injected "already done" table. "journal undo N" proposes inverse operations from snapshots for review.
I7: Infra commands emit huge low-signal output (terraform plan, YAML with managedFields, logs, describe); it fills context, forces early compaction and multiplies cache-creation cost across parallel sessions, a major quota drain. || Output shaper. A PreToolUse hook rewrites known commands via updatedInput to pipe through "shape <kind>", which saves raw output to disk and prints a bounded digest: terraform plan -> per-address actions and counts; kubectl yaml -> managedFields, last-applied and status noise stripped; logs -> template-clustered lines with counts and first/last timestamps; JSON -> inferred schema plus samples. Each digest ends with the raw-file path for targeted grep. Exit codes are preserved with pipefail.
I8: Agents hotfix live objects with kubectl edit/patch/scale that Argo CD or Flux silently reverts, or that drift from Git; they also edit the wrong repo or overlay because live-object-to-source-file mapping is undocumented. || Ownership resolver (MCP tool plus PreToolUse hook). For a target object it reads tracking labels/annotations (argocd.argoproj.io/tracking-id, kustomize.toolkit.fluxcd.io/name, meta.helm.sh/release-name), fetches the owning Application, Kustomization or HelmRelease for repo, revision and path, renders it (kustomize build, helm template) and maps the offending field back to a source file:line by searching the unrendered sources for its value. Direct mutations of owned objects are denied with "edit <repo>/<file>:<line> instead" plus a break-glass flag.
I9: Ops agents read Kubernetes Secrets, Terraform state/outputs, Vault and .env values in plain text; they land in local transcripts, API requests, and sometimes commits or PR text. || Secret placeholder broker. All shell commands are rewritten (PreToolUse updatedInput) to pipe through a redactor that recognizes secret shapes (Secret .data, Vault responses, sensitive Terraform outputs, known token formats, high-entropy strings) and swaps each value for a stable placeholder like ⟦sec:ns/name/key#a1b2⟧, keeping the mapping in the OS keyring. When a later command contains a placeholder, the hook routes it through a wrapper that substitutes the real value inside the subprocess only. The model uses secrets without seeing them.
I10: Agents SSH into many hosts one at a time with ad-hoc loops; interactive prompts, pagers and sudo passwords hang sessions for minutes, output from fifty hosts floods context, and nothing enforces canary-first rollout or stop-on-error. || Fleet-exec MCP server. Input: an inventory selector (Ansible inventory, Consul or cloud tags), a command and mode read/mutate. It runs over SSH with BatchMode, no TTY, stdin closed, PAGER=cat, DEBIAN_FRONTEND=noninteractive, sudo -n and hard per-host timeouts. Mutations hit one canary, then widening waves that halt on first error. Results come back grouped: identical outputs collapsed under host lists, outliers in full, plus an exit-code histogram. A policy hook blocks raw ssh for inventory hosts.
