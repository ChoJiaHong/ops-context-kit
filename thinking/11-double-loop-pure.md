# 11 雙向迴圈

2026-11-07 與作者確認的最終抽象。

## 定義

**雙向迴圈：在兩個相反的方向之間來回移動。**

- **只規定一件事**：方向一定是兩個，而且彼此相反。
- **為什麼是兩個**：只往一個方向走，終究會走到盡頭而停下。有兩個相反的方向，一個方向的終點就是另一個方向的起點，所以能持續移動。
- **其他一切由執行的 AI 決定**：兩個方向是什麼、什麼時候轉向、什麼時候停、什麼算進展、產出什麼、要不要問人。

這個模型是給大型語言模型（例如 Claude Code）跑的。條件是不確定的，所以模型不寫規則，只給一個能持續移動的結構。

## 方向的例子（不是規則）

AI 可能依情況選出這些方向，也可能選別的：

| 兩個方向 | 適合的情況 | 出處 |
|---|---|---|
| 抽象 ↔ 具體 | 整理概念，或把概念做成能用的東西 | 本研究自己的路徑（見下） |
| 問題 ↔ 解法 | 問題還沒界定清楚，要邊試解法邊重新理解問題 | 設計研究的問題與解法共同演化（Dorst 與 Cross，2001） |
| 加條件 ↔ 減條件 | 找出一個做法的適用範圍 | [09](09-double-loop.md)；機器學習的版本空間 |
| 找出失效 ↔ 造出新解 | 產生新工具：在現有工具失效的地方造出局部解，再泛化成工具 | guard 補不完 → 「隔離靠權限」（[10](10-claude-md.md)） |
| 發散 ↔ 收斂 | 找新點子，再挑出可行的 | 一般創意方法 |

## 抽象的路徑

| 版本 | 文件 | 形式 | 結果 |
|---|---|---|---|
| 原模型 | [00](00-original-notes.md) | 創新縮窄法：情境差異 → 新解法 → 優勢範圍 | |

| 有範圍的主張 | [09](09-double-loop.md) | 主張 + 向下／向上迴圈 + 硬湊檢驗 + 證據等級 | 試驗 1（guard.py） |
| 抽象 ↔ 具體 | 本篇 | 向下具體化到能檢驗，向上抽象化到再拿掉就不成立 | 作者接受，要求繼續抽象 |
| 判定 + 加減條件 | 本篇 | 不成立就加條件、成立就減條件，停在邊界 | 作者否定：只能找邊界，不能產生新東西 |
| 產生新工具 | 本篇 | 向下找失效 → 在失效點造局部解 → 向上泛化成工具 | 作者否定：不要明確的規則 |
| 問題 ↔ 解法 | 本篇 | 在問題和解法之間來回，判斷全交給 AI | 作者否定：連方向也交給 AI |
| **雙向迴圈** | 本篇 | 兩個相反的方向，其他全由 AI 決定 | **最終** |

被否定的版本沒有丟掉，它們變成了上面「方向的例子」。

這段研究本身也在走雙向迴圈：06 往抽象走，08、09 往具體走（解外部問題、檢驗 guard），本篇再往抽象走；下一次往具體走，是讓 Claude Code 實際跑它。
