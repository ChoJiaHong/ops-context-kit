# 雙迴圈：檢驗一個有範圍的主張

## 什麼時候用

- 某個做法即將變成規則、預設值、hook、共用腳本或標準流程。
- 某個做法在新情境失敗了。
- 一次性的決定不要用。

## 0. 寫主張紀錄

在 `claims/<名稱>.md` 寫下：

```
G（目標，之後不准改）：
Sₑ（不做任何新東西時的現成做法）：
S（要檢驗的做法，附檔案路徑或版本）：
C（目前假設成立的條件，一行一條）：
評估器（怎麼自動判定一個反例是真的；沒有 E3 以上的評估器就先停下來告訴使用者）：
威脅模型／範圍（哪些反例算數）：
```

G、威脅模型若不明確，先問使用者，這兩項不能由你決定。

## 1. 向上：派獨立的反駁者

用 subagent，只給它：主張紀錄、S 的檔案、評估器的用法、已知的「不涵蓋」清單。不要給你的推理或你預期的弱點。指示：

> 一次放寬 C 的一個條件，找出 S 違反 G、或不再勝過 Sₑ 的具體輸入。每個反例給：輸入、依 G 應該的結果、放寬的是哪個條件、為什麼在範圍內。最多 N 個。先用評估器自己跑過。

## 2. 驗證：自己重現每個反例

- 用評估器實際執行，只接受重現成功的（E4／E3）。
- 標嚴重度：違反 G 的核心（嚴重）／多餘的打擾或成本（輕微）。
- 標是否在範圍內、是否已被既有測試涵蓋。

## 3. 向下：處理每個重現的反例

| 處理 | 條件 | 要留下的東西 |
|---|---|---|
| 修 S | 能局部修好，且既有測試不退步 | 修改 + 回歸測試 |
| 縮 C | 修不了或修的代價太高 | 在 S 的說明裡寫「不涵蓋：…」 |
| 改判 | 認為反例不算數 | **交給使用者決定**，附反例與理由 |

不准改 G 來躲反例。

## 4. 下一輪或停止

- 把本輪結果寫進主張紀錄，再派一個新的反駁者（給它更新後的紀錄）。
- 每輪記下「由上一輪修正引入」的反例數（用上一版的 S 跑一次就知道）。修正會製造新錯誤，回歸測試不可少；解析不確定時，選擇失敗時偏安全的一邊。
- 停止：某一輪沒有新的、在範圍內的嚴重反例；或滿 3 輪；或預算用完。
- 連續兩輪嚴重反例沒有下降：停止補洞，把「S 的結構是不是錯了」當成縮 C 或換 S 的問題交給使用者。

## 交給使用者的東西

只交：主張目前的範圍（成立的 C 與不涵蓋清單）、需要使用者決定的改判項目（最多 5 個）、修改摘要與測試結果。不要轉述反駁者的全部輸出。
