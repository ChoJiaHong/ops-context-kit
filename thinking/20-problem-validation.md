## 對後續工程的具體影響

1. 在用統計決定規則前，先把量測器的「嘗試變更」「拒絕」「失敗」「結果未知」分開。成功 exit code 也不能單獨證明想要的變更已生效，仍要看回讀狀態。
2. 最近 N 天應按事件時間篩選，按 message/tool ID 去重，按完整 cwd 或明確專案 ID 分組；不只依 basename 與檔案 mtime。
3. 有工具資料缺口的來源，工具指標顯示未知。不要把 ChatGPT 文字片段轉成假 Claude transcript 後得到零變更。
4. `correct`、`stop`、`incident` 保留為候選訊號，需要人工核對；規則寫入次數更不能證明 AI 在自主制定規則。
5. 本輪不直接把 parser 補成另一個指令黑名單。指令語言的漏判問題已在 09 發現；正式量測需有原始 trace 與抽樣核對。

未修改正式分析程式、guard 或規則內容。48 例校準沒有用來推導模型或規則的效益。
