# 01 原模型評估：適合什麼、不適合什麼

結論：原模型（[00](00-original-notes.md)）是一套**創意搜尋方法**。用在找新方案、找切入點、教學很有效；用在優化、調校、除錯效果很弱。它的組成部分大多有前例，但「硬湊檢驗」和「優勢範圍」兩點比多數同類方法更好用。

以下都是思想實驗與推理，不是實測。

## 1. 它實際做了什麼

方法告訴你往哪裡看：先確認既有解法卡在哪裡，再縮小情境，直到出現一般情境沒有的條件，最後問這個條件能不能解掉瓶頸。

阿里山例子裡真正的創意跳躍，是把林業鐵路看成「移動式搜救基礎設施」。這一步是分析者自己看出來的，方法只是把他帶到看得到鐵路的位置。所以方法的上限是：**它提高你注意到某個資源的機率，但「重新詮釋資源」那一跳還是靠人的知識和想像。**

## 2. 換情境的思想實驗

| 情境 | 情境差異的性質 | 方法能做出什麼 |
|---|---|---|
| 山區搜救、地方活動、偏鄉服務 | **資源型**（鐵路、廟會人潮、在地組織） | 新方案，這是它的主場 |
| 新產品找第一批市場 | 某群人被現有產品服務過頭或沒服務好 | 切入點，以及之後可以擴張的範圍 |
| 醫院手部衛生、工安 | 多為**限制型**（人力不足、疲勞） | 多半是常見對策，除非刻意去找資源 |
| 資料庫變慢、調 CLAUDE.md | 需要**量測與回饋** | 幾乎沒有幫助：推理只會重新排列已知資訊 |
| 有專家的成熟領域 | 專家早已內化 | 邊際效益低 |

規律：情境差異裡**有沒被利用的資源**時，方法很強；差異主要是限制，或問題要靠資料校準時，方法就退化成常識。

## 3. 用來改善 agent 工作流（寫 CLAUDE.md）時

六個思想實驗：

1. **問題類型對不上一半**：ops 情境的差異大多是限制（prod、不可逆、共用狀態），推出來的是任何專家都會寫的安全規則。資源型差異（session 很便宜、系統狀態可以查、hook 是確定性的）才是方法擅長的。
2. **資訊從哪裡來**：抽象、比較、配對只會重新組織分析者已知的資訊。最關鍵的差異（你的 session 實際在哪裡出錯、多常、代價多大）只存在使用紀錄裡。實驗只有在案例來自分析者以外時才帶得進新資訊；否則就是筆記自己點出的「模型自洽」。
3. **兩個工程師**：方法的步驟是專家在腦中自動做的事。它對不熟領域的人幫助大，對專家幫助小。你熟 ops 安全，但「管理大量 AI session」是新領域，方法在後者才有空間。
4. **槓桿用在哪裡**：影響工作流的槓桿由強到弱是：模型能力、機制和工具、你交代任務的習慣、規則文字。「找最佳 CLAUDE.md」在套用方法前就把槓桿固定在最弱的一個，違反了「P₀ 是假設」。
5. **規則能改變什麼**：對能力強的模型，規則主要改變偏好型的門檻（什麼時候停、記多少）和環境事實。門檻要問你，事實要寫成檔案，兩者都推導不出來。
6. **實驗的檢定力與成本**：規則改動的效果很小，思想實驗的評分者是模型先驗，測不準；效用有雜訊時，上下迴圈會擺盪或隨意停下。

| 部分 | 對工作流 | 原因 |
|---|---|---|
| 把需求當假設、重新界定問題 | 有意義 | 套在工作流結構這一層時，資源型差異多 |
| 情境對比推導規則文字 | 邊際效益低 | 限制型差異只推出專家常識 |
| 硬湊檢驗 | 有意義 | 拿掉你的情境後仍成立的規則，模型本來就會做，可以刪 |
| 每條規則有來源、可以消融 | 有意義 | 防止 CLAUDE.md 越長越肥 |
| 形式化實驗找「最佳」 | 現在沒有意義 | 沒有你的效用權重，「最佳」沒有定義 |
| 真實失敗驅動的輕量迴圈 | 有意義 | 實驗在這裡是紀律，不是最佳化器 |

實驗結果也一致：公平條件下，用這個方法推導的規則沒有比獨立 SRE 直接寫的好（[method/round2.md](../method/round2.md)），修改後也沒有修得比專家好（[method/round3.md](../method/round3.md)）。

## 4. 是不是早就有

組成部分幾乎都有前例。筆記自己已列出問題診斷、案例式推理、類比推理、TRIZ、設計固著緩解。更接近的還有：

- **TRIZ 的資源分析**：用系統裡現成的資源解決矛盾，和「在地資源突破限制」幾乎同構。
- **Christensen 的破壞式創新**：新方案先在既有方案「可用但不是最佳」的利基站穩，再往上擴張，和「Existing Solution Non-optimality」加向上迴圈同構。
- **Geoffrey Moore 的灘頭堡策略**：先拿下一個窄市場，再延伸到相鄰市場。
- **Polya 的特殊化與一般化**：解題時先縮小、再推廣。
- **以資產為本的社區發展（ABCD）**：從地方既有資產出發，而不是從缺乏出發。

## 5. 它自己的貢獻

1. **硬湊檢驗**：拿掉在地特色，方案還成立嗎？這是一個簡單、能明確判出「不成立」的檢驗，很多地方創生提案和競賽作品都死在這一關卻沒人說破。
2. **明確的優勢範圍 P***：既往下找優勢從哪裡開始，也往上找它延伸到哪裡為止。產出的是一個問題範圍，不是一個點子，所以可以檢驗、可以擴大。

## 6. 用在哪裡最有意義

1. **教學**：高中生六問加硬湊檢驗，是很好的專題、科展、競賽引導工具，能擋掉「AI＋在地名稱」的空包彈。
2. **地方創生、在地服務設計**：資源型差異最多的領域。
3. **新創或新產品找切入點**：向下找利基、向上找擴張範圍。
4. **AI 研究**：方法本身難以宣稱是新的。比較有意義的研究問題是「顯式的情境對比，能不能降低 LLM 的解法固著」，要用外部評審或真實結果來評，貢獻會在實證和評測資料集。

不適合：優化、調校、除錯這類需要量測回饋的問題，以及已有成熟解法、專家很多的領域。

## 7. 日常怎麼用

- **寫或調 CLAUDE.md**：不用這個方法，直接用現成的規則集，出錯才改。改的方式見 [02 失敗驅動的縮窄法](02-failure-driven-narrowing.md)。
- **設計 agent 工作流的結構**：用改寫過的版本 [03 人機差異設計法](03-human-agent-design.md)。
- **卡住時**：同一類問題用各層修正都修不好，才拿出原模型重新界定問題。
