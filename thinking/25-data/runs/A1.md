## P1
Solution: Identity Egress Firewall — a local MITM proxy (mitmproxy addon) through which all agent traffic must pass. On model-API requests it replaces the account email and user-listed identifiers in the request body with a placeholder (`user@redacted.invalid`), so the model, sub-agents and the scripts they write never learn the real address. On all other egress it decodes headers, URLs and bodies and searches for the identifiers in any form (case-folded, percent/JSON/quoted-printable escaped, base64 at three offsets, hex, plus-addressed), rewrites hits in headers to the placeholder, blocks bodies with an explained deny, and logs each event. OS rules force every agent process through it (nftables uid-owner rule for a dedicated agent user on Linux; the agent sandbox's custom-proxy port elsewhere), so loopback calls and file writes are never inspected. A commit-msg/pre-push hook applies the same matcher to git.
Differs from existing: It acts on bytes on the wire, not tool-call text, so scripts Claude writes, sub-agents and encoded forms are caught; only real network egress is inspected, ending local false positives; the context scrub works at the network layer, so Team/Enterprise mod restrictions do not apply.
Needs: Local CA trusted by Node/tools (NODE_EXTRA_CA_CERTS); admin approval on managed machines; vendor tolerance of API-body rewriting. Vendor: dropping the email from context is the real fix.

## P2
Solution: permcheck — one policy, compiled per agent, and verified against the real agents. Engineers write a single policy (allow/ask/deny by tool, path and command semantics). A real shell parser (tree-sitter-bash) normalizes commands before matching: splits compounds and subshells, drops `cd` into the workspace, unwraps env prefixes, `sh -c`, `xargs` and `timeout`, and canonicalizes global flags (`git -C x commit` → `git commit`). The compiler emits each agent's native config (Claude settings.json, Codex rules plus `trust_level` entries for every repo under declared roots, Gemini policy TOML) and one enforcement hook installed at user and managed level, so subagents and skills get it too. `permcheck test` runs each installed agent headlessly in a throwaway container against a probe corpus (compounds, quoted flags, python -c, known bypasses) whose binaries are shims that only record calls, and reports intended versus actual allow/prompt/deny. It runs in CI and before every agent upgrade.
Differs from existing: Existing tools add yet another matcher with no proof it is applied; this measures what each agent version actually enforces, catching regressions (broken skip-permissions/yolo, ignored workspace policies, uninherited rules) before unattended runs stall, from one source of truth across Claude, Codex and Gemini.
Needs: Headless modes and hook APIs of each agent; a container runtime. Vendor fixes are still needed for defects it exposes, such as ExitPlanMode ignoring hook allows and mobile prompts.

## P3
Solution: Forge Shadow Bridge — a service that gives GitHub-only agents a private GitHub mirror of each GitLab, Bitbucket (Cloud or Data Center) or Azure DevOps repo, keeping the origin authoritative. Origin push webhooks mirror branches into a locked-down GitHub org where only agent branch prefixes (`claude/*`, `codex/*`) are writable. When an agent opens a mirror PR (Claude Code on the web, Codex cloud, Linear coding sessions, Claude Agent for Jira), the bridge pushes the branch to origin, opens the matching MR with ticket links and turns the mirror PR into a pointer. Review comments on the origin MR are relayed to the mirror PR as `@claude`/`@codex` mentions, which the vendors' GitHub integrations act on, and new commits flow back. Assigning a Jira, Linear or Azure Boards ticket to an "agent" user makes the bridge start a cloud session on the mirror with the ticket text via the vendor CLI.
Differs from existing: Instead of waiting for each vendor to support each forge, one bridge makes every GitHub-only agent work with any forge, including Bitbucket Data Center and Azure DevOps Server, without GitLab Premium gating, feature flags or per-vendor beta integrations.
Needs: A private GitHub org and approval to mirror code there (data residency if required); forge webhooks and API tokens; vendor cloud-session CLIs. No vendor change.

## P4
Solution: Agent State Watcher — a daemon that infers each session's state from evidence that does not depend on hooks, then alerts with escalation. Inputs: the transcripts every surface writes (Claude Code `~/.claude/projects/**/*.jsonl`, Codex `~/.codex/sessions` rollouts) and the agent's process tree. Rules: turn closed with no continuation within a debounce window → done (filters /goal continuations); error record or process exit mid-turn → failed; pending tool call with no child process and no transcript growth for N seconds → needs approval; no growth for M minutes while working → stalled. Thresholds are configurable; alerts are deduplicated. Delivery escalates with input-idle time: terminal bell or OS toast first, phone push via ntfy if unacknowledged after X minutes. For Remote SSH it runs on the remote host. The same data powers `agentlog`, a timeline with wall-clock timestamps for every message, tool call and background check.
Differs from existing: Reading state instead of waiting for hooks, it catches API-error endings and Codex approval waits, survives hooks breaking or lagging after updates, ignores /goal pseudo-completions, works alike in CLI, IDE and SSH, and adds timestamps without patching webviews.
Needs: Read access to local transcripts in undocumented formats (versioned parsers); a push service such as ntfy. Timestamps inside the vendor's own chat UI need the vendor.

## P5
Solution: Effect-based Bash file guard — hooks that judge what a shell command changed, not how it was spelled. PreToolUse on Bash snapshots the workspace into a private git index (`GIT_INDEX_FILE=.git/agent-idx git add -A; git write-tree`, plus an mtime scan for ignored paths); PostToolUse snapshots again and diffs the trees. For each changed file it checks Edit/Write permission rules and path-scoped policies, restores denied files from the pre-snapshot and tells the model to use Edit; shows the diff to the engineer via systemMessage; returns the nested CLAUDE.md and path rules for touched directories as additionalContext; and keeps every pre-snapshot as commits under `refs/agent-checkpoints` so `agent-undo` can revert any Bash edit. Read deny rules and out-of-workspace writes are enforced for Bash by an OS sandbox profile (bubblewrap/Seatbelt) generated from the same rules. A SessionStart note asks the model to prefer Edit, but nothing relies on it.
Differs from existing: Pattern blockers miss python, heredocs and new tools and fight the harness's Bash-first prompt; this catches every write route by its effect and restores diffs, path rules and undo for Bash edits instead of only refusing them.
Needs: A git workspace; PreToolUse/PostToolUse hooks with additionalContext; an OS sandbox for reads. Native /rewind tracking and dropping Bash-first steering need the vendor.

## P6
Solution: Attested credential broker — a customer-run service (container or Cloudflare Worker) holding all real secrets; cloud sessions authenticate only to it, using one network secret scoped to the broker host or, where those are unavailable (Team, CMEK), GitHub attestation: the session pushes a nonce ref through the vendor's GitHub proxy to a designated repo, and the broker verifies pusher and repo before issuing a 15-minute token bound to that repo. The broker reverse-proxies HTTP with any auth scheme (SigV4 for R2 and other S3-compatible hosts, private registries); acts as an OIDC issuer AWS, GCP and Azure trust, so sessions exchange tokens for short-lived cloud roles; tunnels Postgres, MySQL and SSH over WebSocket, injecting credentials server-side; and enforces per-repo policy with audit logs. Secrets rotate at the broker, reaching running sessions immediately. Dependency installs move from setup scripts to a SessionStart hook.
Differs from existing: Covers what network secrets cannot: non-HTTP protocols, non-AWS SigV4, keyless cloud federation, Team and CMEK orgs, mid-session changes. Unlike postern or mcp-warden it is reachable from vendor clouds and needs no engineer machine online.
Needs: Session egress to the broker host; vendor GitHub proxy allowing pushes; WebSocket support through the agent proxy (unverified). Credentials for setup scripts themselves would require the vendor.

## P7
Solution: Change-set coordinator — a GitHub/GitLab app plus CLI that turns per-repo PRs into one reviewable, mergeable unit. Any agent (multi-repo web session, Codex multi-folder, local) uses one branch name or PR label `cs/<id>` across repos and commits a `changeset.yaml` (repos, dependency order, contract notes). The app finds every PR in the set, posts a shared status comment and a combined diff page, and runs a joint CI job that checks out all branches together and builds downstream repos against upstream branches via workspace overrides (pnpm overrides, go.work, Cargo [patch], Maven snapshots). A required `changeset` check blocks partial merges; on approval it merges as an ordered train, bumping downstream pins to the released upstream versions and pausing if a step fails. Per-repo `.agent-policy` files compile into branch rulesets (writable prefixes, protected paths). `cs checkout <id>` rebuilds the set as local worktrees: multi-repo teleport through git.
Differs from existing: Existing tools produce independent PRs or coordinate sessions; none tests the set together or enforces merge order. This adds atomic review, joint CI, ordered merges, per-repo push policy and git-based teleport, regardless of which agent produced the branches.
Needs: App permissions to read, check and merge PRs; CI able to clone several repos; package-manager overrides. No vendor change; showing change sets inside agent UIs would need vendors.

## P8
Solution: Resume scheduler — make resumption a scheduled job instead of a waiting process. Delegated tasks run headless under a supervisor (`claude -p --output-format stream-json`, `codex exec --json`) that records session id, cwd and goal and instructs the agent to keep `progress.md` current. When a run ends on a limit, the supervisor reads the structured error and its reset time, never the human message; if no reset time is available it schedules cheap probe runs. It then registers an OS timer with wake-from-sleep (systemd WakeSystem timer; launchd plus `pmset schedule wake`) for any horizon, weekly included, which runs `claude -p --resume <id>` or `codex exec resume <id>` with "Limit reset; continue from progress.md". Resumed runs use a pre-approved permission profile plus a deny-and-explain hook, so nothing stalls on a prompt; model-specific limits switch to a configured fallback model. Optional: continue on a spend-capped API key near a deadline.
Differs from existing: Nothing waits in-process, so sleep, closed terminals and Remote Control do not matter; it covers -p, background and weekly resets, starts when already over the limit, survives message-format changes, and resumed work does not stall on permission prompts.
Needs: Headless resume (exists in Claude Code and Codex); OS scheduler with wake. A documented machine-readable reset time in headless output would make scheduling exact (vendor).

## P9
Solution: Queue file with Stop-hook dispatcher. Tasks live in `.agent/queue.md`, one block each with optional `verify:` command, `after:` dependency and `fresh: true`, editable in any editor, via a CLI (`q add`) or a small VS Code panel. A Stop hook (Claude Code Stop, Codex Stop, Gemini AfterAgent) fires only when the turn has really ended; if it ended normally and tasks remain, the dispatcher runs the finished task's `verify:` command, optionally commits a checkpoint, then blocks the stop with the next task as the reason, so each queued task becomes the next instruction after the previous one is done. A failed check re-prompts once, then pauses the queue and notifies. `fresh` tasks run as separate headless sessions in a worktree for clean context. Input never passes through the chat box, so mid-turn folding, VS Code interruption and desktop message loss cannot occur.
Differs from existing: Built-in queues fold messages mid-turn, merge them or lose them; third-party queues are UI- or platform-bound and unverified. This is durable, agent- and surface-agnostic, strictly one task per completed turn, and gated on verified success.
Needs: Stop hooks with block-and-reason semantics (Claude Code, Codex, Gemini); the loop ends when the queue empties. A native hold-until-turn-end setting would need the vendor.
