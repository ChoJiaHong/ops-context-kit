### Analysis
The bottleneck has moved from doing to supervising: many concurrent agents act on shared, stateful, mostly irreversible systems (clusters, state files, hosts), and one human must decide what to allow, notice what is stuck, and trust what is reported. Most agent tooling assumes one session editing one git working tree, where mistakes are undone with git. Infra work breaks that assumption in five ways.

1. Hidden shared state. Worktrees isolate files, but kubeconfig current-context, cloud profiles, terraform state and workspaces, Helm releases and hosts are global. Parallel sessions interfere silently.

2. Permissions judge strings, not effects. Issues about compound-command parsing show even string matching misfires. The danger of `terraform apply` lies in the plan, so users either approve everything or babysit. Missing: auto-approval of the read-only majority, and approvals bound to a reviewed effect.

3. Long tasks lose their contract. The top complaint (complex tasks unusable), plus compaction and handoff requests, point to no durable, executable definition of done surviving compaction and moves between Claude, Codex and Cursor.

4. Infra-specific leaks and drift. Secrets reach transcripts through ordinary debugging output; GitOps clusters get imperative fixes that the controller reverts while the agent reports success.

5. The operator is blind at fleet scale. Many top issues concern quota drain, cache TTL and cache_creation regressions, and CLI-version regressions; users cannot attribute a change to model, CLI or their own config. Requests for multi-window, timestamps, renaming, message queueing and remote control show that tracking many sessions is itself a job.

Selection: problems specific to stateful infra plus parallelism, under-served by worktrees, permission rules, token counters, session dashboards and todo lists, and buildable now with hooks, MCP, wrappers and transcripts. Ranked by blast radius × frequency × gap. Excluded: account, pricing and UI asks (real but vendor-side) and instruction-file syncing (largely solved by generators/symlinks). Several items share one PreToolUse pipeline (parse → classify → lease → plan-gate), but each is separately useful.
### Items
I1: Parallel sessions share global infra context—kubeconfig current-context, AWS_PROFILE, gcloud config, terraform workspace. One session's `kubectl config use-context prod` silently retargets every other session; worktrees isolate files, not targets. || Session target envelope. A SessionStart hook creates a per-session kubeconfig containing only the declared contexts, an AWS config with only allowed profiles, and a private CLOUDSDK_CONFIG/TF_WORKSPACE, exported via CLAUDE_ENV_FILE so nothing global is read. A PreToolUse hook blocks commands that reference global config paths or override KUBECONFIG/AWS_PROFILE inline; widening the envelope requires a human-confirmed `/target` command. The status line shows the target, coloured by environment tier. A shell wrapper gives Codex/Cursor sessions the same envelope.
I2: Approving `terraform apply`, `helm upgrade` or `kubectl apply` by command text is meaningless; risk lies in the resulting change. Users either rubber-stamp or babysit, and the applied change can differ from what was reviewed. || Plan-bound approval gate. A PreToolUse hook intercepts mutating infra commands and instead runs the dry-run equivalent (`terraform plan -out`, `helm diff upgrade`, `kubectl diff --server-side`), summarises it (creates/updates/destroys, replacements, RBAC, IAM, network-exposure changes), scores risk by policy, and auto-allows low-risk changes in non-prod. Otherwise it asks the human with the summary. The approval is stored as the plan's hash; only `terraform apply <planfile>` matching that hash, or an identical rerendered diff, is permitted.
I3: Permission rules match command strings, so compound commands, pipes, `sh -c`, `xargs`, `ssh host '…'` and `kubectl exec -- …` are misjudged. Read-only inspection, the bulk of ops work, still triggers prompts, causing fatigue and blanket allows. || Effect classifier for shell. A PreToolUse hook parses the command with tree-sitter-bash, recursively unwraps nested shells (`sh -c`, `ssh`, `kubectl exec`, `docker exec`, `xargs`, `env`), and classifies every leaf using a verb table per CLI (kubectl get/describe/logs = read; aws describe-*/list-* = read; terraform plan/show = read; helm template/diff = read). Allow if all leaves read-only; ask on unparseable constructs (`eval`, command substitution into commands); route anything mutating to the plan gate (I2). Log decisions for table tuning.
I4: Long multi-part tasks lose their contract: after compaction or handoff to another session/tool, subtasks are forgotten, and agents declare 'done' without evidence. The human must re-verify everything, negating delegation. || Executable task ledger. Each task is a repo file (`.agent/tasks/<id>.yaml`) whose items carry acceptance commands (`kubectl rollout status …`, `terraform plan -detailed-exitcode` exiting 0), agreed with the human up front. A Stop hook runs unchecked items' commands and blocks stopping, returning failures, until all pass or the agent records 'blocked: reason'. SessionStart hooks (including after compaction) reinject the ledger; AGENTS.md points other tools to it. The final report is generated from command results, not prose.
I5: Ops commands routinely print secrets (`kubectl get secret -o yaml`, `terraform output`, `env`, `.env`, kubeconfigs), which then persist in local transcripts, compaction summaries and API traffic. Denying these reads breaks debugging; allowing them leaks credentials. || Secret placeholder proxy. A PreToolUse hook wraps every Bash command (via updatedInput) so output passes through a redactor that decodes base64 Secret data, detects credentials (key names, entropy, provider token formats), and substitutes stable placeholders like `{{secret:prod/db/password#3f2a}}`, storing values in a session-scoped keyring. When a later command contains a placeholder, the wrapper substitutes the real value at exec time, outside the model's view. Read-tool access to secret-bearing paths is denied, forcing the wrapped path.
I6: Several agents on one project contend for the same external resources: terraform state, Helm releases, namespaces, hosts. State locks fail late or get force-unlocked; agents unknowingly undo each other's applies or restart services mid-change. || Resource lease broker. A small local daemon (SQLite + Unix socket, exposed also as MCP) issues leases keyed by canonical resource IDs: `tfstate:<backend>/<key>`, `helm:<context>/<ns>/<release>`, `host:<fqdn>`. The I3 parser extracts targets from each mutating command; a PreToolUse hook acquires the lease or denies with 'held by session X (task Y, since 14:02)'. Leases heartbeat on PostToolUse and expire on SessionEnd or missed heartbeat. Agents can call `list_leases` to plan around contention.
I7: With ten sessions across terminals and hosts, the human cannot see which are blocked on a prompt, waiting for input, finished, or looping. Sessions idle for hours; approvals are given hastily without context. || Session switchboard with approval inbox. Hooks in every session (Notification, Stop, PreToolUse, PostToolUse; remote hosts via SSH-forwarded socket) post events to one local SQLite store: state, branch, infra target, ledger progress, last tool, time-in-state, tokens. A TUI/menu-bar view ranks sessions by time-blocked × target risk and jumps to the tmux pane. Risky approvals route to the inbox: the PreToolUse hook long-polls for the decision, shown beside the plan summary. Hook timeout falls back to the normal prompt.
I8: Quota drains unpredictably across parallel sessions; users can't tell whether cost came from their workflow (idle gaps beyond cache TTL, huge tool outputs, MCP schemas) or a CLI/server regression, so they can't fix it or report it with evidence. || Cache-aware usage forensics. A daemon tails transcript JSONL, recording per turn input, cache_creation, cache_read, output, CLI version, model, gap since previous turn. It flags cache rebuilds (high cache_creation after short gaps → regression; after long gaps → TTL expiry), attributes tokens to tool outputs, MCP schemas and memory files, and tracks first-turn cache_creation per CLI version to expose overhead regressions. Live: a status-line warning before an idle session crosses the cache TTL, and a projected time-to-limit across all sessions.
I9: On Argo/Flux-managed clusters, agents fix incidents imperatively (`kubectl patch/scale/edit`), report success, then the controller reverts the change, or self-heal is off and git silently diverges from live state. || GitOps ownership guard. Before any mutating kubectl/helm command, a PreToolUse hook reads target objects' ownership markers (Argo CD tracking label/annotation, Flux `*.toolkit.fluxcd.io/name` labels), resolves the owning Application/Kustomization to repo and path, and locates the manifest file defining that object. If owned, it denies with 'edit <repo>/<file>, open a PR'. A break-glass flag permits the imperative change but auto-opens a matching reconcile PR and schedules a drift check.
I10: Agent quality shifts with model and CLI releases; users notice weeks later via frustration and cannot tell whether model, CLI version, or their own CLAUDE.md/skills changes caused it, nor safely pin or roll back. || Personal regression bench. Turn 20–30 past successful tasks from your transcripts into fixtures: repo commit + original prompt + checker script (tests, `terraform validate`/`plan` against a sandbox account, kind cluster rollout). A nightly job runs each headless (`claude -p`, `codex exec`) in throwaway worktrees across a matrix of CLI version × model × your config revision, recording pass rate, turns, tokens and wall time. The CLI auto-update is gated: a version is adopted only if it doesn't regress.
