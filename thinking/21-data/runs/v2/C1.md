### Analysis
A(P0): many semi-autonomous actors work in parallel and over long horizons on shared, stateful infrastructure, using one human's credentials and limited human attention.

Se (named, real): git worktrees; Terraform state locks and stale-plan detection; Atlantis PR locks with conftest/OPA on plan JSON; kubie/kubectx/direnv; Claude Code permission rules, hooks, todo lists, compaction, /resume; Kubernetes audit logs and CloudTrail; Argo CD self-heal and Kyverno admission; pdsh+dshbak, Ansible ad hoc; gitleaks/trufflehog; ccusage.

L: each assumes one of: a human in an interactive shell, one actor per credential, change gated by PR, output sized for a screen, or a human who knows what Argo owns. Agents break all five.

Down loop (people, place, time, behavior, constraints, resources) produced recurring differences:
D1 behavior: every agent action passes a per-command chokepoint (PreToolUse/Stop/SessionStart, or a PATH shim) carrying a session ID; humans have none.
D2 place: agent shells are non-interactive and non-persistent, so per-shell isolation fails while global config files leak across sessions.
D3 people: N agents share one identity.
D4 constraints: the context window, not the screen, is scarce; the agent lacks tacit ownership knowledge.
D5 time: sessions outlive their context (compaction) and run unattended.
D6 resources to reinterpret: Kubernetes Lease objects and SSA field managers (controller primitives reused as inter-agent locks); dry-run/plan JSON (review artifacts reused as approval input); GitOps ownership labels; STS session names and kubeconfig impersonation; typed secret metadata; local transcripts as a behavior dataset; read-only CLI queries as truth oracles.

Match/forced-fit: each item pairs an L with a D, then the D was removed. With one interactive human, kubie beats I1; without dry-run, I2 reverts to string matching; without context limits, dshbak suffices for I10; without verifiable end state, I5 is just a todo list. Items that survived only as labels were dropped.

Rounds: R1 isolation/safety (I1-I4, I6); R2 completion/knowledge (I5, I8); R3 leakage/context (I7, I10); R4 meta (I9) plus rejections: rule-file sync across tools (symlink/@import solves it), cross-session approval inbox (generic notification batching), worktree collision warnings (git merge-tree adequate), plan summarizers (exist), cheaper-model selection by replaying recorded tasks against offline verifiers (valid, ranked 11th). R5 and R6 produced nothing new; stopped.

Up loop: each Sn widened until its measured advantage over the best Se disappeared; that boundary is P*. Goal check: every item still serves the original goal, letting one engineer safely delegate infra work to many parallel agents with less supervision.

### Items
I1: Parallel agent sessions share global CLI state (kubeconfig current-context, gcloud active config, az account). One session's `use-context` silently retargets every other session; per-shell fixes (kubie, direnv) fail because agent Bash calls are non-interactive and non-persistent. || Session context pinning: SessionStart hook copies kubeconfig to ~/.kube/s/<session>.yaml, creates a per-session gcloud configuration, and exports KUBECONFIG/CLOUDSDK_ACTIVE_CONFIG_NAME via CLAUDE_ENV_FILE (agents without hooks: PATH shims keyed on worktree). PreToolUse adds explicit --context/--kube-context to kubectl/helm calls and denies switches outside the session's declared targets. Metric: commands hitting an undeclared context, counted from transcripts, → 0. P*: any agent in non-persistent shells using CLIs with global config files.
I2: Permission rules judge command strings, not effects: `terraform apply` may be a no-op or replace a database, so engineers hand-approve everything or allow-list broadly. Policy-on-plan (Atlantis+conftest) runs only in PR pipelines, not at agents' local applies. || Effect gate: before any mutation, PreToolUse runs its dry run (terraform plan -out + show -json, kubectl diff --server-side, helm diff), evaluates the effect with OPA rules (no deletes/replaces of stateful kinds, nothing in prod namespaces), auto-allows if clean, otherwise asks with a five-line effect summary, then rewrites the call to apply exactly that saved plan. Metric: approval prompts per session down, destructive-effect escapes = 0. P*: mutations through tools with dry-run/preview (also Pulumi preview, ansible --check).
I3: Worktrees isolate files, not live targets. Two sessions can helm-upgrade the same release or kubectl-apply the same namespace; Terraform locks only cover one run, and SSA conflict detection is blind because all sessions use the same field manager. || Target lease hook: PreToolUse parses mutating kubectl/helm/terraform/argocd commands into a target key (context/namespace/release or backend/workspace), acquires a coordination.k8s.io Lease in that cluster (file lock for Terraform keys) holding session ID and task, renews on each call, releases on SessionEnd or TTL; denial names the holder. It also injects --server-side --field-manager=agent-<session> so the API server flags cross-session field overwrites. Metric: cross-session mutations of one target within 30 minutes → 0. P*: any shared mutable target with a lease primitive.
I4: Agents act with the engineer's own credentials, so Kubernetes audit logs and CloudTrail cannot tell which session, task, or human made a change, and every agent holds the human's full privileges, including prod delete. || Per-session identity minting: SessionStart hook runs aws sts assume-role --role-session-name agent-<session>-<task>, sets CLOUDSDK_AUTH_IMPERSONATE_SERVICE_ACCOUNT, and writes a kubeconfig user with impersonation (as: agent-<session>, as-groups: agents) bound to a narrower RBAC role; credentials are short-lived and refreshed by PreToolUse. Audit records then carry session IDs, joinable to transcripts. Metric: share of agent mutations attributable to a session in audit logs, ~0% → ~100%. P*: any API supporting short-lived delegated credentials.
I5: In long multi-part tasks (upgrade 14 clusters, rotate certs on 80 hosts) agents stop early or declare done after compaction loses the checklist; todo lists are self-reported, and Stop hooks cannot judge completion. || Acceptance-predicate ledger: the task file lists each subtask with a read-only check and expected result (kubectl --context X version shows 1.31; cert expiry > 60 days; terraform plan -detailed-exitcode returns 0), hash-locked against agent edits. The Stop hook runs all checks in parallel and blocks stopping with the failing list (capped retries); a SessionStart compact/resume hook re-injects only unmet items. Metric: sessions declaring done while checks fail → 0. P*: tasks whose end state is queryable.
I6: Agents hotfix with kubectl edit/patch on objects owned by Argo CD or Flux; the command succeeds, the agent reports done, and the next sync silently reverts it (or, without self-heal, Git stops matching reality). || Ownership redirect hook: before kubectl mutations, PreToolUse reads the target's ownership markers (argocd.argoproj.io/tracking-id, app.kubernetes.io/instance, Flux kustomize.toolkit.fluxcd.io labels, Helm managed-by), resolves the owning Application/Kustomization to repo, path and values file, and denies with that location so the agent edits Git instead. Kyverno-style admission can block but cannot tell the agent where to go. Metric: agent changes later reverted by sync → 0. P*: resources whose source of truth leaves a marker (GitOps, Helm, Terraform-tagged cloud resources).
I7: Secrets reach the model and on-disk transcripts through command output (kubectl get secret -o yaml, terraform output -json, helm get values, env), which file deny-rules and repo scanners like gitleaks never see; regex detection misses opaque random values. || Type-aware redaction: PreToolUse pipes matching commands through a redactor driven by the source's own sensitivity metadata (Secret .data/.stringData; Terraform sensitive_values in show -json, state sensitive_attributes), replacing values with length plus an HMAC prefix so agents can still compare. A nightly job loads current secret values from clusters/Vault into memory, searches transcripts for them (raw and base64) with Aho-Corasick, and scrubs hits. Metric: known secret values in transcripts → 0. P*: outputs from sources that type their secrets.
I8: CLAUDE.md/MEMORY.md accumulate environment facts (which cluster is prod, node pool names, host roles) that silently go stale, and agents act on them confidently; nothing checks memory against reality. || Verifiable memory: each fact line carries a read-only probe, e.g. `payments runs in gke-eu-1 <!--check: kubectl --context gke-eu-1 -n payments get deploy payments-api-->`. A nightly job runs probes (verbs allow-listed to get/describe/show), marks failures STALE inline with date and observed output; a PostToolUse hook on memory-file edits asks the agent to attach a probe or tags the line UNVERIFIED. Metric: share of sampled memory facts that are false (target <2%). P*: memory about machine-queryable state, including repo structure.
I9: Prose rules in CLAUDE.md/AGENTS.md/skills (always pass --context, never apply to prod, use helmfile) are followed unevenly, and nobody knows which rules are ignored or which wording works; files only grow. || Rule-compliance miner: each rule gets a predicate over tool calls (LLM-drafted, human-confirmed; regex/AST on Bash commands, edited paths). A weekly job scans local transcripts (Claude JSONL, Codex session logs), computes per-rule trigger count and violation rate; rules violated >5% are compiled into PreToolUse deny/rewrite hooks, rules whose trigger never occurs in 60 days are proposed for deletion. Metric: per-rule violation rate before/after and rule-file tokens. P*: rules expressible as predicates over agent actions.
I10: Diagnosing across dozens of hosts or clusters, agents loop ssh/kubectl per target and flood context; pdsh+dshbak -c coalesces only byte-identical output, and timestamps, hostnames and PIDs make every host unique, so outliers drown. || Fleet-exec MCP: runs one allow-listed read-only command across an inventory (Ansible inventory, kube contexts), masks identifiers (hostnames, IPs, timestamps, PIDs) and numbers, clusters by masked hash, then returns: majority group, each minority group as a diff against it, per-number-position min/median/max with outlier hosts, and unreachable targets; raw outputs stay on disk behind a drill-down handle. Metric: tokens per fleet query (80 hosts: ~40k → <2k) at equal outlier recall. P*: any same-command-many-targets read.
