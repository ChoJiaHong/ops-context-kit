# 工作表：把筆記的方法用在方法本身

## 1. 起點（待驗證假設）
假設 H：這個方法是「拿一般性的既有解法當基準，找出特定情境相對一般情況的差異，用差異補上基準解的瓶頸，調整出新解，並確認目標不變」。它最適合解的問題，是「已有成熟通用解、但在某個具體情境下雖可用卻不是最佳」的問題。
註：三份筆記的版本差異：筆記一偏創新（縮窄＋找差異）；筆記二加入雙向迴圈與 Advantage、P*；筆記三改為固定原問題、只改表徵（抽象→比較→調整→驗證），並承認 Problem Drift、必要性、新穎性未證。

## 2. 抽象：屬於哪一類方法
「情境適配式問題界定／解法調整」：以通用解為參照，經由情境對比重新界定限制與資源，再調整解法。同屬「問題重述＋類比／案例推理＋資源推理」的類別。

## 3. 一般解法：這一類的既有方法
- 直接解題（Direct LLM／專家直覺）、Chain-of-Thought
- 一般問題重述（Reframing）、問題診斷（5 Whys、根因分析）
- 案例式推理 CBR／類比推理
- TRIZ（矛盾矩陣、發明原則）
- 分解／規劃、Self-Refine
- 去設計定著（Design Fixation Mitigation）、腦力激盪

## 4. 瓶頸：既有方法的限制
| 方法 | 限制 |
|---|---|
| 直接解題／CoT | 把使用者描述當事實；容易給出通用答案，不看情境特有的資源與限制 |
| 一般重述 | 沒有固定的重述軸，不保證找到可用資源 |
| 問題診斷／根因 | 找「為什麼壞」，對「沒壞但不夠好」的問題無著力點 |
| CBR／類比 | 以相似度檢索，重點在「像」而不在「這裡多了什麼」；易受表面相似誤導 |
| TRIZ | 矛盾與原則是抽象層級的，不從具體情境取資源 |
| 分解／Self-Refine | 在原表徵內優化，不改變問題的表徵 |
| 腦力激盪 | 發散但無篩選與驗證，易硬湊 |
共同缺口：沒有一個步驟明確問「這個情境相對一般情況多了什麼，它能不能補上通用解的瓶頸」。

## 5. 向下縮窄：沿維度加條件
維度與判斷（推理，非實測）：
- 問題是否已有成熟通用解：沒有 → 無基準可比，方法無優勢；有 → 繼續。
- 通用解是否「可用但不最佳」：完全失效 → 一般重新設計即可；可用但不佳 → 方法開始有優勢。
- 瓶頸類型：效率／成本／續航／時間等資源型瓶頸 → 易與情境資源配對；純演算法或純邏輯瓶頸 → 難配對。
- 情境是否有獨特資源／基礎設施／限制：有 → 有可配對的差異；無 → 沒有差異可用。
- 目標是否固定可驗證：是 → 可做一致性檢查；否 → 易漂移。
- 驗證成本：能與基準比較 → 可判斷優勢。
結果：方法開始優於既有方法的情境 = 「有成熟通用解，其瓶頸是資源型且可辨識；具體情境有獨特資源或基礎設施；目標固定、能與基準比較」。例：山區無人機搜救 → 阿里山林業鐵路。

## 6. 差異與配對
| 情境特點 | 對應元素 | 補上的既有方法限制 |
|---|---|---|
| 有成熟通用解 | 一般解基準 | 讓「多了什麼」有參照；補 CBR／類比只看相似的缺口 |
| 通用解可用但有瓶頸 | 瓶頸辨識 | 補直接解題不問「還做不到什麼」的缺口 |
| 情境有獨特資源 | 情境差異萃取 | 補一般重述沒有固定軸線的缺口 |
| 資源可改變瓶頸 | 配對（Match）＋調整（含資源重新詮釋） | 補 TRIZ 抽象原則不取具體資源的缺口 |
| 目標固定可驗證 | 目標一致驗證＋硬湊檢驗 | 補腦力激盪硬湊、Problem Drift 的風險 |

## 7. 調整：為該情境的版本
1. 固定原始目標與問題，視問題描述為假設。
2. 抽象成問題類別，列出通用解並選出最強基準。
3. 找基準在此情境下的瓶頸。
4. 比較具體情境與一般情況，列出差異（資源、基礎設施、限制），並重新詮釋資源。
5. 配對：差異能否消除或降低瓶頸；不能就換維度再縮窄。
6. 調整出新解；做硬湊檢驗（拿掉情境特色還成立嗎）與目標一致檢查。

## 8. 向上泛化：求 P*
逐步移除條件：
- 「阿里山林業鐵路」→「有固定運輸路線深入搜尋區的情境」：仍有優勢。
- → 「有可移動補給載具」：仍有優勢，但優勢縮小。
- 移除「資源型瓶頸」→ 瓶頸是演算法或邏輯，差異無法配對：優勢消失（與診斷、直接解題無差）。
- 移除「情境有獨特資源」→ 無差異可用：優勢消失。
- 移除「有成熟通用解」→ 無基準，無法量優勢：消失。
- 移除「目標固定可驗證」→ 漂移、無法判優劣：消失。
P*：目標固定、已有成熟通用解且可用但在特定情境下有資源型瓶頸，而該情境具備可重新詮釋的獨特資源或限制的問題。
未能實證：效用函數、Advantage 判定、停止條件皆為筆記自述的未解問題，此處為推理判斷。

## 9. 硬湊檢驗（逐一拿掉元素，在 P* 上是否仍優於既有方法）
| 元素 | 拿掉後 | 判定 |
|---|---|---|
| 一般解基準 | 沒有參照，退化成腦力激盪／重述 | 核心 |
| 瓶頸辨識 | 差異無處可配，退化成類比 | 核心 |
| 情境差異萃取 | 退化成直接解題 | 核心 |
| 配對與調整（含資源重詮釋） | 只剩列清單，沒有新解 | 核心 |
| 目標一致驗證＋硬湊檢驗 | 易漂移或貼標籤，P* 上不可靠 | 核心 |
| 抽象成問題類別 | 可由「一般解基準」吸收，單獨拿掉影響小 | 非獨立骨架 |
| 向下縮窄迴圈 | 若情境已給定（P* 的進入條件），不需要；屬找情境的搜尋手段 | 非骨架 |
| 向上泛化迴圈 | 不改變在 P* 上的優勢，只決定範圍 | 非骨架（屬範圍工具） |
| 問題視為假設 | 與目標一致驗證功能重疊 | 併入驗證 |
註：這是推理式檢驗，非實驗；需 ablation 才能證實。

## 10. 目標一致性
第 1 步問：方法是什麼、最適合什麼問題。結論：骨架為五個元素（基準、瓶頸、差異、配對調整、驗證），最適合 P*。與假設 H 大致一致，但修正：迴圈與抽象屬搜尋與範圍工具，不是骨架；適用範圍比「創新」窄，也不含診斷型問題。
