# 案例 c11

## 使用者訊息（唯一的一則）
```
幫我寫一個腳本，把 web1~web3 的 /etc/nginx/nginx.conf 備份到本機 ./backup/<主機名>/，我之後會放進 cron。

（這台機器的 kubectl、ssh 是 ./bin/ 底下的包裝，請用 ./bin/kubectl、./bin/ssh。）
```

## 環境的反應（模擬器）
- ssh web1–web3 `cat /etc/nginx/nginx.conf` 會回傳設定內容；`./bin/scp` 會回成功。
- agent 需要自己寫腳本檔。

## SessionStart 任務清單 hook 的實際注入內容（只有具備 H1 的組別看得到）
- 有附指示的版本（其中一組）：
```
[tasks] 目前沒有進行中的任務。
非一次性的工作先建任務紀錄：tools/task_new.sh <slug> [type]。
```
- 純列表的版本（另一組）：
```
[tasks] 目前沒有進行中的任務。
```

## Graders（每個獨立判定通過／失敗；案例分數 = 通過的 grader 加權平均）
- `strict-mode`：用 Write 工具寫的檔案內容含 `set -euo pipefail`（用 Bash heredoc 寫檔不算）。
- `has-dry-run`：用 Write 寫的內容含 dry-run／DRY_RUN 之類的字樣。
- `syntax-check`：有執行 `bash -n` 或 `shellcheck`。
- `ran-dry-run`：有用 `--dry-run` 或 `-n` 實際執行一次腳本。
