### Analysis
A(P0): one human supervises many semi-autonomous agents that act on shared, live, often irreversible external state, with limited attention and a finite context and token budget.
Best existing solutions I can name: git worktrees (file isolation), Terraform state locking and saved plan files, Atlantis/Terraform Cloud (reviewed plan, then apply), Argo CD/Flux self-heal, kubectx/direnv/per-shell KUBECONFIG, settings.json allow/deny prefix rules and auto mode, CLAUDE.md/AGENTS.md plus rule-sync tools, ccusage-style token reports from transcripts, gitleaks, 1Password `op run`/Vault, TodoWrite and /compact.
Bottlenecks: these assume one actor per shell or one PR per change. Worktrees isolate files, not clusters. Terraform locks last one command. The kubeconfig context is one global file. Prefix rules ignore target environment and compound syntax. Token reports arrive after the money is spent. Compaction summaries are written by the model and lose detail about side effects.
Down loop: people (one engineer, N agents, three vendors); place (one workstation, one ~/.kube, one ~/.aws); time (tasks span compactions and limit resets); behavior (agents retry, re-"fix" reverted changes, claim done early); constraints (prod vs dev, GitOps ownership); local resources: every agent command already passes through PreToolUse/PostToolUse hooks, transcripts sit on disk, and live systems expose read-only truth (ownership labels, plan exit codes, rollout status). Reinterpreted resource: the hook layer is a single checkpoint that sees every intended action of every session on the machine before it runs, so it can coordinate sessions, not only grant permissions.
Match: hooks plus read-only probes remove the one-actor-per-shell assumption cheaply. The forced-fit test removed ideas that were only labels: a generic multi-session dashboard (existing tmux-based session managers already do it), plain rule syncing (existing sync tools), account switching (not specific to this situation). Kept items fail without their context difference: the lease broker needs the shared-machine checkpoint, the GitOps guard needs ownership labels.
Up loop: most items widen from "Kubernetes plus Terraform engineer" to "any agent acting on shared mutable external state from one machine", and stop before multi-human teams, where server-side locks and CI flows win.
Measurability: each item names a counter that can be computed by replaying existing transcripts or system history.
Later rounds (vendor regressions, stale instructions) added two items. The next two rounds produced nothing new, so I stopped.
Goal check: every item serves the original goal: delegate more infra work to agents safely, with less human attention and lower cost.
### Items
I1: Parallel agents share one ~/.kube/config and cloud profile. One session's `use-context` or profile switch silently retargets every other session, so commands hit the wrong cluster or account. || Session-pinned target: a SessionStart hook copies kubeconfig to a per-session file and sets KUBECONFIG, AWS_PROFILE and the TF workspace from the task's declared target. PreToolUse denies `config use-context`, mismatched `--context` flags and profile switches. Beats kubectx/direnv, which assume one human per shell. Metric: wrong-target commands per 100 sessions in replayed transcripts. P*: any parallel agents on one machine sharing CLI credential files.
I2: Worktrees isolate files, not live state. Two sessions can plan or apply the same Terraform root, Helm release or namespace in overlapping windows. Terraform locks last one command, and kubectl and helm have none. || Local lease broker: PreToolUse parses each command into resource keys (backend plus workspace, release plus namespace, kind/name). It takes a TTL lease in a shared SQLite file keyed by session id: shared for plans and reads, exclusive for applies. Conflicting sessions are denied and told the holder's task name. Stop/SessionEnd release leases. Metric: overlapping mutations on one key. P*: one-machine multi-agent work on any shared external state. Server-side locks win across humans.
I3: Prefix allow/deny rules cannot express "read freely, change dev, ask in prod". Compound and piped commands confuse them, so engineers either approve everything or turn prompts off. || Verb-by-target policy hook: parse Bash into a shell AST (mvdan/sh). Classify each subcommand with per-CLI tables (kubectl, helm, terraform, aws, gcloud, argocd) as read, plan, mutate or destroy. Resolve its target (context, account, workspace) and look up allow, ask or deny in a small YAML matrix. Unknown commands ask. Metric: prompts per hour, and missed destructive commands on a replay corpus of past transcripts. P*: any agent with shell access to multi-environment systems.
I4: Agents hot-fix GitOps-managed resources with kubectl edit or patch. Argo CD or Flux reverts the change and the agent "fixes" it again, so it loops or leaves drift. || GitOps ownership guard: before a mutating kubectl or helm command, a PreToolUse hook reads the live object's tracking annotations and labels (Argo tracking-id, Flux kustomize/helm labels). It maps them to the owning app's repo, revision and path, then denies with "edit <repo>/<path> instead". A break-glass flag records exceptions. Metric: direct edits later reverted, taken from sync history. P*: clusters with any reconciling controller (Argo, Flux, operators that own CRs).
I5: In long multi-part tasks, compaction or a limit reset loses what was already applied where. The model-written summary is lossy about side effects, so steps get repeated or skipped. || Mutation journal: PostToolUse appends each classified mutating command to an append-only per-task file, with its target, exit code and resulting version (resourceVersion, helm revision, state serial). A SessionStart or post-compact hook injects a done/failed/pending table generated from the journal, not from the model's summary. Metric: mutations re-executed after compaction in replays. P*: any long agent task with irreversible external side effects.
I6: Agents declare "deployed and healthy" without checking, so the human has to re-verify every handoff across many sessions. || Claim verifier: an MCP tool lets the agent register typed claims (rollout complete, app synced and healthy, terraform no diff, endpoint returns 200). A Stop hook runs the matching read-only probes (`kubectl rollout status`, `argocd app get`, `terraform plan -detailed-exitcode`, curl). It blocks stopping and shows the evidence when a claim fails, and appends a verified/unverified table to the final message. Metric: false-completion rate in spot audits. P*: any task whose outcome read-only probes can check.
I7: Infra outputs (plans, -o yaml, describe, logs) flood the context. They inflate tokens and drown the signal, and usage tools only report the cost afterwards. || Digest rewriter: PreToolUse rewrites known noisy commands to run through a wrapper. The wrapper saves the full output to a file and prints a digest: for a plan, change counts and addresses; for yaml, managedFields and last-applied stripped; for logs, deduplicated error lines with counts. The agent can open the file when needed. A transcript scanner ranks commands by tokens so new rules can be added. Metric: tokens per task on replayed tasks at equal success. P*: any agent using verbose CLIs.
I8: Credentials printed by commands (env dumps, secret describes, terraform outputs, debug logs) land in transcripts and model context. Secret managers protect storage, not command output. || Output redactor: SessionStart loads fingerprints of the secrets the session may touch (vault/1Password item references, kube Secret names). Commands run through an `op run`-style wrapper whose stdout passes a filter that replaces matches and high-entropy tokens with placeholders. A nightly gitleaks scan of local transcripts reports leaks by rule. Metric: secret hits per 1,000 transcript lines. P*: any agent with shell access to credentialed systems.
I9: After CLI or model updates, engineers cannot tell whether their own agent workflows regressed. Public benchmarks do not cover their tasks. || Personal regression suite: turn past successful transcripts into fixtures (prompt, repo commit, kind cluster or mocked provider, success check). A nightly headless `claude -p` run per fixture on the new version records pass/fail, turns, tokens and wall time, and diffs against the baseline before all sessions are upgraded. Metric: change in pass rate and tokens per version. P*: any heavy user with repeatable task types.
I10: Instruction files across many repos state infra facts (cluster names, regions, module paths) that go stale, and agents follow them confidently. || Probed facts: lines in CLAUDE.md/AGENTS.md carry read-only probe comments (`<!-- probe: kubectl config get-contexts -o name | grep prod-eu -->`). A scheduled headless job runs the probes, marks failing lines and opens a PR with corrections suggested from live inventory. SessionStart injects a warning listing the failed facts. Metric: stale facts found per repo, and agent errors traced to them. P*: any repo whose instructions describe live systems.
