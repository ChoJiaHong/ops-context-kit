## P1
Solution: Alias-swap gateway — the agent is launched through a wrapper that points ANTHROPIC_BASE_URL at a local model gateway and HTTPS_PROXY (with a local CA) at a local egress proxy. The gateway rewrites every occurrence of the account email in outbound model requests (system prompt, tool results) to a revocable forwarding alias the engineer chose (e.g., a masked-email address), so the model, subagents and scripts it writes only ever know the alias. The egress proxy inspects non-vendor traffic after decoding (headers, URLs, bodies, including URL-encoded, base64 and hex forms of the real email) and substitutes the alias instead of blocking; loopback and file-only commands never reach it, so they cannot be false-denied. A SessionStart note tells the model to use the alias whenever a site demands a contact email (e.g., sec.gov User-Agent). Spam reaching the alias identifies the leak and the alias can be killed.
Differs from existing: Removes the email at its source, including on managed-settings logins where context mods are skipped, and judges wire bytes, not command text, so self-written scripts, subagents and encodings are covered without blocking tasks. Measure: real-email egress hits over a leak-route corpus = 0; local false denies = 0.
Needs: Agent honoring ANTHROPIC_BASE_URL and HTTPS_PROXY with a trusted local CA, user control of launch env, a forwarding-alias service. A supported opt-out would make the gateway rewrite unnecessary (vendor).

## P2
Solution: Permission conformance harness — a CI/pre-upgrade runner that black-box tests the real CLI's enforcement in a throwaway container. A fake model server (via ANTHROPIC_BASE_URL or a Codex custom provider) replays scripted tool calls: compound and cd-chained commands, quoted flags, git -C, ExitPlanMode, and the same calls issued from inside a subagent or skill. --permission-prompt-tool points at a recording MCP server, so each case's actual outcome (allowed, asked, denied) is captured at zero token cost. Expected outcomes come from a short intent file plus cases harvested from the engineer's own transcripts, where every prompt they approved or rejected is a labelled case. Output is a divergence table per CLI version. A wrapper pins the CLI and promotes a new version only when the suite passes; for each divergent case it generates a narrowly scoped PreToolUse shim and keeps it only if the whole suite, including deny cases, still passes.
Differs from existing: Hook projects are one more unverified matcher; this measures the enforcement actually delivered, catches regressions (bypass, yolo or inheritance breaks) before unattended runs, and only adds shims proven against both allow and deny cases. Measure: divergent cases per version; prompt stalls per unattended run.
Needs: CLI accepting a custom model endpoint and a permission-prompt tool; version pinning. Unfixable divergences (ExitPlanMode hook allow, Remote Control prompts, Gemini policy loading) need vendor fixes; it reports them.

## P3
Solution: Forge-native agent runner — one container image (headless Claude Code or Codex) plus thin pipeline adapters for Bitbucket Pipelines, Azure Pipelines, GitLab CI and Jenkins, running on the organization's own runners, self-hosted included. A small webhook relay starts the pipeline when an engineer assigns a Jira, Linear or Azure Boards item to an "agent" user or comments "@agent" on an MR/PR, passing the ticket text, links and comments as job input. The job clones with the pipeline's scoped repo token, runs the agent, pushes a branch, opens the MR/PR through the forge API and posts the link on the ticket. The session transcript is stored as a pipeline artifact keyed by MR; each later review comment re-triggers the job, which resumes that session (--resume) with the new comments, giving multi-turn sessions on stateless CI.
Differs from existing: Uses compute, credentials and network approval each forge already provides, so Bitbucket Data Center, Azure DevOps Server and self-managed GitLab work without GitHub mirrors, Premium tiers, feature flags or beta integrations; resumable transcripts add review iteration that one-shot CI jobs lack. Measure: manual copy/branch steps per ticket = 0.
Needs: Runners with outbound model-API access, an API key or cloud-provider model access, forge and tracker API tokens and webhooks. Vendor-hosted web sessions on these forges still need the vendor.

## P4
Solution: Out-of-band session watcher — a daemon on the machine or SSH host where the agent runs, independent of harness hooks. It tails the session transcript files (Claude Code and Codex JSONL, Gemini chat files, which already carry per-message timestamps) and inspects the agent's process tree and CPU. State rules: final assistant message and no new entry for N seconds → done (debounces /goal continuations); pending tool call with no child process and idle CPU → waiting for approval; API-error entry or process exit → failed. Alerts escalate and deduplicate per state change: terminal bell or desktop toast at once, phone push via ntfy if unacknowledged after a configurable delay. A TUI and local web timeline list every session's state and the timestamp of each instruction, tool run and background check.
Differs from existing: Derives state from what the agent did, not from hook events, so API-error endings, delayed or broken hooks, missing approval events and false /goal "done" alerts are covered, over Remote SSH and in any IDE. Measure: missed idle-waits and alert latency on a fault-injection suite.
Needs: Read access to transcript files (undocumented formats; per-version parsers) and the process table; an ntfy topic or other push service. No vendor change.

## P5
Solution: Effect-based shell supervision — a PreToolUse/PostToolUse hook pair on Bash that judges what a command changed, not how it was spelled. Before each call it snapshots the workspace cheaply (git add -A into a temporary index plus git write-tree; protected ignored paths such as .env hashed explicitly; hash scan outside git) and diffs after it. Every changed path goes through the same Edit/Write allow/deny and path rules: forbidden changes are restored from the snapshot and the agent is told why; allowed changes are shown as a unified diff, recorded as a checkpoint on a shadow git ref (restorable by a rewind command), and nested CLAUDE.md or path-scoped rules for touched directories are returned as PostToolUse additionalContext. A strict mode runs the command in a copy-on-write overlay and applies only allowed changes. Reads stay with the OS sandbox's read-deny.
Differs from existing: Pattern hooks block sed/cat, are routed around by python, perl or heredocs, and fight the harness's Bash-first steering. This lets Bash run and supervises the effect, so any program is covered, no turns are lost to block-and-retry, and rewind works. Measure: undetected writes across a write-route corpus = 0.
Needs: A git workspace (hash fallback otherwise) and hooks with PostToolUse additionalContext. Native /rewind and diff-view integration, and removing Bash-first steering, need the vendor.

## P6
Solution: One-secret credential broker — the engineer runs a small HTTPS broker and stores exactly one vendor network secret: a broker token attached only to the broker host. The agent proxy adds it after requests leave the VM, so the session holds nothing secret yet can reach every other credential through the broker: AWS/GCP/Azure calls proxied and signed by the broker (or short-lived tokens it mints), replacing the missing OIDC token; a SigV4 re-signing proxy for R2 and other S3-compatible stores; an authenticated npm/PyPI/Maven proxy for private registries; and an HTTPS-tunnelled database/SSH gateway, where a local shim listens on localhost and the broker supplies the password upstream. Secrets live in the broker, so rotation reaches running sessions. Each use is logged with session and scope. Private installs move from the setup script into the session (e.g., a SessionStart hook).
Differs from existing: Reuses the one secure primitive the vendor ships and converts it into every form the docs exclude: non-amazonaws SigV4, private registries, database URLs, cloud identity, live rotation. postern and mcp-warden are local-only. Measure: secret occurrences in session env, files and transcript = 0 for each gap case.
Needs: Network secrets on the account (Team availability needs the vendor; fallback: a scoped, short-lived env token), the broker host in the network allowlist, and an engineer-run broker.

## P7
Solution: Changeset gate — a forge app plus an agent skill that turn a multi-repo session's independent PRs into one coordinated unit. At session end the skill writes a changeset ID and Zuul-style Depends-On footers into each PR body, ordered from the repo that changes the shared contract to those that consume it. The app then shows an umbrella view of all PRs with review state and merge order; runs each consumer's CI speculatively against the producer PR's head (building the producer branch instead of the published package); holds a required "changeset" status pending until every PR in the set is approved and green; and merges in topological order, re-verifying the next PR after each merge and opening revert PRs if a later step fails. Per-repo push and merge policy lives in one org-level config file.
Differs from existing: Multi-repo sessions, mars, nemus and Codex multi-folder stop at editing several repos; none link PRs, test them together or order merges. This brings Zuul's cross-repo gating without running Zuul or Gerrit, and works for any agent. Measure: consumer CI failures from unmerged producers; out-of-order merges = 0.
Needs: GitHub/GitLab app permissions and CI able to build sibling branches. Multi-repo teleport and native changeset display in the agent UI need the vendor.

## P8
Solution: Wake-scheduled resume supervisor — the agent runs as a durable job under launchd, systemd or Task Scheduler (surviving terminal close), with session ID, directory, permission settings and prompt kept on disk. On a limit stop it takes the reset time from structured data (stream-json or transcript events, or rate-limit headers seen by a local gateway), never from human-readable text, and otherwise probes with a minimal request on backoff. It schedules an OS wake for the reset (pmset schedule wake, rtcwake, wake timers), holds a sleep-inhibit assertion while work runs, and resumes headlessly (claude -p --resume ID, codex exec resume) with a continuation prompt and the original allowed-tools set so no prompt stalls it; anything still needing approval goes to the engineer's phone. Weekly resets are just a later timer, with no 24-hour cap or re-arm limit.
Differs from existing: Built-in auto-continue skips -p and background runs, weekly resets, sleeping laptops and closed terminals; wrappers break on message-format changes or when already limited. Waking the machine and resuming headlessly from structured data covers those. Measure: share of limit stops resumed within 5 minutes of reset, unattended.
Needs: OS wake support (on AC power; lid-closed behaviour varies), an agent CLI with headless resume, structured limit data or probing. Native auto-continue for background sessions needs the vendor.

## P9
Solution: Verify-then-advance task file — the queue is a plain file in the repo (.agent/queue.md), one task per heading, each with an optional done-check command (e.g., npm test -- auth). The engineer edits, reorders or deletes tasks in any editor while the agent works; nothing is typed into the chat, so no surface (CLI, VS Code, Desktop) can interrupt or fold it mid-turn. A Stop hook fires only when the turn truly ends: it runs the current task's check; on pass it commits a checkpoint, marks the task done with timestamp and commit hash, and returns the next task as the continuation (Stop decision "block" with the task as reason), one task per turn, FIFO; on fail it feeds the failure output back for up to N retries, then halts and notifies. A PAUSE line stops the queue.
Differs from existing: Existing queues deliver blindly, so the engineer still checks each result before the next; the per-task check makes absence safe. File delivery sidesteps the buggy UI queues (mid-turn folding, VS Code interrupts, Desktop loss). Measure: tasks started on a failed predecessor = 0; lost or merged queued items = 0.
Needs: A Stop hook able to continue the session (Claude Code; Codex where supported), which runs in every surface using that harness. Fresh context per task needs the vendor.
