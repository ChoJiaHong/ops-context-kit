### Analysis
Diverge (24 candidates): (1) parallel sessions share kubeconfig context/AWS profile/TF workspace; (2) permissions match command strings, not effects; (3) imperative kubectl fixes fight GitOps; (4) crash or compaction mid-rollout loses step state; (5) secrets enter transcripts; (6) "done" without verification; (7) subtasks dropped in long tasks; (8) huge CLI output floods context; (9) no map from live resource to owning repo; (10) live changes untraceable to a session; (11) CLAUDE.md facts go stale; (12) same human correction repeated across sessions; (13) approval prompts from many windows, no triage; (14) agents inherit admin credentials; (15) logical conflicts between sessions on one namespace or values file; (16) instruction files diverge across Claude/Codex/Cursor; (17) wasteful polling during long applies; (18) no sandbox to test changes; (19) reviewers see code diffs, not rendered/plan diffs; (20) change freezes ignored; (21) transcripts hard to search; (22) MCP tool bloat; (23) token spend not attributed to tasks; (24) remote-host commands lack per-host scoping.

Converge. Discarded as largely solved: 16 (ruler/rulesync-style generators, AGENTS.md symlinks), 17 (background shells, monitors), 21 and 23 (transcript search, ccusage-style reports), 22 (deferred tool loading), 19 (Atlantis, Argo diff previews), 13 (Conductor/claude-squad-style dashboards and notifications). Weaker or incremental: 8 (generic output compressors exist), 18 (kind/LocalStack exist; wiring is the gap), 12 (auto-memory partly covers it). Folded: 14 and 24 into 1 (one scoped per-session credential file fixes isolation and privilege together); 7 into 6 (one acceptance ledger); 20 into 2 (freeze calendar becomes a risk input).

Pattern behind the survivors: worktrees isolate files, but infra agents act on shared external state (clusters, state files, cloud APIs) that no current tool scopes, gates by actual effect, or records. Code-centric agent tooling assumes the diff is the change; in ops the change is what the API server or cloud receives.

Ranking: prevented blast radius first (effect gate, scoped credentials, GitOps guard), then recoverability and confidentiality (journal, redaction), then trust and feedback loops (acceptance ledger, ownership index, attribution, leases, executable memory). All are buildable from hooks, PATH shims, small daemons or MCP servers, and keep state in plain files or the target systems, so they also work with Codex and Cursor.

### Items
I1: Permission rules match command strings, so `terraform apply` or `helm upgrade` is allowed or prompted identically whether it changes a tag in dev or replaces a prod database; humans approve blindly under prompt fatigue. || Effect gate: a PreToolUse hook intercepts mutating infra commands, first runs the dry run itself (terraform plan -out, helm diff, kubectl diff), parses deletes/replacements/IAM/stateful/prod-target counts plus the change-freeze calendar into a risk score, auto-allows low risk, otherwise shows a one-screen summary for approval. Approval is bound to the plan hash; apply is rewritten to use that saved plan, so nothing unreviewed executes.
I2: Parallel sessions share ambient state (kubeconfig current-context, default AWS profile, Terraform workspace) and inherit the engineer's admin rights; one window switching context silently retargets another, and every mistake runs with full privilege. || Session credential broker: a SessionStart hook reads the worktree's `.agent-target.yaml` (cluster, namespaces, AWS account/role, hosts), mints short-lived scoped credentials (Kubernetes TokenRequest for a namespace-bound ServiceAccount, STS AssumeRole with session tags, Vault SSH certs for listed hosts), writes them to a private per-session KUBECONFIG/AWS config, and exports env vars (via CLAUDE_ENV_FILE) pointing there. Read-only by default; write scope requires an approved escalation. A status line shows the pinned target.
I3: Agents fix incidents imperatively (kubectl edit/patch/scale, helm upgrade) on resources owned by Argo CD or Flux; the fix is reverted on next sync or becomes silent drift, and git no longer describes reality. || GitOps guard: a PreToolUse hook parses mutating kubectl/helm commands, does a read-only lookup of the target object, and if it carries Argo/Flux ownership labels or annotations, blocks the command and returns to the agent the owning Application, repo and file path (from the ownership index, I7) so it edits git instead. A break-glass flag allows the change but immediately opens a draft backport PR and pauses auto-sync for that app with an expiry.
I4: Long multi-step operations (upgrade a cluster, migrate state, roll many services) span compactions, crashes and tool switches; the next session cannot tell which steps already ran, so it repeats or skips non-idempotent actions. || Operation journal: the agent writes the plan as `.ops/<task>.yaml`, each step with command, precondition check and verification command. A PostToolUse hook appends every mutating command, exit code and verification result to `.ops/<task>.jsonl` in the repo. On SessionStart or after compaction, a hook injects the journal summary; a `resume` command re-runs only verifications, marking steps done, then continues from the first unverified step. Plain files work for Codex and Cursor too.
I5: Infra commands routinely print secrets (kubectl get secret -o yaml, terraform output, env dumps, Helm values); they enter model context, transcripts and summaries, and nothing redacts them before the model sees them. || Redacting CLI shims: PATH-first wrappers for kubectl, helm, terraform, aws, vault and env pipe stdout through a structure-aware redactor (Secret `data`/`stringData`, Terraform sensitive outputs, values keys matching password/token/key) plus token-format and entropy rules, replacing values with stable placeholders like `<secret:db-pass:3fa9>`. An `unredact` filter resolves placeholders only in input piped to kubectl apply or vault write, so agents move secrets without seeing them. A PreToolUse hook denies absolute-path bypasses.
I6: Handed a long multi-part task, agents silently drop subtasks or declare success on unverified claims ("rollout complete") without checking pods, endpoints or plan convergence; the engineer discovers gaps hours later. || Acceptance ledger: a UserPromptSubmit hook has a small model split the request into numbered acceptance items, each with a proposed check (rollout status, curl health URL, `terraform plan -detailed-exitcode` returns 0). The ledger lives in a session file. A Stop hook blocks finishing until every item is marked verified (the hook itself re-runs its check) or explicitly deferred with a reason; failures are fed back to the agent. The final message includes the ledger table.
I7: Knowledge of which repo, chart, module or team owns a live resource is scattered across many repositories and state files; agents grep blindly, edit the wrong copy, or change a module consumed elsewhere. || Ownership index: a CI job renders every Helm/Kustomize source and Argo/Flux Application, parses Terraform state and module calls across repos, and writes a SQLite map: live object/cloud ARN to repo, path, line, module, consumers, owning team. An MCP server exposes `who_owns(resource)`, `what_deploys(path)` and `impact(module)`. A PreToolUse hook on Edit warns when the file feeds more than one environment or consumer.
I8: When something changes in a cluster or cloud account, nobody can tell which of dozens of agent sessions did it or why; transcripts are local and unlinked to Kubernetes, cloud or git audit trails. || Session attribution: a PreToolUse hook rewrites mutations to carry the session ID: kubectl `--field-manager=agent-<sid>` (recorded in managedFields), Terraform default_tags via an injected variable, STS RoleSessionName (CloudTrail), git commit trailers. A `why <resource>` CLI reads managedFields, tags or CloudTrail, extracts the session ID, and returns the matching transcript excerpt (prompt, reasoning, command) from local session storage, or a shared store synced by a Stop hook.
I9: Several windows on one project collide on live shared resources (one session restarts a deployment while another is measuring it, two edit the same values file in different worktrees); state locks miss this and git only reveals it at merge. || Lease registry: a tiny local daemon (SQLite plus Unix socket) holds TTL leases on logical keys: `cluster/ns/deployment`, Terraform address prefixes, repo-relative file globs. A PreToolUse hook derives keys from each mutating command or Edit path and acquires a lease; if another session holds it, the agent is told who, why and until when, and can wait or pick other work. Leases auto-release on SessionEnd or TTL expiry; a CLI lists them.
I10: CLAUDE.md, AGENTS.md and skills accumulate facts (cluster names, versions, endpoints, "X is deprecated") that silently go stale; agents follow outdated instructions confidently and nothing tests the instructions themselves. || Executable memory: facts in instruction files carry inline checks, e.g. `<!-- verify: kubectl --context prod get ns argocd -->` or `<!-- verify: terraform version | grep 1.9 -->`. A nightly job with read-only credentials runs every check and, for failures, uses `claude -p` to draft a corrected line from the observed output, opening a PR. Until merged, a SessionStart hook injects a warning listing the failing lines so agents distrust them.
