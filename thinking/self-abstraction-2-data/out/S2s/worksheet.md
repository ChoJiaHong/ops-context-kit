# 工作表

目標方法（以下稱 M）：三份筆記合併後的版本。流程是：把具體問題抽象成一般問題類別，取得一般解法與其瓶頸，比較具體情境與一般類別的差異，把差異對接到瓶頸（資源、限制、被改變的假設），調整出情境化解法，再向上泛化找出優勢範圍。目標固定，只改變問題表徵，原始問題描述視為假設。

## 1. 參照

| 參照方法 | 核心 | 最擅長的問題 |
|---|---|---|
| 直接請 LLM 解題 | 憑訓練分佈，一次產出該問題類別的常見解 | 定義清楚、有標準解的常見問題 |
| Chain-of-Thought／分解規劃 | 把問題拆成步驟逐步推 | 結構明確、可拆解的推理或多步任務 |
| TRIZ | 把矛盾抽象成通用矛盾，查通用發明原則再還原 | 技術上有明確矛盾的工程問題 |
| 案例式推理／類比 | 找相似舊案例，搬移並微調解法 | 有相近歷史案例的問題 |
| 通用問題重述（reframing） | 換個說法或角度重新界定問題 | 問題描述含糊、視角受限的問題 |
| 設計思考／腦力激盪 | 發散產生大量點子再收斂 | 開放式、使用者需求不明的創新題 |

## 2. 綁定假設與瓶頸

| 參照方法 | 預設了什麼 | 造成的瓶頸 |
|---|---|---|
| 直接 LLM | 使用者的問題描述正確；問題屬於常見類別，常見解就適用 | 輸出類別通解；描述有誤時解錯問題（例：加機器，其實是 retry storm） |
| CoT／分解 | 問題表徵已經對；只需把推理做好 | 在錯的表徵上推得再仔細也沒用，不會去質疑問題框架 |
| TRIZ | 問題可被抽象成通用矛盾，通用原則可還原 | 抽象時丟掉情境特有資源，只給通用原則，不知道此地有什麼可用 |
| CBR／類比 | 有夠像的舊案例，相似處比差異處重要 | 搬案例時看相似不看差異；差異恰好是機會或陷阱時被忽略 |
| 通用 reframing | 換個說法就能得到更好表徵 | 沒有方向，不知道往哪個維度改；缺少錨點（一般解）可對照 |
| 設計思考 | 靠發散與使用者洞察就能出好點子 | 成本高、不收斂，且沒有系統地利用「此情境與一般情境的差」 |

共通預設：為了通用，這些方法都把情境當成可忽略或已被描述完整的背景；它們的瓶頸都來自「沒有拿具體情境去對照一般解的預設」。

## 3. 差異（M 對參照）

1. M 先取得「一般解」，再拿具體情境與一般類別做顯式對照；參照多半直接解，或只比較案例相似處。
2. M 的比較對象是「一般解的瓶頸」，不是整個問題，所以差異有方向。
3. M 把差異分類成新限制、缺少的限制、可用資源、被改變的假設。
4. M 允許資源重新詮釋（火車變成移動基地）。
5. M 把使用者問題視為假設，可修正表徵。
6. M 固定目標，只動表徵，避免問題漂移。
7. M 以相對優勢（對所有既有解的最大效用）判斷，不是判斷「既有解是否失效」；既有解仍可用但不是最佳也算。
8. M 向上泛化，輸出的是 (P*, 新解) 而非單一情境專用解。
9. M 有「拿掉在地特色還成立嗎」的反硬湊檢驗。

## 4. 作用與功能重述

| 差異（它是什麼步驟） | 對瓶頸做了什麼（功能） | 解掉哪個參照瓶頸 |
|---|---|---|
| 先取得一般解 | 提供對照錨點，讓「此處哪裡不同」可被判斷 | 通用 reframing 缺錨點；直接 LLM 只給通解 |
| 比較具體與一般 | 把情境事實從背景變成可計算的輸入 | TRIZ／CBR 丟掉或忽略情境特有資源 |
| 差異對接一般解瓶頸 | 只留下能鬆動瓶頸的事實，過濾雜訊 | 腦力激盪不收斂；CBR 只看相似 |
| 差異分類成限制／資源／被改變的假設 | 讓事實轉成可寫進問題表徵的條件 | CoT 在錯表徵上推理 |
| 資源重新詮釋 | 讓既有物件改當另一種角色，繞過瓶頸 | 各法都只用資源的原本用途 |
| 原問題視為假設 | 允許修正錯誤表徵 | 直接 LLM、CoT 預設描述正確 |
| 目標固定 | 防止表徵改動時偏離初衷 | 通用 reframing 容易漂移 |
| 以相對優勢判斷 | 不要求既有解失效，只要此處可以更好 | 只在「失效」時才換方法的作法 |
| 向上泛化 | 把單一發現延伸為一類問題的解 | 單一情境巧思不可重用 |

## 5. 範圍（找 P*）

沿三個方向調整問題：

- 往參照擅長的領域靠近（情境變得普通、與一般類別幾乎無差異）：差異 D 縮小，一般解的瓶頸不再被鬆動，優勢趨近 0。例：沒有特殊資源的一般山區搜尋，就是固定基地無人機。
- 往參照擅長的領域靠近（有標準解且瓶頸不在情境）：例如純演算法效率、純算力不足的問題，情境差異無法改變瓶頸，M 沒有優勢。
- 遠離（沒有成熟一般解）：沒有可抽象的一般類別，對照錨點不存在，M 退化成腦力激盪，無明確優勢。
- 保持在中間（有成熟一般解、一般解仍可用但有情境相關瓶頸、情境中存在能鬆動瓶頸的事實、事實可取得）：M 優勢最大。
- 向上泛化：阿里山鐵路 → 固定運輸路線深入搜索區 → 可移動補給載具的廣域搜尋；只要「存在可移動的補給或資源節點且瓶頸是往返成本」就仍有優勢；移除這個條件則優勢消失。
- 另一方面，問題描述本身有誤的情境（例：加機器 vs. retry storm）也屬於 P*，因為一般解（擴容）的預設「描述正確」被違反，M 仍有優勢。

P*：已有成熟的一般解、該解在具體情境下仍可用卻被某個與預設綁定的瓶頸卡住、且情境中存在可重新詮釋的事實，能鬆動該瓶頸，並且目標可驗證的問題。

## 6. 必要（逐一拿掉）

| 拿掉的元素 | 在 P* 上還有優勢嗎 | 判定 |
|---|---|---|
| 抽象成一般類別並取得一般解 | 沒有。沒有錨點就不知道哪裡不同，退化成通用重述或直接解 | 核心 |
| 找出一般解的瓶頸（綁定假設） | 沒有。差異沒有方向，變成盲目找特色，雜訊多、硬湊多 | 核心 |
| 比較情境與一般類別的差異 | 沒有。這是新資訊的唯一來源，拿掉就是一般解的換名 | 核心 |
| 差異對接瓶頸並重述為資源、限制、被改變的假設（含資源重新詮釋） | 沒有。有差異清單但不能轉成解法，等於只有描述 | 核心 |
| 目標固定並驗證 | 在效果上有，但容易漂移、得到不解原問題的方案；驗證是有效性的保障 | 核心（保障） |
| 原問題視為假設 | 在使用者描述正確的子範圍仍有優勢，只失去「描述有誤」的子範圍 | 非核心，是範圍擴充 |
| 向上泛化 | 在發現的原情境仍有優勢，只是不知道 P* 邊界、不可重用 | 非核心，是範圍界定程序 |
| 六個縮窄維度、向下 loop 逐層縮窄 | 有。差異可直接由一般類別對照得到，縮窄只是搜尋手段之一 | 非核心 |
| 反硬湊檢驗（拿掉在地特色） | 仍有優勢，這是驗證步驟 | 非核心，併入驗證 |
| 效用函數與形式化符號 | 有。不影響實際優勢 | 非核心 |

核心骨架：一般解錨點、假設與瓶頸、情境差異、功能對接、目標固定與驗證。
