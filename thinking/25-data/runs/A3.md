## P1
Solution: Identity-blind egress proxy — Run the agent and every child process in a container or network namespace whose only route out is a local mitmproxy-based proxy (HTTPS_PROXY plus NODE_EXTRA_CA_CERTS/SSL_CERT_FILE; nftables drops direct egress). On requests to the model API it rewrites the body, replacing the account email in the system prompt and context with a fixed alias (dev@example.invalid), so the model never learns the address and cannot put it in headers, scripts or commits. On every other request it scans URL, headers and body for the email and its variants (case, %40, base64, JSON/quoted-printable escapes, "at") plus a user PII list, then rewrites or blocks with a logged notice. Loopback and Unix-socket traffic bypass the proxy, so local calls are never denied. One config covers Claude Code, Codex and Gemini CLI.
Differs from existing: It acts on real traffic, not tool-call text, so scripts Claude writes, subagents and encoded forms are covered; it hides the email from the model without prompt.context hooks, so it works on Team/Enterprise and managed machines; loopback bypass removes the false positives; no vendor release needed.
Needs: A container or namespace for the agent and a trusted local CA. Nothing from the vendor, unless it adds certificate pinning; vendor-side fetches are protected only by the alias.

## P2
Solution: Policy-as-tests (permcheck) — One agent-neutral allow/ask/deny policy file, compiled three ways. (1) Native rules for Claude Code settings, Codex config and Gemini user-level policies; a launcher adds Codex trust entries for directories under approved roots. (2) One PreToolUse/PermissionRequest decision hook registered at user level in each agent, so subagents and skills hit the same rules; it parses commands into a shell AST (mvdan/sh), normalises `cd` into the workspace, env prefixes, `git -C`, quoted flags and wrapper commands, and denies what it cannot resolve (eval, `bash -c "$x"`). (3) A conformance suite: a mock model endpoint, set through each agent's base-URL option, emits a few hundred scripted tool calls (including subagent ones) in a throwaway sandbox after every agent update. It records what each agent actually did — allowed, prompted, denied — and fails with a rule-by-rule drift report, optionally pinning the last passing version.
Differs from existing: Existing hooks replace matching but nobody checks that enforced behaviour equals the written policy. Deterministic probes catch drift (yolo regressions, ignored policy files, subagent inheritance) before unattended runs, across Claude Code, Codex and Gemini, and fail-closed parsing plus the probe corpus supply the missing security review.
Needs: Hook and base-URL support in each agent. Vendor fixes remain needed where the harness overrides hooks (ExitPlanMode allow, Remote Control prompts); the suite detects these and pins versions.

## P3
Solution: Forge shadow bridge — A self-hosted service that mirrors chosen GitLab, Bitbucket (Cloud or Data Center) or Azure DevOps (Services or Server) repositories into private repos in a dedicated GitHub organisation, so every GitHub-only agent works on them unchanged. It subscribes to Jira, Linear, Azure Boards and GitLab issue webhooks: when a ticket is assigned to an agent user or labelled, the bridge syncs the mirror, opens a GitHub issue carrying the full ticket context and starts the agent through its existing GitHub entry point (`@claude` Action, `@codex` mention, Linear coding session, `claude --cloud`). When the agent opens a PR, the bridge pushes the branch to the origin forge, opens the linked MR/PR there, relays review comments both ways (an MR comment re-prompts the agent) and removes the shadow branch on merge. Origin branch protection and CI stay authoritative; only feature branches flow back.
Differs from existing: Instead of waiting for each vendor to support each forge, it reuses the vendors' mature GitHub path for all of them, covering Bitbucket Data Center, ADO Server and GitLab without Premium tiers, feature flags or betas, and closes the push-back loop that bundle uploads lack.
Needs: A GitHub organisation (free private repos), forge service accounts and webhooks, and organisational approval to hold code on GitHub. Nothing from the vendors.

## P4
Solution: Log-driven attention daemon — A background service on whichever machine runs the agent (including Remote SSH hosts) that fuses three signals: each agent's session logs (Claude Code ~/.claude/projects/*.jsonl, Codex ~/.codex/sessions, Gemini chat files), process state (CPU, child processes) and hook events when they fire. It keeps a per-session state machine — working, awaiting approval, asked a question, done, API error, stalled (alive but silent for N minutes) — and alerts only on states that persist past a short quiescence window, which drops /goal-continuation false 'done' alerts and duplicates. Alerts go to desktop, terminal bell, a small VS Code extension and phone (ntfy), escalating to phone if unacknowledged. The logs' own timestamps feed a statusline segment ('instruction 14:02 · last check 14:37') and an `agent-log` view of every turn, tool call and background check with wall-clock times.
Differs from existing: Hook-only notifiers fire late, miss API-error endings, double-fire on continuations and break on updates. Fusing logs, process state and hooks catches every ending and silent stall, works over SSH without subscriptions or Remote Control, and gives timestamps on any surface without patching webviews.
Needs: Undocumented log formats (version-pinned adapters that need updating when formats change) and a push service such as ntfy. Native in-chat timestamps would need the vendor.

## P5
Solution: Effect-based file gate — Judge Bash calls by what they changed, not how they are spelled. A PreToolUse hook on Bash snapshots the work tree into a shadow git index (separate GIT_DIR; `git add -A`, `write-tree`; configurable excludes); a PostToolUse hook snapshots again and diffs the trees. Every file written or deleted then goes through the same path rules as Edit/Write: a denied path is restored from the snapshot and the model is told why. Allowed changes are shown as a diff in the transcript, saved as a checkpoint that an `/undo-bash` command restores, and any nested CLAUDE.md or path-scoped rules for touched directories are returned as additionalContext. Since reads cannot be undone, Read deny rules are compiled into an OS sandbox (Seatbelt, or bubblewrap plus Landlock) wrapped around Bash. The same tracker works for Codex and Gemini shell tools.
Differs from existing: Pattern hooks are bypassed by python, heredocs and new tools; this sees every write whatever the language, so path rules, diffs, undo and nested rules apply whether the agent used Edit or Bash, which makes the harness's Bash-first steering harmless instead of fighting it.
Needs: Pre/PostToolUse hooks, git and an OS sandbox; snapshot cost grows with tree size. Native /rewind integration and dropping the Bash-first prompt would need the vendor.

## P6
Solution: Attested credential broker — A self-hosted, OpenBao-backed broker that cloud sessions ask for short-lived credentials instead of holding secrets. Bootstrap: where network secrets work, one broker token stored there is attached by the vendor proxy; where they do not (Team gaps, CMEK orgs), the session pushes a broker-issued nonce on a throwaway branch of an attached repo through the vendor's GitHub proxy, and the broker verifies the pusher from the push webhook, mapping it to allowed scopes, before issuing a 30-minute token. A `cred` helper, installed by the setup script, then supplies: cloud credentials via STS or workload identity federation (OIDC substitute), dynamic database users, private-registry tokens through npm/pip/git credential helpers, and a signing reverse proxy for SigV4 to R2 and other non-AWS hosts. Secret-needing setup steps move to a SessionStart hook. Fetching on demand means rotation needs no restart; each credential is scoped, logged and revocable.
Differs from existing: Network secrets only add HTTP headers for listed hosts; this also covers env-var and TCP uses, setup-time installs, R2, keyless cloud auth and mid-session rotation, including Team and CMEK accounts, with any value entering the VM short-lived. Unlike postern or mcp-warden, it serves vendor-cloud sessions.
Needs: Broker host on the environment's network allowlist, an attached repo the GitHub proxy can push to, OpenBao and cloud IAM trust. No vendor change; native OIDC would simplify bootstrap.

## P7
Solution: Change-set manager (xpr) — A GitHub/GitLab App plus a CLI and MCP tool the agent calls. The agent declares a change set — member repos, branches and dependency order — recorded as `.changeset/<id>.yaml` on each branch. The App cross-links the member PRs, opens one umbrella issue with a combined multi-repo diff, and adds a required `changeset` status check to each PR, which turns green only when every member is approved and an integration job, checking out all member branches together, passes contract and integration tests. A merge train then merges in dependency order, waiting for each upstream package publish or deploy before the next, and pauses with revert PRs prepared if anything fails. Per-repo policy (push allowed, draft only, required reviewers) lives in App config and is applied as rulesets. `xpr checkout <id>` recreates every branch as a local worktree and `xpr push` sends them back: multi-repo teleport.
Differs from existing: Existing tools put several repos in one session but emit unrelated PRs; this turns them into one reviewable, jointly tested unit merged in order, with per-repo policy and local hand-off, whichever agent or vendor produced the branches.
Needs: App permissions on each repo, branch protection with required checks, and CI that can clone several repos. No vendor change required.

## P8
Solution: Limit-aware task supervisor — A launchd/systemd user service that owns long tasks instead of a terminal. Tasks run headless (`claude -p --resume <id> --output-format stream-json`, `codex exec resume`) with a pre-set allowlist and a permission mode that denies rather than asks, so nothing stalls on a prompt; an interactive session that hits a limit is adopted by session ID (hook or one command). The supervisor reads the reset time from the structured error event, never from screen text; if it is missing, it probes with a minimal request on backoff, which also works when already over the limit. State lives on disk, so weekly resets days away, reboots and closed terminals do not matter, and an OS wake timer fires at the reset. It resumes with 'continue the interrupted task; re-check repo state first' and can optionally fail over to an API-key profile under a hard spend cap.
Differs from existing: Built-in auto-continue skips -p, background, weekly, sleeping-laptop and Remote Control cases and still stops on prompts; wrappers scrape changing text and fail when already limited. This is terminal-independent, reads structured events with a probe fallback, and survives sleep and reboots.
Needs: Headless resume by session ID (exists in both CLIs), OS wake timers, and use within plan terms. A documented machine-readable reset time from the vendor would remove probing.

## P9
Solution: Out-of-band task queue — A per-workspace queue file (`.agent/queue.md`, one task per block, optional `check:` command) edited in any editor or filled by `aq add "…"` from any terminal, a VS Code command or a phone (git push), so queuing never touches the chat input and cannot interrupt, fold into or be lost by it. A Stop hook delivers tasks: when a turn ends cleanly it runs the finished task's `check:` (e.g. tests); if that passes and the agent's last message does not end in a question or NEEDS_INPUT marker, it pops the next task and returns `decision: block` with the task text as the next instruction — one task per turn, FIFO. On a failed check, a question, an interrupt or a pause file it holds the queue and notifies. A statusline segment shows 'queue 3 · next: …'. Codex uses the same file through its Stop hook or `codex exec resume`.
Differs from existing: Built-in queues inject mid-turn, merge messages, interrupt in VS Code or lose input on desktop; existing hook queues deliver blindly. This is surface-independent, durable and reorderable as text, and releases each task only after the previous one finished, passed its check and is not awaiting an answer.
Needs: Stop hooks that can continue a session (Claude Code has them; where Codex lacks this, headless resume). No vendor change required.
