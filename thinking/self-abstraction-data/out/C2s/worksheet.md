# Worksheet

**採用方式**：把三份筆記當作同一方法的三個版本，先做「不變量抽取」（三版都出現、換掉就不成立的成分），再對每個成分做思想實驗式的「移除測試」（拿掉它，方法還能產出什麼？）。最後用「什麼條件下它勝過直接解題」反推最適合的問題類型。

## 1. 三版共同出現的成分
| 成分 | 筆記一 | 筆記二 | 筆記三 |
|---|---|---|---|
| 通用／既有解法當基準 | 現有解法 | Se | General Existing Solutions |
| 具體情境相對一般情況的差異 | 在地差異 D | Context Difference | ΔContext |
| 基準解法的弱點 | 限制 L | 瓶頸 L(Se,P) | New/Missing Constraint |
| 差異與弱點配對 | 差異能否解決限制 | Match(L,D) | Map ΔContext |
| 依配對改造基準 | 新方案 | Sn=Adapt | Context-adapted Solution |
| 防止偽創新／漂移 | 硬湊檢驗 | Advantage>0 | Goal(P_final)=Goal(P0) |

## 2. 移除測試
- 拿掉基準解法：無法判斷「新」，也無從定義瓶頸。必要。
- 拿掉情境差異：只剩通用解。必要。
- 拿掉瓶頸：差異無從篩選，會堆出一堆「有特色但無用」的點子。必要。
- 拿掉配對：變成列舉差異。必要，是核心動作。
- 拿掉優勢／參與檢驗：硬湊出現。必要，但屬驗收，非生成。
- 拿掉目標固定：問題漂移。三版中僅筆記三顯式處理，視為必要護欄。
- 縮窄／向下向上循環：是尋找差異的「搜索策略」，非本質；筆記三已改為固定問題、只換表徵，仍成立。降為可選。
- 抽象步驟：是取得通用基準的手段，併入「基準」。
- 創新：是結果而非目標。

## 3. 三版分歧與取捨
- 限制：筆記一偏「做不到」，筆記二修正為「可用但非最佳」。取後者（涵蓋較廣）。
- 向上泛化：筆記二用來找 P*；筆記三因漂移疑慮拿掉。取折衷：保留，但以原目標回驗。
- 資源重新詮釋（火車→移動基礎設施）是配對成功的關鍵手法。

## 4. 骨架（定稿）
基準解法、情境差異、瓶頸、配對、改造解法、驗收（優勢＋參與）、目標錨定。

## 5. 勝出條件分析
骨架比直接解題或自由發想強，當且僅當：
1. 有成熟通用解法可當基準（否則無差異可比）。
2. 具體情境有可觀察的特殊資源或限制，且常被忽略。
3. 瓶頸來自情境而非問題本質。
4. 解法優劣可比較（否則優勢無法判定）。
5. 目標穩定，可固定。
例：阿里山搜救（鐵路）、SRE／coding／support 中把表面請求還原成真正瓶頸（較弱的相符，因側重診斷而非利用資源）。

## 6. 不適用
- 無成熟基準的前沿問題。
- 情境無特殊差異（標準化、通用情境）。
- 瓶頸是本質性的（物理或理論極限）。
- 效用無法比較、無法驗收。
- 純診斷／問題本身描述不清：需先釐清，該骨架只在其後。
- 急迫、成本極低的例行決策。
