# 05 自我抽象實驗：用原模型抽象原模型，比直接抽象好嗎？

結論：**不會比較好。** 同樣用 Sonnet 執行時，用原模型抽象原模型的兩份方案，平均只比直接抽象多 1 分（滿分 35），在誤差範圍內；兩位評審也認不出哪些方案用了原模型。影響結果最大的是分析的深度和使用的模型：用 Opus 直接抽象的兩份方案分數最高，也是唯一有實質新洞見的。

資料都在 [self-abstraction-data/](self-abstraction-data/)。

## 1. 設計

- **輸入**：所有組別只拿到同一份原始筆記整理（[00](00-original-notes.md)），看不到彼此、也看不到任何先前的骨架草稿。
- **組別**：
  - **M 組**：規定用原模型的十個步驟分析原模型本身（抽象 → 一般解 → 瓶頸 → 向下縮窄 → 差異配對 → 調整 → 向上泛化 → 對模型元素做硬湊檢驗 → 目標一致）。
  - **C 組**：用執行者自己認為最好的方式，**不准**用原模型的流程當分析程序。
- **輸出格式固定**：核心骨架（3–7 個元素）、形式化、最符合的問題 P\*、不適用的情況、為 P\* 調整後的模型，正文不超過 900 字，且不准提到用了什麼分析方法。
- **評分**：標準在產生方案之前寫好（[criteria.md](self-abstraction-data/judge/criteria.md)）。七個面向各 1–5 分：忠實、鑑別、遷移、邊界、可操作、洞見、精簡。另有六道遷移測試題：除錯、預測、學習、agent 工作流，以及兩題預期不適用的（定義明確的最短路徑、毫無參照的全新領域）。
- **評審**：Sonnet 與 Opus 各一位，方案匿名、兩位看到的順序不同。最後請評審猜哪些方案用了原模型。

### 執行中的變動

- 第一次用 Opus 執行 M 組時，兩次都被 Anthropic 的安全機制中途擋下。錯誤訊息說明這有時會發生在正常的對話，並建議換模型重試。
- 於是 M 組與 C 組都改用 Sonnet 各重跑兩次，讓兩組用同一個模型比較。
- 先前已完成的兩份 Opus C 組方案保留，一起送評，作為「模型與深度」的參考。

## 2. 結果

兩位評審的平均分數（七面向總分，滿分 35）：

| 方案 | 組別 | 模型 | 分數（Sonnet 評審 / Opus 評審） | 平均 | 洞見 F |
|---|---|---|---|---|---|
| M1s | 用原模型 | Sonnet | 25 / 25 | 25.0 | 2.0 |
| M2s | 用原模型 | Sonnet | 22 / 25 | 23.5 | 1.5 |
| C1s | 自己的方式 | Sonnet | 21 / 24 | 22.5 | 1.5 |
| C2s | 自己的方式 | Sonnet | 24 / 24 | 24.0 | 2.0 |
| C1 | 自己的方式 | Opus | 26 / 32 | **29.0** | 4.5 |
| C2 | 自己的方式 | Opus | 25 / 28 | 26.5 | 5.0 |

- **同模型比較**：M 組平均 24.25，C 組平均 23.25，差 1 分。同一組兩份之間就差 1.5 分，同一份在兩位評審手上最多差 3 分，所以這 1 分不代表差異。
- **四份 Sonnet 方案的洞見都很低**（1.5–2.0），基本上是把筆記重新整理一遍。
- **評審猜不出來**：兩位評審都把兩份 Opus 方案猜成用原模型做的（機率 0.6–0.65），都猜錯了。原模型組沒有留下看得出來的方法痕跡。
- **兩位評審都把 C1 排第一**。排名：Sonnet 評審 C1 > M1s > C2 > C2s > M2s > C1s；Opus 評審 C1 > C2 > M1s > M2s > C2s > C1s。
- **遷移題**：六份都正確排除 T5（最短路徑）和 T6（全新領域）。分歧在 T1（除錯）：部分方案把診斷型問題排除在 P\* 外，Opus 評審認為其實套得上，見 [04 第 5 節](04-prototype-and-skeleton.md#5-兩層的關係)。

## 3. 找到的骨架

六份方案收斂到同一條主線：**基準解 → 瓶頸 → 情境差異 → 配對 → 改造 → 檢驗**。C1 多出「綁定假設」和「功能重述」兩點，並據此回答了原筆記自列的「下一次往哪個維度縮窄」。完整內容整理在 [04 原模型當原型](04-prototype-and-skeleton.md)。

## 4. 解讀

- 用原模型分析原模型沒有額外價值。這和 [01](01-evaluation.md) 的判斷一致：原模型擅長在情境裡找出被忽略的資源，而「抽象一份方法」這種任務沒有這種資源可找。
- 真正的差別來自投入的深度。兩份 Opus 方案每份花 4–6 分鐘、做了反事實的元素移除和案例校正；Sonnet 方案每份不到一分鐘。

## 5. 限制

- **缺一格**：「Opus＋原模型」沒有數據，所以在 Opus 這一層無法比較。
- **樣本小**：每組只有兩份，評審只有兩位。
- **同一系列模型**：執行者和評審都是 Claude 系列。
- **分組重疊**：C 組被禁止使用原模型流程，但 C2 的「逐一拿掉元素」在形式上接近硬湊檢驗（判準不同），兩組不是完全互斥。
