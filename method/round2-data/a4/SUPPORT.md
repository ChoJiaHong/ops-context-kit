# 輔助檔案

路徑皆相對於工作區根目錄（與 RULES.md 中的 `ops/...` 一致）。`ops/sessions/`、`ops/scripts/` 是 agent 執行時自行建立的資料夾，不屬於輔助檔案。

## 1. ops/session-template.md

用途：每個 session 建檔的格式。前六行欄位固定，讓任何 session 都能用 Grep 一次彙整所有 session 的狀態。

````markdown
# <ID> <一句話目標>
狀態: 進行中
環境: <prod-eks | stg-eks | web1-3 | 本機>
鎖定: 無
授權: 無
更新: <YYYY-MM-DD HH:MM>

<!-- 前六行欄位名固定，給 Grep 用。
狀態只用：進行中 / 等使用者 / 阻塞 / 完成 / 放棄
鎖定：正在變更的正式資源，例 prod-eks/payments/deploy/api、web2:nginx
授權：使用者在本 session 預先授權的操作與範圍，沒有就寫「無」 -->

## 完成條件
- 

## 事實（附來源指令或檔案）
- 

## 假設（[?] 待查 / [v] 證實 / [x] 排除）
- [?] 

## 決定與變更紀錄
- HH:MM｜做了什麼｜在哪（context/ns 或主機）｜回滾方式｜驗證結果

## 下一步
- 

## 交接摘要（收尾或交棒時填）
- 結論：
- 留下的變更與回滾方式：
- 未完成與後續建議：
````

## 2. ops/change-card.md

用途：正式環境（B/C 級）變更前給使用者看的確認卡，讓使用者一眼判斷能不能做，也讓失敗時的處置事先講好。

````markdown
# 正式環境變更卡（B/C 級動手前貼給使用者）

【變更卡】<ID>-<序號>
- 目標：<prod-eks / namespace / 資源> 或 <web1 → web2 → web3：服務>
- 原因：<對應哪個證據或假設>
- 指令（逐字、依序）：
  1. 
- 影響：<會不會中斷、動到幾個 pod 或哪台、預計多久>
- 前置：<現況備份路徑 ops/sessions/<ID>/...；stg 是否驗證過；鎖定已寫入>
- 驗證：<每一步之後跑什麼指令、看到什麼算成功>
- 停止條件：<出現什麼就停>
- 回滾（逐字）：
  1. 
- C 級另附：備份位置，以及如何確認備份可用

請回覆「同意」執行，或指出要改的地方。

## 使用規則
- 一張卡可包含一組有順序的步驟（例：三台逐台 reload），每步之間都要驗證。
- 觸發停止條件：立即執行卡上的回滾（已含在同意範圍內），然後停手回報，不自行改試別的修法。
- 指令、目標、範圍任何一項要改，就出新卡重新取得同意。
- 執行後在 session 檔「決定與變更紀錄」記一行，並更新「更新:」時間。
````
