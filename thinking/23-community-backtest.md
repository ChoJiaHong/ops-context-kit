# 23 社群回測：模型找出的「問題＋新解法」，後來社群真的需要嗎

2026-11-07。接 [21](21-backtest.md) 的設計檢討。

## 為什麼做

要回答決定 3：模型找到的解法值不值得採用。同時順便回答決定 1：模型值不值得繼續發展。

[00](00-original-notes.md) 的模型主張：用它可以找出一組問題 P 和新解法 Sn，而且 P 是真的、Sn 是新的、Sn 比現有最好的解法 Se 好，而且這件事不用模型比較難做到。這次逐一檢查這四點，每一關都不由產出答案的 AI 自己評。

和 21 的差別：21 拿 14 個工具當標準答案，看模型能不能撞到它們，找到別人沒做過的好點子反而拿 0 分。這次反過來，**模型提出的每一組都拿去 GitHub 逐一查證**。

## 設計（作答前登記，之後不改）

**時間切點 T = 2026-06-30**，也就是作答模型的知識截止日。T 之前的社群資料給模型找問題；T 之後的社群資料拿來驗證，模型完全看不到。

**找問題用的資料**（只用 GitHub，用 REST 搜尋 API 依下列規則自動抓取，不由我挑；每則保留標題、建立日期、反應數、留言數、內文前 600 字）：

| 組 | 搜尋條件（建立時間都是 2026-01-01..2026-06-30） | 排序 | 取幾則 |
|---|---|---|---|
| S1 | `repo:anthropics/claude-code is:issue` | 反應數 | 100 |
| S2 | `repo:openai/codex is:issue` | 反應數 | 40 |
| S3 | `repo:google-gemini/gemini-cli is:issue` | 反應數 | 20 |
| S4 | `repo:cline/cline is:issue`、`repo:Aider-AI/aider is:issue` | 反應數 | 各 10 |

共 180 則，全文在 [23-data/corpus.md](23-data/corpus.md)。

規則改過一次（作答前）：原本還有「含 `"claude code"` 和 kubectl、terraform 等關鍵字的 issue，依留言數排序」。實際抓下來大多是機器人自動產生的 issue（每日 CI 報告、懸賞活動，留言數上千），改成反應數排序也一樣雜，所以換成主要 agent 工具的 repo。代價是資料偏一般開發，infra 專屬的痛點變少。



**組別**（提示全文在 [23-data/arms/](23-data/arms/)）：

| 組 | 方法 |
|---|---|
| A | 直接做 |
| C | 原模型＋三個補充（同 21 的英文版） |

- 各跑 3 次，每次是一個獨立的 agent。
- 只准讀資料檔和最後寫一次答案，不准上網。上網就會看到 7 月以後的東西。
- **只交結果，不要求寫出思考過程**：21 發現要求寫出分析會被安全機制擋下。
- 每次交 5 組，依價值排序。每組寫 P、Se（到 6 月為止現有最好的解法和它的不足）、Sn（怎麼運作）、Check（什麼可觀察的證據能顯示 Sn 比 Se 好）。

**查證**：30 組全部打亂、拿掉組別，交給查證 agent。查證 agent 可以用 GitHub REST 搜尋和網路搜尋，每關都要附上連結。

| 關 | 問題 | 過關條件 |
|---|---|---|
| G1 真問題 | 7 月之後有人回報 P 嗎 | 2026-07-01 之後建立、讀過確認相關的 issue 至少 3 則，來自至少 2 個不同的 repo 或作者 |
| G2 新 | 6 月以前已經有人這樣做了嗎 | 找不到 2026-07-01 以前就存在、核心機制相同的工具或產品功能 |
| G3 有人要 | 7 月之後有人做出來或提出需求嗎 | 至少 1 個：7 月後建立、機制大致相同的 repo，或明確要求這種功能的 issue |
| G4 比較好（只當參考） | 7 月之後的具體失敗案例，Sn 和 Se 誰處理得了 | 最多 3 個案例，分別判斷，回報次數 |

- 7 月之後才出現的工具不影響 G2（它們算 G3 的證據）。
- 我抽查約 20% 的查證連結：連結存在、日期對、內容相關。抽查錯誤率超過 20% 就整批重查。

**主要指標**：每次執行的 5 組裡，有幾組同時通過 G1、G2、G3（記為「合格新解」）。

**次要指標**：各關通過率、G4 的勝負。

## 預測與判定

| | 預測 | 判定規則 |
|---|---|---|
| H1 | C 的合格新解比 A 多 | C 每次平均至少比 A 多 1 組，才算模型有用；差距小於 1 組，記為「這次看不出差別」 |
| H2 | 兩組都有不少 Sn 過不了 G2：直接想到的往往是已經有人做的 | 只記錄，不判定 |

- 合格新解就是決定 3 的候選，可以進下一步的實地試用。
- C 被安全機制擋下時，用同一個提示重跑一次；再被擋就記錄為缺資料。

## 限制（事先承認）

- 社群資料是很多人的平均處境，不是使用者自己的處境。這次測的是模型在公開資料上的能力。
- G3 用「有沒有人做或有沒有人要」代表價值；有人做不等於做得好。
- 查證是 AI 做的，只靠連結和抽查來約束。
- 每組只跑 3 次，差距小的時候看不出來。
