## 核心骨架
- 基準解：一般類別的成熟解法，既是比較原點，也是被改造的母體。
- 瓶頸變數：基準解受限的那個可量化的量（距離、容量、次數、成本）。
- 情境餘裕：具體情境擁有、通用解為求普適而不能假設的資產或規律。
- 功能重述：把餘裕從「它是什麼」改寫成「它能對瓶頸變數做什麼」，新意由此產生。
- 嫁接：保留基準解主體，只把重述後的餘裕接到瓶頸位置。
- 承重檢驗：同一目標與指標下新解勝過基準解，且拿掉餘裕後優勢即消失。

## 形式化
Sn = Se ⊕ φ(d) ⊕ X（d ∈ Δ(Ps, Pg)；φ：功能重述；X：其餘改動）
成立：φ(d) 作用於 Se 的瓶頸變數，且在 Ps 下 U(Sn) > max U(Se) ≥ U(Sn − φ(d))
優勢來源：Se 只能假設類別共有的最少資源，Δ 中的資產對它是系統性閒置。

## 最符合的問題 P*
通用解成熟卻卡在結構性瓶頸的問題上，為一個具體情境設計靠其獨有資產勝過通用解的方案。
進入條件：
1. 瓶頸是單一可量化變數，且不會很快被通用技術的進步解掉。
2. 情境中有主要用途不同、仍有剩餘容量的既有資產，且它本來就沿瓶頸的維度運作（會移動、定期經過、已部分有序）。
3. 解題者有在地知識或取用權，看得見也動用得了這個資產。
4. 目標固定，新舊解可用同一指標比較。

## 不適用的情況
- 沒有成熟基準解的全新問題：瓶頸與餘裕都沒有參照點。
- 需求本身說錯的診斷型問題（如 CPU 高其實是 retry storm）：差異只用來推翻假設，比對近期變更等現成診斷法更直接。
- 瓶頸是多因的行為或制度問題（如霸凌、拖延）：餘裕沒有單一的靶可對準，易淪為貼標籤。
- 情境同質，或目標要求一套解通吃所有情境：沒有餘裕可用，或解無法移轉。

## 為 P* 調整後的模型
1. 定基準與指標：寫下通用解與一個比較指標（如平均抵達時間）。
2. 把瓶頸寫成變數：確認它是結構性的，若通用技術很快會解掉就停。
3. 沿瓶頸維度找資產：不盲目縮窄，直接問「此情境中什麼已沿這個維度運作、還有剩餘容量？」找到即停。
4. 功能重述並嫁接：把資產改寫成對瓶頸的功能（列車→移動補給點），接上基準解的瓶頸位置，其餘不動。
5. 承重與代價檢驗：拿掉資產優勢是否消失；同一指標是否勝過基準解；原主用途、排程與法規衝突是否吃掉優勢。
6. 標出可移轉範圍：把資產改寫成抽象描述（「深入目標區的固定路線載具」），列出同樣具備它的其他情境。
