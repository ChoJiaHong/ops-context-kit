### Analysis
What distinguishes this work from ordinary agentic coding is that agents act on shared, live, stateful systems (clusters, cloud accounts, Terraform state, Helm/Argo, hosts) from many concurrent sessions, while one human is the scarce resource for approval and review. Current tooling isolates files (worktrees, branches) and filters command strings (allow/deny lists, hooks). The real risk sits elsewhere:

1. State outside the repo. Worktrees do nothing for kube contexts, Terraform state, releases or hosts, so sessions that are each locally correct still collide. Sessions inherit the human's global credentials, so each has full power, a context switch in one leaks into others, and audit logs cannot attribute actions.

2. Enforcement at the wrong layer. String-matching rules cannot tell dev from prod and are bypassed the moment an agent writes a script. Real enforcement belongs in credentials, saved plans and ownership metadata; hooks should route and annotate, not be the security boundary.

3. Unverified completion. Agents stop when the diff looks right; in infra, done means converged: rollout healthy, GitOps synced at that commit, plan empty. GitOps lag makes 'merged' look like 'done', and direct kubectl fixes fight the controller.

4. World state missing from context. Compaction, window handoff, agent switching and rollback all need a record of what changed outside git; today it is scattered across transcripts and shell history.

5. Human attention does not scale. Ten sessions produce interleaved prompts in separate terminals without risk context, so the human rubber-stamps or bottlenecks.

6. No compounding. Corrections die with the session, secrets leak into transcripts, and verbose infra output burns context.

Ranking: likelihood times severity of harm, weighted by how poorly existing tools cover it. Over-broad credentials and collisions can cause outages, so they lead; false completion and approval overload are the main throughput limits; the ledger, plan binding and GitOps guard close specific correctness gaps; secrets, learning and context hygiene are recurring costs. I skipped what is already reasonably served (multi-session tmux managers, notification hooks, worktree creation, generic PR review bots). Each item is one buildable mechanism, mostly a small local daemon plus hooks; where an agent lacks equivalent hooks, the same logic ships as PATH shims around kubectl, helm, terraform and ssh, so Claude Code, Codex and Cursor sessions share one coordination layer.
### Items
I1: Every agent session inherits the human's global kubeconfig and cloud profiles: one session's context switch redirects others, every session holds prod-admin power, and cloud/Kubernetes audit logs cannot attribute an action to a session or task. || Session credential broker: a SessionStart hook reads task scope (accounts, clusters, namespaces, read/write) from .task.yaml and exports, via CLAUDE_ENV_FILE, a private KUBECONFIG and AWS config holding only short-lived credentials: STS AssumeRole with session tags carrying session/task IDs, and TokenRequest tokens for a per-task ServiceAccount bound to scoped Roles. Sandbox rules deny reading the human's ~/.kube and ~/.aws. Default read-only; write elevation needs human approval. Audit logs now name the session.
I2: Parallel sessions collide on state worktrees cannot isolate (cluster namespaces, Terraform state, Helm releases, Argo apps, SSH hosts) and on files when windows share one checkout, overwriting each other's plans, applies and edits. || Live-resource lease broker: a local daemon (SQLite, unix socket) plus a PreToolUse hook or PATH shim. The hook maps each kubectl/helm/terraform/argocd/ssh invocation, and Edit/Write on shared checkouts, to resource keys (context/namespace, state backend key, release, host, file path) and requests a read or write lease tagged with session and task. Conflicting writes block with 'held by session X doing Y since T'; leases expire on SessionEnd or missed heartbeat. Reads are shared.
I3: Agents declare multi-part infra tasks done when the diff looks right, not when the system converged: rollouts unhealthy, Argo not yet synced to the commit, Terraform still showing drift, or later subtasks silently skipped. || Acceptance contract runner: before any mutating command (PreToolUse gate), the agent must write .task/accept.yaml and the human must ack it; the file is hashed so later weakening requires re-ack. Each subtask gets a probe command, predicate and timeout, e.g. `argocd app wait X --revision $SHA --health`, `terraform plan -detailed-exitcode` exits 0. A Stop hook runs all probes, blocks stopping on failure and feeds failing output back; the final report embeds probe evidence.
I4: With many parallel sessions, permission prompts are scattered across terminals, arrive without risk context, and block sessions until noticed; the human either rubber-stamps risky commands or becomes the bottleneck that idles every agent. || Central risk-ranked approval queue: a PreToolUse hook classifies each command (read/mutate, environment from target context, blast radius from parsed resource kind and count) and auto-allows low risk. Others are POSTed to a local queue server while the hook long-polls. One web/TUI view lists pending requests from all sessions sorted by risk, each with the session's task, exact command, and rendered diff or plan summary; decisions (allow, deny with reason, allow-similar-for-this-task) return to the hook.
I5: Changes made outside git (kubectl patches, helm upgrades, terraform applies, host edits) live only in scattered transcripts. After compaction, a window switch or handoff to another agent, nobody knows what was changed, where, or how to undo it. || Mutation ledger: a Pre/PostToolUse hook pair appends one JSONL record per mutating infra command to ~/.agent-ledger/<task>.jsonl: session, command, target, exit code, and undo anchors captured beforehand (helm revision, terraform state serial and plan file, `kubectl get -o yaml` of patched objects, file backups for SSH edits). SessionStart hooks, which also fire after compaction, inject a compact 'changed so far / not reverted' table; `ledger undo <id>` executes the inverse from the anchors.
I6: Agents run `terraform plan`, summarize it, then `apply -auto-approve`, which re-plans against possibly changed state or code; the human approved a summary, not the actual change, and replacements or destroys hide in long plan output. || Plan-bound apply gate: a PreToolUse hook rejects any `terraform apply` (and tofu/terragrunt equivalents) not given a saved plan file. When a plan is saved, a PostToolUse hook runs `terraform show -json`, extracts deletes, replaces, IAM/security-group/public-exposure changes and counts into a deterministic summary (not model-written), stores it keyed by plan SHA-256, and requests approval. Apply passes only for an approved, unmodified plan file; Terraform itself rejects stale plans.
I7: Agents fix things with `kubectl edit/apply/scale` on resources owned by Argo CD or Flux; the controller reverts it minutes later, or self-heal is off and live state drifts from git, so the 'fix' is lost or becomes hidden debt. || GitOps ownership guard: a PreToolUse hook resolves each mutating kubectl target, reading tracking labels/annotations (argocd.argoproj.io/instance, kustomize.toolkit.fluxcd.io/name) and walking ownerReferences. If GitOps-owned, it denies and returns the source location: Application/Kustomization repo, path, chart, and the values file and key that render the field (found by rendering with a unique sentinel per values key and seeing which lands in the field). Emergency override requires approval and auto-files a reconciliation task in the ledger.
I8: Agents routinely pull secrets into context (`kubectl get secret -o yaml`, `terraform state pull`, `.env`, host config files), sending them to the model provider and persisting them in plaintext local transcripts. || Secret-shape redactor: a PreToolUse hook uses updatedInput to pipe known secret-bearing reads (Kubernetes Secrets, tfstate, .env, vault read) through a filter that replaces values with `<redacted sha256:8 len:N>`, keeping keys and structure so the agent can still compare and debug. When a command needs a real value, the agent writes a handle (`secretref://ns/name/key`) that a trusted exec wrapper resolves at run time, so plaintext never enters context or transcripts.
I9: Corrections the human gives in one session ('use the prod-eu context alias', 'never helm upgrade without --atomic') never reach future sessions, other agents or other repos, so the same mistakes recur and instruction files stay stale. || Correction miner: a nightly headless `claude -p` job parses Claude Code, Codex and Cursor transcripts, extracting (a) user turns that reject or redirect a tool call and (b) failed commands followed by a corrected retry. It clusters them by command family and repo, keeps clusters seen in at least two sessions, and opens PRs adding a rule to the right CLAUDE.md/AGENTS.md scope or a deny pattern to hooks, each citing transcript excerpts as evidence for human review.
I10: Infra commands produce huge outputs (`kubectl get -A -o yaml`, describe, logs, terraform plan, journalctl over SSH) that flood context, trigger early compaction, and bury the few relevant lines; agents then re-run commands or truncate blindly with head. || Output spooler: a PreToolUse hook rewrites matching commands via updatedInput to `spool --kind <type> -- <cmd>`. Spool saves full output to /tmp/spool/<session>/<n>.log, preserves the exit code, and returns a type-aware digest under a token budget: logs deduplicated into templates with counts, errors and first/last occurrences; `get` filtered to non-ready objects; plans reduced to change counts and destructive actions; YAML stripped of managedFields and status noise. The digest ends with the spool path for grepping.
