### Analysis
Forward: failure → tool: take a concrete failure in this workflow, design the smallest mechanism preventing it. Backward: tool → failure: drop that tool into the real workflow (many windows, GitOps, ssh hosts) and find how it is bypassed, breaks or adds burden; that is the next failure. Each end starts the other. Progress = a backward step yields a failure existing tools (worktrees, prefix permissions, TodoWrite, terraform locks, Argo, ccusage) don't handle. Stop when backward steps only return solved or duplicate failures.

Loop. F1 Two sessions apply to one namespace → lease broker keyed cluster/ns/object. B1 Key is parsed from the command, but the real target is the shared kubeconfig current-context, which another window can switch; worktrees isolate files, not ambient state. F2 → per-session target pinning. B2 Pin and lease rely on parsing; `ssh host '…'`, `bash -c`, `make deploy` hide verb and target; prefix rules see only `ssh`. F3 → unwrapping semantic gate. B3 Gate asks the human on prod apply, but the apply re-plans; approval doesn't bind execution. F4 → plan-hash-bound approval. B4 Apply exits 0; agent says done; in GitOps the deploy happens after the session. F5 → evidence-checked completion with deferred watcher. B5 Watcher finds breakage later; imperative patches made during debugging can't be listed or reverted. F6 → mutation journal with provenance. B6 Gates, leases and watchers multiply interruptions across windows; the human approves blind and blocked sessions idle. F7 → attention router. B7 Router shows the request, but the session has compacted away 'never touch prod-eu'; a Codex window never knew it. F8 → task ledger whose target constraints compile into gate rules (closing back onto F3). B8 Ledger, journal and router persist outputs to disk; `kubectl get secret -o yaml` puts secrets there and into context. F9 → fingerprint redactor. B9 Redactor already rewrites output; remaining cost is size: plans and yaml burn tokens, truncation loses the destroy line. F10 → output shaper. B10 Ledger and memory facts rot (renamed Argo app); F11 executable facts, ranked 11th, cut. B11 returned only solved items (instruction sync tools, ccusage) → stop.

Finding: the loop kept returning to the gate's parsed (verb, target) record; pinning, leases, journal, redaction, shaper and router all consume it, so build the gate first even though wrong-target pinning ranks top by damage. Ranking: severity × daily frequency.

### Items
I1: Parallel sessions share ambient target state: kubectl current-context, AWS_PROFILE, gcloud config, terraform workspace. Worktrees isolate files, not these; one agent's `kubectl config use-context prod` silently retargets every other session's next command. || Session target pinner. SessionStart hook creates ~/.agent-sessions/<id>/, copies a kubeconfig containing only the declared cluster/context, and writes KUBECONFIG, AWS_PROFILE, CLOUDSDK_CONFIG, TF_WORKSPACE to CLAUDE_ENV_FILE (shell wrapper for Codex/Cursor). Target is chosen from the worktree's .agent-target file or asked once. A PreToolUse hook rejects `use-context`, `--context`, `--kubeconfig`, `workspace select` and profile overrides that differ from the pin; switching targets requires an explicit `pin set` command the human approves. Statusline shows the pinned target.
I2: Permission rules match command prefixes, so `kubectl` allows `kubectl delete`, and `ssh host '…'`, `kubectl exec`, `bash -c`, `make deploy` or generated scripts hide the real verb and target from both rules and hooks. || Semantic infra gate (PreToolUse). Parses the command into a shell AST, recursively unwraps ssh, bash -c, kubectl exec, xargs, env; expands make targets via `make -n` and inlines called scripts. Each leaf is classified by per-CLI verb tables into read/mutate/destroy, and its environment from the pin, host inventory tags or tfvars path. A policy matrix (verb class × env) returns allow, ask with a one-line risk summary, or deny. Unparseable commands that could mutate default to ask.
I3: Humans approve a `terraform plan` or `helm diff` shown in chat, but the agent then runs `apply`/`upgrade` which re-plans; edits, state drift or a different var file mean what executes differs from what was approved. || Plan-bound approval. The gate rewrites `terraform plan` to `-out=<session>/p.tfplan`, renders `terraform show -json` into a summary (counts, every delete/replace address) and asks the human; approval stores the planfile's sha256. `terraform apply` is then allowed only as `apply <that planfile>` with matching hash; Terraform itself rejects it if state moved. For Helm, approval hashes `helm diff upgrade` output; the upgrade runs only if a fresh diff hashes identically.
I4: Agents report 'deployed and healthy' from a successful command or merged PR. In GitOps the merge is not the deploy: Argo/Flux reconciles minutes later, after the session ended, so failures surface to nobody. || Evidence-checked completion. Stop hook requires .agent/claims.yaml with one claim per ledger subtask: a read-only check command and expected result (`argocd app get x -o json | jq .status.health.status` == Healthy). The hook re-runs checks through the gate in read-only mode and blocks Stop listing failures. Checks needing future reconciliation are queued with the commit SHA to a poller that waits until Argo reports that revision synced, then runs them and resumes the session headlessly (`claude -p --resume`) on failure.
I5: With 5–10 parallel windows, the human polls terminals to find which session waits on approval, asked a question, loops on the same error, or finished; approvals get granted without context, and blocked sessions idle for hours. || Attention router. All sessions' hooks (Notification, Stop, gate asks, PostToolUse errors) append events to a local SQLite bus. Gate asks become blocking: the hook writes a request row and polls for a verdict; a Stop hook can likewise wait and return the human's reply as its block reason, continuing the session. A TUI lists only items needing the human, ranked by risk and wait, each showing goal, pinned target, last actions, risk summary. Three identical command+error hashes flag a loop.
I6: Two agents working the same environment from different worktrees mutate the same live objects—Helm release, namespace, Terraform module, host config—concurrently. Terraform locks only one state during apply; kubectl, helm and ssh have no cross-session coordination. || Live-resource lease broker. The semantic gate derives a resource key for each mutating leaf command (cluster/ns/kind/name, helm release, tf state+address, host:path) and acquires a lease before allowing it: Kubernetes keys as coordination.k8s.io Lease objects in the target cluster (visible across machines), others in a shared DynamoDB/SQLite table. TTL renewed by PostToolUse, released at SessionEnd; a namespace lease blocks objects inside it. Conflicts are denied with holder session, goal and age; the human can break leases.
I7: Long multi-part tasks lose user constraints ('never touch prod-eu', 'keep CIDR 10.20/16') and pending subtasks at compaction or when handed to another session or tool; TodoWrite lives inside one session and is not enforced. || Task ledger. A UserPromptSubmit hook extracts constraint-like sentences (never/only/must/don't) and asks the agent to confirm them into .agent/ledger.yaml beside subtasks with acceptance checks and status. SessionStart (including source=compact and resume) re-injects the ledger; constraints that name targets compile into gate deny rules, so they are enforced, not remembered. Stop blocks while subtasks are open unless marked deferred with a reason. Because it is a plain file, Codex or Cursor sessions read the same ledger via AGENTS.md pointer.
I8: Agents routinely run `kubectl get secret -o yaml`, `terraform output`, `cat .env` or `helm get values` while debugging; secret values enter model context and local transcripts, and hooks generally cannot scrub Bash output after it runs. || Secret fingerprint filter. A PreToolUse hook uses updatedInput to pipe secret-emitting commands (kubectl get secret, terraform output, helm get values, env, .env/tfvars reads, vault read) through a redactor that keeps structure and keys but replaces each value with `<secret:sha256-8:len>` of the decoded value. The agent can still verify presence, cross-environment equality and rotation without seeing values. When a value must flow onward, a `secretref` helper pipes it straight into the consuming command, never to stdout.
I9: Agents debugging live systems make imperative changes—`kubectl patch/scale/edit`, `helm rollback`, editing files over ssh—outside Git. File checkpoints don't cover them, so nobody can list or revert what a session changed, or tell which session did it. || Mutation journal. Before each mutating leaf the gate allows, a PreToolUse hook saves a before-image (`kubectl get -o yaml` minus managedFields/status, current `helm history` revision, remote file copy) to <session>/journal/NNN and injects provenance: `--field-manager=agent-<session>` plus an annotation for kubectl, a commit trailer for git, a syslog line on hosts. `agent-undo <session> [--to NNN]` shows a diff, then restores in reverse order, refusing objects whose resourceVersion moved since; `agent-whodid <object>` maps managedFields to the session transcript.
I10: Infra outputs are huge and noisy—`terraform plan` on large states, `-o yaml` with managedFields, `kubectl get pods -A`, Helm renders—so they burn tokens and get truncated, often cutting the destroy summary or the failing line the agent needed. || Output shaper. A PreToolUse rewrite, applied after the secret filter, tees full output to <session>/out/NNN.log and pipes stdout through per-command reducers: plan → action list per address, deletes first, plus summary line; yaml → drop managedFields, last-applied annotation, status noise; pod lists → non-Ready rows plus counts; logs → deduplicated lines with counts, errors with context. Output ends with the log path for grep. Reducers are prioritized by measured tool-result tokens per command pattern in transcripts.
