### Analysis
Diverge (25 candidates): (1) shared kubeconfig/AWS profile state retargets agents; (2) parallel sessions collide on live targets; (3) permissions match strings, not effects; (4) approval fatigue; (5) imperative hotfixes never backported to GitOps; (6) unverified "done" claims; (7) long-task state lost to compaction/handoff; (8) secrets in context and transcripts; (9) cross-repo change propagation; (10) audit logs cannot separate agent sessions; (11) leftover debug pods, port-forwards, scaled deployments; (12) huge plan/log outputs flood context; (13) stale CLAUDE.md/AGENTS.md assertions; (14) repeated user corrections never captured; (15) attention triage across sessions; (16) token cost per task; (17) prompt injection from logs/issues while holding prod credentials; (18) PRs lack agent reasoning provenance; (19) worktree bootstrap cost; (20) wasteful polling of slow operations; (21) no cheap sandbox for manifests; (22) hook/config drift across machines; (23) stale saved plans; (24) no cached cluster inventory; (25) no evaluation of context-file changes.

Converge: scored on blast radius in infra, amplification by parallel delegation, and gap left by existing tools. Dropped as largely solved: 19 (plugin caches), 22 (plugins, managed settings), 23 (saved plan files, folded into I2), 15 and 16 (session multiplexers, usage analysers exist), 20 and 21 (background tasks, kind/vcluster), 24 (Kubernetes MCP servers). Folded: 4 into I2, since fatigue comes from prompts that carry no effect information. Below the cut but real: 12, 13, 14, 18, 25 (partly covered by output truncation and auto memory, or lower consequence); 17 is serious, but taint tracking is hard to enforce reliably, and I1 plus I2 bound its damage.

Kept, ranked by consequence: 1, 3, 2, 5, 6, 7, 8, 9, 10, 11 become I1-I10. They cover preventing wrong or conflicting mutations (I1-I3), keeping Git, claims and task state truthful afterwards (I4-I6), and containing exposure, attribution and loose ends (I7-I10). They share one spine: a session ID from SessionStart pins targets, owns leases and ledger steps, names credentials and labels debris, stored in local files or SQLite. Where possible each is a CLI plus files referenced from AGENTS.md, so Codex and Cursor sessions take part, not only Claude hooks.
### Items
I1: Parallel sessions share global mutable target state: kubeconfig current-context, AWS_PROFILE, Terraform workspace, gcloud config. A context switch by one session or the human silently retargets another agent's next kubectl/terraform command to the wrong cluster or account. || target-pin: a SessionStart hook reads a per-worktree .target.yaml (cluster, namespace, cloud account, Terraform workspace) and exports a private KUBECONFIG copy, AWS_CONFIG_FILE/AWS_PROFILE and TF_WORKSPACE via CLAUDE_ENV_FILE (direnv for other agents), so context switches elsewhere cannot reach it. A PreToolUse hook rejects `config use-context` and `--kubeconfig`/`--context`/`--profile` flags naming other targets. The statusline shows the pinned target, coloured by environment.
I2: Permission rules match command strings, not effects. `terraform apply` or `helm upgrade` is equally allowed whether it changes one tag or replaces a database; humans approving dozens of prompts per hour rubber-stamp the dangerous one. || effect-gate: a PreToolUse hook intercepts mutating infra commands and first computes their effect: `terraform plan -out` + `show -json`, `helm diff upgrade`, `kubectl diff`. A Rego/YAML policy scores the diff (destroys/replaces, IAM, network, stateful kinds, prod target, object count). Low scores auto-allow; high scores ask with a ten-line effect summary instead of the raw command. The hook rewrites the apply to use the approved plan file, so exactly the reviewed diff executes.
I3: Worktrees isolate files, not live infrastructure. Two sessions can plan against the same Terraform state, Helm release or namespace; one applies, the other's plan or mental model is stale, and state locks only serialise the apply moment. || lease-broker: a local daemon (SQLite, Unix socket) keyed by canonical target IDs (state backend+key, cluster/namespace/release, host). A PreToolUse hook maps each infra command to target IDs; mutations need an exclusive lease (session ID, task, TTL renewed while active), reads register interest. Conflicts block with "held by session X for task Y". Each apply bumps the target's generation; a PostToolUse hook in interested sessions injects "target changed since your plan, re-read state".
I4: During debugging agents hotfix live clusters imperatively (kubectl edit/patch/scale, helm upgrade --set). The fix "works", the session ends, Git never learns; Argo/Flux reverts it later or drift silently persists. || drift-ledger: Pre/PostToolUse hooks snapshot the target object (`kubectl get -o yaml`) around every imperative mutation and append command, object and diff to .agent/drift.jsonl. A Stop hook runs `argocd app diff`/`flux diff` for each owning app; unresolved drift blocks stopping until the agent commits a backport to the matching GitOps values/manifests, reverts the live change, or the human marks it intentional. A daily sweep reports entries from sessions that died before resolving.
I5: Agents report "deployed and healthy" from exit codes or partial evidence while pods crash-loop, Argo is OutOfSync or terraform still shows changes; with many parallel sessions the human cannot re-check every claim. || claim-check: a Stop hook sends the final message (from transcript_path) to headless `claude -p` with a JSON schema that extracts typed claims (app X synced at rev R; dir D has no Terraform changes; host H runs version V). Each type maps to a deterministic probe: `kubectl rollout status` plus restart counts, `argocd app get -o json` sync/health, `terraform plan -detailed-exitcode`, an SSH version check. Failed probes block stopping with evidence; unprobeable claims are flagged unverified.
I6: Long multi-part tasks lose state through compaction, crashes, rate limits and handoffs between Claude, Codex and Cursor; the next session re-derives progress from chat, repeats completed steps or silently skips unfinished ones. || task-ledger: a tool-agnostic .agent/task.yaml of steps (id, acceptance-check command, status, evidence path, owning session), changed only through a small CLI (`ledger start|done|block`); a PreToolUse hook denies direct edits. `done` runs the check and refuses without passing evidence. A SessionStart hook, including the post-compaction "compact" source, injects open steps; a Stop hook blocks while unblocked steps remain. AGENTS.md tells Codex and Cursor to use the same CLI, so any agent resumes exactly where the last stopped.
I7: Infra commands put secrets into model context and local transcripts: `kubectl get secret -o yaml`, `terraform output`, `helm get values`, env dumps, logs. They persist in ~/.claude transcripts and leak into summaries, commits and PR descriptions. || secret-shim: a PreToolUse hook rewrites risky Bash commands (via updatedInput) to pipe output through a redactor that knows Secret `data`/`stringData`, sensitive Terraform outputs, Helm values keys matching password|token|key, plus gitleaks rules and entropy. Each value becomes a handle like `{{sec:7f3a}}` held in a keychain-backed local vault. A Read matcher denies raw tfstate and .env files. A `secret-run` wrapper substitutes handles back at execution, its own output redacted too, so agents use secrets without ever seeing them.
I8: Infra changes span repos: a Terraform module or Helm chart edit needs version bumps in live/env repos, GitOps values updates and app config changes. A session sees one repo, so it finishes "done" with consumers unpropagated or broken. || dep-graph MCP: a nightly indexer clones all infra repos and parses module `source`/version refs, Chart.yaml dependencies, Argo Application/Flux HelmRelease sources, image tags and remote_state references into an edge table (SQLite). The MCP exposes `consumers(path|module|chart)` and `impact(diff)`. A Stop hook in a producer repo calls `impact` on the session's diff and writes follow-up ledger entries or headless `claude -p` jobs, one per consumer repo, each in its own worktree.
I9: Cloud, Kubernetes and host audit logs attribute every agent action to the engineer's identity, so after an incident nobody can tell which session, prompt or transcript caused a change, or separate agent from human actions. || session-identity: a SessionStart hook mints short-lived credentials carrying the session ID: AWS `assume-role` with RoleSessionName=agent-<id> (visible in CloudTrail), a kubeconfig user with `as-user-extra: agent-session=<id>` impersonation (visible in Kubernetes audit logs), and SSH certificates whose key ID is the session ID (logged by sshd). An indexer joins audit events to transcript JSONL by session ID, so `whodid <resource>` returns the session, the prompt and the exact command.
I10: Agents leave debris: debug pods, port-forwards, `kubectl proxy`, scaled-down deployments, temp namespaces, cordoned nodes, test buckets. Across dozens of sessions nobody knows what belongs to which finished session, or how to undo it. || debris-tracker: a PreToolUse hook rewrites creating commands to add an `agent-session=<id>` label and expiry annotation (kubectl run/create, cloud CLI --tags), and logs reversible toggles (scale, cordon, suspend, rollout pause) with their inverse in .agent/undo.jsonl. Background processes start in a per-session process group. A SessionEnd hook kills that group and writes a debris report with one-command undo; a cron sweeper deletes labelled objects whose session ended and expiry passed.
