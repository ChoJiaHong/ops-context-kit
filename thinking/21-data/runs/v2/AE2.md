### Analysis
One fact drives most of this engineer's problems. What gets changed is shared live state (clusters, cloud accounts, Terraform state, hosts), not only files. Today's building blocks isolate files (worktrees) and check command strings (permission rules), but in infra the risk sits in targets and effects. Each parallel session gets its own worktree, yet every session still shares one kubeconfig, one Terraform working directory and one prod cluster. Permission rules match string prefixes. The issue list shows they break on compound commands (`cd && ...`, pipes), and they cannot tell whether `kubectl apply` hits staging or prod.

The second theme is trust in long delegated tasks. The most-reacted issue says complex engineering tasks fail. The issues about ignored instructions (verbose comments, word tics) show that rules written in CLAUDE.md are weak. In infra work this shows up as agents saying "applied and healthy" without evidence, or summarising a Terraform plan wrongly. The fix is to move checks out of prose and into deterministic hooks that read the transcript and the real systems.

The third theme is continuity. Compaction, rate-limit stops, stream errors and parallel windows each split up the record of what was done to which target. Transcripts exist on disk, but nothing collects mutations across sessions and hands them to the next session.

The fourth theme is cost. Usage-drain issues dominate the list. Infra CLIs print very large outputs (pod lists, plans, logs). Each one stays in context, is sent again on every later turn and makes cache writes bigger.

The fifth theme covers secrets and GitOps. Secret values fetched with kubectl or Terraform end up in transcripts. Imperative fixes to objects managed by Argo CD or Flux are silently reverted.

Ranking: likelihood × blast radius, weighted by how badly existing tools cover the problem. Wrong-target commands and auto-approved unsafe mutations come first, because they are catastrophic and parallel sessions make them common. Evidence-checked completion and plan binding come next, because they decide whether delegation can be trusted at all. Coordination (leases, journal) follows. Cost, secrets and fleet tooling come last: they are valuable, but partial workarounds exist (ccusage, Vault, Ansible). I left out account switching, desktop UI and Linux builds. Those pains are real, but they are vendor product work, not tools this engineer could build. Every item uses mechanisms that exist now: SessionStart env files, PreToolUse blocking and input rewriting, Stop hooks that can refuse to end, transcript JSONL, and PATH shims for agents without hooks.
### Items
I1: Sessions and the human's own terminals share ~/.kube/config's current-context and each checkout's .terraform/environment. One agent's `kubectl config use-context` or `terraform workspace select` silently retargets the others, so commands hit the wrong cluster or workspace. || Session target pinning. A SessionStart hook copies the kubeconfig to a per-session file with one fixed context. It writes KUBECONFIG, AWS_PROFILE, TF_WORKSPACE and HELM_KUBECONTEXT into the session environment (CLAUDE_ENV_FILE). A PreToolUse hook adds explicit --context/--namespace to kubectl and helm calls and denies context switches. Retargeting goes through a `pin <target>` script that always asks the human. The status line shows the pin. PATH shims give Codex and Cursor the same behaviour.
I2: Permission rules match command-string prefixes. Compound commands, pipes, `xargs`, `bash -c` and `ssh host '…'` either prompt too often or slip through, and the rules cannot tell a harmless read from a prod deletion. || Effect gate. A PreToolUse hook parses Bash input with tree-sitter-bash and recurses into subshells, `bash -c`, `xargs`, and `ssh`/`kubectl exec` remote strings. Per-CLI verb tables (kubectl, helm, terraform, aws, rm, systemctl) classify each simple command as read, mutate or destroy. Flags or the session pin give its target. A matrix of effect × environment decides: reads allow, staging mutations allow, prod mutations ask, destroys and unparseable input ask. The strictest part decides for the whole command.
I3: On long multi-part tasks, agents report "applied, rollout healthy, tests pass" for steps they skipped, ran against the wrong target or saw fail. The human must reread transcripts to find out, which defeats the point of delegating. || Evidence ledger. Before working, the agent writes `.task/checklist.yaml`: one item per requested part, each with an acceptance command (`kubectl rollout status … --context prod-eu`). The human approves it. A Stop hook parses the transcript JSONL and matches each item to a real tool call: same command and target, succeeded, after the last related edit. It blocks stopping and lists the items without evidence. The final report is generated from the ledger, marking each item verified, failed or unverified.
I4: Agents summarise Terraform plans and Helm diffs in prose and sometimes leave out replacements or destroys. The human approves that prose, not the exact change that then runs. || Plan binding. A PreToolUse hook allows `terraform apply` only with a saved planfile whose SHA-256 a human approved. It allows `helm upgrade` only when the chart version and values-file hashes match an approved `helm diff` run. A script builds each approval request from `terraform show -json`: counts, every replace/destroy, and highlighted IAM and network changes. All sessions share one approval queue, so the human reviews effects, not the agent's prose.
I5: Worktrees isolate files, not live systems. Two sessions can upgrade the same Helm release, edit the same host or apply conflicting changes to one cluster. Terraform's state lock covers only Terraform. || Target lease broker. A small local daemon (SQLite) holds leases keyed by target: context/namespace/release, Terraform state path or host. The effect gate's PreToolUse hook requests a lease before any mutation. If another session holds it, the call is denied with that session's id, task title and lease age, so the agent waits or works elsewhere. Leases renew on each tool call and expire after a TTL or at SessionEnd. A `leases` command lists the holders. A shared network backend extends this to teammates' agents.
I6: After compaction, a rate-limit stop or a stream error, and in parallel windows, a session cannot see what any session already changed on a target. Half-applied work gets rediscovered by guesswork or done twice. || Cross-session change journal. A PreToolUse hook saves each mutation target's prior state (`kubectl get -o yaml`, Helm revision, Terraform state serial). A PostToolUse hook appends an entry to an append-only JSONL journal: session, target, command, exit status and snapshot path. SessionStart hooks, including the one that runs after compaction, inject the latest entries for the session's pinned targets and flag mutations not yet verified. `journal undo <id>` reapplies the snapshot or rolls the Helm release back.
I7: Agents fix GitOps-managed objects with `kubectl edit/patch/scale`. Argo CD or Flux reverts the change minutes later, or drift builds up if self-heal is off, after the agent has already reported success. || Ownership guard. Before any kubectl mutation, a PreToolUse hook fetches the target object and reads its ownership markers: the Argo CD tracking annotation, Flux kustomize/helm-controller labels and Helm release annotations. If the object is owned, the hook denies the call. It returns the source location (repo URL, path and values file, read from the Argo Application or Flux Kustomization) so the agent edits Git instead. Break-glass needs a flag the human approves and is recorded in the journal.
I8: Infra CLIs print very large outputs (`kubectl get pods -A`, `-o yaml`, plans, logs). Each dump stays in context and is sent again on every later turn. This is a major hidden cause of fast quota drain. || Output shaper. A PreToolUse hook rewrites commands whose last pipeline stage is kubectl, helm, terraform, journalctl or aws. Output goes to `.agent-out/<id>.txt`. Above a size threshold, a digester prints only a summary: row counts, non-Ready or erroring items, error lines, plan resource counts and the file path for targeted grep. Earlier pipeline stages are left alone, and a `RAW=1` prefix bypasses the shaper. Per-command thresholds are tuned from the token counts in transcripts.
I9: To debug, agents run `kubectl get secret -o yaml`, `terraform output` or `env`. Credentials end up in model context, local transcript files and summaries, and agents have no safe way to use a secret without seeing it. || Secret handles. Agents refer to secrets as `{{secret:vault/prod/db#password}}`. A PreToolUse hook rewrites the command to run under `secret-exec`. It resolves handles from Vault, SOPS or a cloud secret manager into environment variables at run time. It scrubs those exact values, and their base64 forms, from stdout/stderr before the agent sees the output. The same hook rewrites secret reads (`get secret`, sensitive `terraform output`) to show only keys and value hashes.
I10: On many hosts, agents loop over `ssh` one host at a time, change every host at once without a canary, and paste N near-identical outputs into context. Partial failures get lost in the noise. || Fleet MCP server over the inventory (Ansible inventory or cloud tags). `fleet_run(group, command, mode)` runs read-only commands in parallel. In mutating mode it runs on one canary host first and waits for a health check. Then it proceeds in batches and stops when failures pass a threshold. Results come back grouped by identical normalised output ("41 hosts: active; 2 hosts: failed, see …"), with per-host files on disk. The effect gate denies raw multi-host ssh loops and points to this tool.
