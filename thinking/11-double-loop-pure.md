# 11 雙向迴圈

2026-11-07 與作者確認：這就是最終抽象模型。

> 之後的討論（[16](16-model-selection.md)）：要「找出問題、做出比現有更好的工具」時，單靠這個模型不夠（沒有判準），選用 06 的收斂骨架當內容，這個模型當動力。

## 定義

**雙向迴圈：在兩個相反的方向之間來回移動。**

- **只規定一件事**：方向一定是兩個，而且彼此相反。
- **為什麼是兩個**：只往一個方向走，終究會走到盡頭而停下。有兩個相反的方向，一個方向的終點就是另一個方向的起點，所以能持續移動。
- **其他一切由執行的 AI 決定**：兩個方向是什麼、什麼時候轉向、什麼時候停、什麼算進展、產出什麼、要不要問人。

這個模型是給大型語言模型（例如 Claude Code）跑的。條件是不確定的，所以模型不寫規則，只給一個能持續移動的結構。

## 方向的例子（不是規則）

AI 可能依情況選出這些方向，也可能選別的：

| 兩個方向 | 適合的情況 | 出處 |
|---|---|---|
| 抽象 ↔ 具體 | 整理概念，或把概念做成能用的東西 | 本研究自己的路徑（見下） |
| 問題 ↔ 解法 | 問題還沒界定清楚，要邊試解法邊重新理解問題 | 設計研究的問題與解法共同演化（Dorst 與 Cross，2001） |
| 加條件 ↔ 減條件 | 找出一個做法的適用範圍 | [09](09-double-loop.md)；機器學習的版本空間 |
| 找出失效 ↔ 造出新解 | 產生新工具：在現有工具失效的地方造出局部解，再泛化成工具 | guard 補不完 → 「隔離靠權限」（[10](10-claude-md.md)） |
| 發散 ↔ 收斂 | 找新點子，再挑出可行的 | 一般創意方法 |

## 評估（作者確認為最終抽象模型後）

**它是什麼**：不是一套方法，而是讓 AI 持續前進的最小結構。只保證永遠有一個相反的方向可以轉，其他全部交給 AI 判斷。

**不矛盾**：
- 「全部交給 AI」和「一定要兩個方向」不衝突：這是唯一固定的限制，其他都自由。
- 「持續移動」和「AI 決定何時停」不衝突：兩個方向讓它能夠一直走下去，停不停是它的選擇。

**意義要分兩個角度看**：
- **當成理論**：很弱。方向可以任意選，幾乎任何過程事後都能說成雙向迴圈，無法用來預測或檢驗。
- **當成給 AI 的指令**：有意義。它針對 LLM agent 兩個常見的毛病：太早停（做完一輪就宣布完成）、卡在單一方向（一直分析不動手，或一直產生方案不回頭檢查）。

**注意**：規定的內容非常少，AI 可能照原本的方式做事，只是事後說自己在跑雙向迴圈。所以有沒有用只能看行為，不能靠討論判斷。08 號實驗裡，結構化的思考提示在一般題目上沒有帶來差別；這個版本更簡單，效果可能更小，也可能因為不綁手綁腳而更好。

## 尚未驗證

這個形式來自討論，還沒被實際跑過。最直接的檢驗：同一批任務，讓 Claude Code 帶著和不帶著這個 skill 各跑一次，看產出的問題界定和解法有沒有差別。
