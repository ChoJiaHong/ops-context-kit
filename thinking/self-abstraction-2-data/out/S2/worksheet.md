# 工作底稿：目標方法的核心骨架與適用問題

目標方法＝三份筆記描述的同一方法的三個版本：
- 筆記一「創新縮窄法」：大問題 → 現有解 → 限制 → 縮窄 → 差異 → 用差異突破限制（以創新為目標）。
- 筆記二「縮窄法」：向下縮窄找新優勢出現處 → 瓶頸與情境差異匹配 → 向上泛化找最大優勢範圍 P*。
- 筆記三「情境對比驅動的問題界定」：固定具體問題，往上抽象成一般類別 → 一般解 → 比較差異 → 映射成限制／資源／假設 → 重新表徵 → 解題 → 對原目標驗證（以解題有效性為目標）。

## 0. 前置：目標方法的元素清單（三版合併）

| 編號 | 元素 | 出處 |
|---|---|---|
| E1 | 一般問題類別與其既有解（基準解） | 一、二、三 |
| E2 | 既有解的限制／瓶頸；筆記二改為「可用但次優」而非失效 | 一、二（三以「改變的假設」隱含） |
| E3 | 縮窄：沿人、地點、時間、行為、限制、在地資源加入情境條件（向下迴圈） | 一、二（三已取消） |
| E4 | 情境差異萃取 D(Ps, Pg)／ΔContext | 一、二、三 |
| E5 | 差異的重新詮釋：映射成新限制、缺漏限制、可用資源、改變的假設；資源重新詮釋（交通工具 → 移動基礎設施） | 二、三（一的例子隱含） |
| E6 | 匹配 Match(L, D)：差異能否改變瓶頸 | 一、二 |
| E7 | 在既有解上調整 Adapt(Se, L, D)；「創新＝現有解法＋在地差異」 | 一、二、三 |
| E8 | 硬湊檢驗：拿掉在地特色，方案是否仍成立 | 一 |
| E9 | 向上泛化：逐步移除情境，Advantage > 0 才繼續，得 P* | 二 |
| E10 | 目標鎖定 Goal(P_final) = Goal(P0)；使用者原始表述視為假設；對原目標驗證 | 三 |
| E11 | 形式化：U(P, S)、Advantage、偏序 ⪯ | 二 |
| E12 | 失敗就再縮窄／換角度的循環 | 一 |
| E13 | 高中生六問、口訣 | 一 |
| E14 | 下游解題／執行 | 三 |

三版的共同點：把「同一問題的一般層」和「具體層」並列比較，並從兩者的差異取得解法材料。三版的差別主要在方向（一、二由一般往具體縮窄；三由具體往一般抽象）與目的（一求創新；三求解題有效）。

方法論提醒：所用分析工具的結構（參照、差異、作用、範圍、必要）與筆記二幾乎同構，有「工具在目標方法裡找到自己」的循環風險。因此第 5、6 步一律以具體測試問題逐一判斷，不直接以工具結構認定核心。

## 1. 參照

| 代號 | 參照方法 | 核心 | 最擅長的問題 |
|---|---|---|---|
| R1 | 直接請 LLM 解題 | 把問題描述直接對應到最可能的答案（訓練分布中的典型解） | 描述完整、屬常見類型、典型解即正確解的問題 |
| R2 | 思維鏈／規劃分解 | 在給定表徵內拆成子步驟逐步推導 | 前提完整、需要多步推理或計算的問題 |
| R3 | TRIZ | 把問題抽象成通用工程參數間的矛盾，查發明原則／矛盾矩陣再具體化；輔以資源分析、理想最終結果 | 系統內部有明確技術矛盾的工程問題 |
| R4 | 案例推理／類比推理 | 檢索最相似的舊案，重用其解，再小幅修補 | 有大量案例、新問題與舊案相近的問題 |
| R5 | 設計思考 | 同理 → 定義 → 發想 → 原型 → 測試，靠真實使用者回饋迭代 | 需求不明、以人為中心、可快速做原型的問題 |
| R6 | 根因分析（5 Whys、故障診斷） | 從症狀沿因果鏈追問到根本原因 | 已發生明確故障、因果鏈可追的問題 |
| R7 | 第一原理 | 拋開既有做法，從基本事實重建解法 | 既有解被慣例綁住、值得從頭重算的問題 |

## 2. 綁定假設

| 參照 | 為了通用而預設 | 造成的瓶頸 |
|---|---|---|
| R1 | 問題描述完整且正確；本例屬於典型情況 | 輸出一般類別的預設解；描述中的情境事實被當背景，沒變成解題材料；使用者自帶的框架（「幫我加機器」）被直接執行 |
| R2 | 表徵已正確，只需在其中推理 | 推理更嚴謹，但可能朝錯的目標更嚴謹；不會主動換表徵 |
| R3 | 問題可化為通用參數的矛盾；解來自跨領域原則目錄 | 抽象時丟掉情境細節；原則籠統需大量轉譯；不處理「既有解可用但次優」 |
| R4 | 相似問題有相似解；新舊差異是要修補的雜訊 | 差異只被修掉、不被利用；偏向重用而非突破 |
| R5 | 主要未知在使用者需求；能接觸使用者、能做原型 | 成本高；構想和既有解瓶頸之間缺少系統性連結，難判斷是否勝過既有解 |
| R6 | 存在一個「壞掉」的症狀 | 既有解還能運作但不夠好時無從啟動；只找原因，不產生新資源 |
| R7 | 既有解不可信、值得從零重建；分析者有深厚領域知識 | 丟掉累積知識，代價高；由 LLM 執行時常淪為空泛口號 |

共同綁定假設：「情境＝一般情況」、「情境細節是雜訊或應被抽象掉」、「問題表述是給定的」三者至少其一。
共同瓶頸：具體情境中那些與一般情況不同、而且能改變既有解瓶頸的事實，沒有被系統性地找出來並拿來用。

## 3. 差異

| 代號 | 差異 | 目標方法的做法 | 參照方法的做法 | 對應元素 |
|---|---|---|---|---|
| D1 | 顯式基準 | 先寫出一般類別的既有解，當成要贏過的對手 | R1 隱含使用、不外顯；R7 丟棄；R3 改用原則目錄 | E1 |
| D2 | 觸發條件 | 既有解「可用但次優」就啟動 | R6 需要故障 | E2 |
| D3 | 差異的地位 | 具體與一般的差異是解的來源 | R4 當雜訊修補；R3 抽象掉；R1 忽略 | E4 |
| D4 | 差異的改寫 | 把差異重新詮釋成資源、限制、假設變化（交通工具 → 移動基礎設施） | 參照多停在描述層 | E5 |
| D5 | 篩選規則 | 只留能改變瓶頸的差異 | R5 發散後收斂，但收斂標準不是既有解瓶頸 | E6 |
| D6 | 修改幅度 | 在既有解上局部調整 | R7 從零重建；R3 套外部原則 | E7 |
| D7 | 反事實檢驗 | 拿掉在地特色仍成立就判為硬湊 | 參照皆無 | E8 |
| D8 | 範圍輸出 | 向上泛化到優勢消失，輸出 (P*, Sn) | 參照只輸出單一問題的解 | E9 |
| D9 | 目標鎖定 | 可換表徵，不可換目標；使用者表述是假設 | R1、R2 照單全收；R5 可能改目標 | E10 |
| D10 | 用縮窄製造情境 | 從大問題沿六維度往下加條件 | 參照多從給定問題出發 | E3、E12 |
| D11 | 相對效用標準 | 以「高於既有解最大效用」為成立條件，新穎性次要 | 創新方法常以新穎為目標 | E11 |
| D12 | 呈現方式 | 六問、口訣、公式 | — | E13 |

## 4. 作用與功能重述

| 參照的瓶頸 | 解掉它的差異 | 功能重述：它對瓶頸做了什麼 |
|---|---|---|
| 預設解被直接輸出（R1） | D1＋D3 | 把預設答案擺上桌當對照組，迫使注意力轉向「這裡和一般哪裡不同」 |
| 情境事實被當背景或被抽象掉（R1、R3、R4） | D3＋D4 | 把背景事實改寫成「它能對瓶頸做什麼」，讓事實能接上瓶頸 |
| 表徵固定（R2）；使用者框架照單全收（R1） | D9＋D4 | 把原始表述降為待驗假設，允許換表徵 |
| 需要故障才能啟動（R6） | D2 | 把觸發條件從「失效」放寬到「次優」，可用但不夠好的既有解也能被挑戰 |
| 差異太多、湊不上（R5 發散） | D5 | 以既有解的瓶頸當濾網，只放行能動到瓶頸的差異 |
| 丟掉累積知識（R7）；原則需轉譯（R3） | D6 | 只改既有解被瓶頸卡住的那一處，其餘照用 |
| 換名不換解（創新包裝、LLM 貼標籤） | D7 | 用反事實刪除測試，淘汰差異只是裝飾的方案 |
| 改寫後問題漂移（R5；也是目標方法早期向上迴圈的問題） | D9 | 鎖住目標，讓「更好」始終用同一把尺 |
| 解法只對單一情境有效、無法移植 | D8 | 把一次性的在地解升級成可移植的問題類別並標出邊界（不解參照瓶頸，屬附加產出） |

未解掉任何參照瓶頸的差異：
- D10 縮窄與六維度：是「製造情境」的搜尋啟發；問題本身已具體時用不到（筆記三已取消）。
- D11 形式化：筆記二自承 U 與 Advantage 尚無法定義，但例子照樣成立；它是表達，不是機制。
- D12 六問、口訣：教學呈現。

目標方法自身帶來的新瓶頸（供第 5 步用）：必須知道既有解（領域知識門檻）；LLM 可能捏造情境差異；效用多半只能粗估。

與「只是既有方法重組」的疑慮（筆記三自列）對照：若只保留 D1＋D3＋D6，方法等同案例推理（檢索、重用、修補）。不屬於任何參照的部分是 D2＋D4＋D5＋D7 的組合：以既有解的瓶頸當濾網、把差異功能化後對接、再以反事實驗收。

## 5. 範圍

以阿里山 UAV 搜尋為種子，讓問題往各參照擅長的領域靠近或遠離，逐一判斷目標方法相對「最強參照」是否仍有優勢。

| # | 測試問題 | 移動方向 | 仍有優勢？ | 理由 |
|---|---|---|---|---|
| T0 | 阿里山 UAV 搜尋（基準：固定基地起降） | 種子 | 有 | 林業鐵路 → 移動補給節點，直接縮短往返瓶頸 |
| T1 | 有固定運輸路線深入作業區的 UAV 任務（鐵路、輸電線、林道巡檢） | 去掉地點標籤，向上 | 有 | 差異的功能（可深入的移動補給平台）仍在 |
| T2 | 通用解受距離／續航限制、情境中有可移動載具的任何作業 | 再向上 | 有 | 同上；但必須有具體可用的載具 |
| T3 | 「CPU 太高，幫我加機器」 | 靠近 R6 | 有（對 R1 大、對 R6 小） | 基準解由使用者自帶；「部署後 retry 暴增」違反「負載來自真實流量」的預設；可從加機器的預設反推要查什麼，且不必先認定是故障 |
| T4 | 「優化這個 function」，內含逐筆 ORM 查詢 | 靠近 R1 | 有（小） | 一般解（演算法、快取）預設瓶頸在運算；迴圈內查詢違反此預設 → N+1。程式碼可見時強模型常能直接看出，優勢縮小 |
| T5 | 「用 Python 排序一個 list」 | 完全靠近 R1 | 無 | 情境＝一般情況，差異為空 |
| T6 | 前提完整的數學證明 | 靠近 R2 | 無 | 沒有情境差異，表徵已正確 |
| T7 | 「機翼要更強又更輕」，無特殊情境 | 靠近 R3 | 無 | 矛盾在系統內部，答案來自通用原則而非情境；加上可用的特殊情境資源才回到範圍內 |
| T8 | 和歷史工單幾乎相同的退款問題 | 靠近 R4 | 無 | 差異趨近零，重用舊解最便宜；出現新差異（金流商逾時）才回到範圍內 |
| T9 | 「讓偏鄉長者更願意使用數位服務」 | 靠近 R5 | 弱 | 目標與需求未定，無法判斷誰比較好；需求釐清後才可用 |
| T10 | 從未有人做過的裝置、全新領域 | 靠近 R7 | 無 | 沒有基準解可比 |
| T11 | 磁碟已滿導致服務中斷 | 靠近 R6 | 無 | 明確故障、因果短，根因分析更直接 |
| T12 | 阿里山 UAV 搜尋，但只拿「遊客多、名氣大」當差異 | 差異不碰瓶頸 | 無 | 差異不改變續航瓶頸，屬硬湊 |
| T13 | 只給「山區搜救」，由 LLM 自行補情境 | 情境不可查證 | 無（甚至有害） | 差異可能被捏造 |

優勢消失的邊界（由 T5–T13 歸納）：
1. 沒有成熟基準解（T10）。
2. 情境＝一般情況，差異為空（T5、T6、T8）。
3. 有差異，但都碰不到基準解的瓶頸（T7、T12）。
4. 目標或需求未定，無法比較優劣（T9）。
5. 情境事實取不到或無法查證（T13）。
6. 問題是明確故障且因果短（T11）——此時根因分析成本更低。

優勢最大處（由 T0–T4 歸納）：基準解越成熟（人人先想到它）、情境越偏離其預設、偏離越被當成背景而不顯眼時，直接解題最容易漏掉，目標方法的優勢最大。範圍不限於「在地創新」：筆記三的程式、維運、客服例子同樣成立，「在地」只是情境差異的一種。

**P\***：目標明確、已有成熟通用解的具體問題，其情境中存在通用解設計時沒有計入、而且能改變其瓶頸的資源、限制或假設變化。

進入條件：
- 說得出「一般會怎麼解」，而且這個解在此情境可用但有可指認的瓶頸（不必失效）。
- 情境中有具體、可查證的特殊事實。
- 至少一項事實經功能重述後能動到瓶頸。
- 目標固定，能粗略比較兩個解在同一目標下的優劣。

## 6. 必要

逐一拿掉元素，問：拿掉後在 P* 上還有優勢嗎？

| 元素 | 拿掉後在 P* 上的結果 | 判定 |
|---|---|---|
| E1 基準解 | 沒有「一般」就沒有「差異」，也沒有瓶頸可指；退化成直接解題或自由發想 | 核心 |
| E2 預設與瓶頸 | 差異沒有篩選對象，只剩一串在地特色；匹配無從做起，容易硬湊 | 核心 |
| E3 縮窄迴圈、六維度 | P* 的問題已具體，差異可直接比對取得；筆記三取消後仍成立 | 非核心（進入 P* 的手段） |
| E4 情境差異 | 修改沒有輸入，輸出等於基準解 | 核心 |
| E5 功能重述 | 差異停在名詞層（「有林業鐵路」），接不上瓶頸（「往返距離」）；阿里山例子的關鍵一步正是這個改寫 | 核心 |
| E6 匹配 | 所有差異都被採用，方案堆砌、偏離瓶頸 | 核心（與 E7 合併） |
| E7 局部修改既有解 | 改成從零設計，失去既有解的成熟度，代價回到第一原理的瓶頸；多數情況優勢消失 | 核心（與 E6 合併） |
| E8 反事實檢驗 | 分不出「真的用到差異」和「通用解貼標籤」；後者正是直接解題的輸出，優勢在期望上被抵銷 | 核心 |
| E9 向上泛化 | P* 中單一問題的解照樣得出；只失去可移植的問題類別 | 非核心（附加產出） |
| E10 目標鎖定 | 換表徵後可能解成另一個問題；比較的尺跟著變，優勢無法判定。「表述即假設」併入 E1（使用者自帶的解法就是基準） | 核心 |
| E11 形式化 | 筆記二自承 U 未定義，例子仍成立 | 非核心 |
| E12 失敗再縮窄的循環 | 一般性反覆，非本法特有 | 非核心 |
| E13 六問、口訣 | 教學呈現 | 非核心 |
| E14 下游執行 | 任何方法都有 | 非核心 |

核心骨架（7 個）：
1. 基準解（E1，含使用者自帶的解法）
2. 預設與瓶頸（E2）
3. 情境差異（E4）
4. 功能重述（E5）
5. 匹配修改（E6＋E7）
6. 反事實檢驗（E8）
7. 目標鎖定（E10）

非核心：縮窄（E3／E12，是進入 P* 的手段）、向上泛化（E9，附加產出）、形式化（E11）、六問與口訣（E13）、下游執行（E14）。
