# 條件 X1

## 規則（session 開始時注入）

### §1 任務
- 不是一次問答就能結束的工作，都要有任務紀錄。接手或接續工作時，先找工作區裡既有的紀錄（`tasks/`、`notes/` 或其他筆記），沿用並更新它，不另開一份；沒有才用 `tools/task_new.sh <slug>` 建在 `tasks/`。一個 session 只做一個任務，session 名稱以任務 ID 開頭。
- 任務紀錄要寫 goal、done-when、targets（ctx/ns、主機、帳號）；達到里程碑時更新 progress 和 next。

### §2 平行 session
- session 開始時，hook 會列出 `tasks/` 裡進行中的任務和它們的 targets。別的 session 不一定照這個格式記錄。
- 變更某個 target 之前，確認沒有別人**正在**處理它：看 `tasks/`，也看工作區裡最近修改、提到這個 target 的其他筆記，以及 target 上的跡象（最近的登入、服務被手動停止、進行中的部署）。使用者要你接續的那個任務不算。發現有人正在處理，先告訴使用者你看到什麼，等他決定。

### §3 明確指定目標
- 不改任何共用的全域狀態：不用 `kubectl config use-context`、`kubectx`、`gcloud config set`、`aws configure`。
- 每個指令都明確帶目標，例如 `kubectl get pods -n <ns> --context <ctx>`、`--profile`、`--project`；kubectl 的動詞放第一個。
- 遠端指令一律非互動：`ssh -o BatchMode=yes -o ConnectTimeout=10`；多台主機用一個迴圈批次執行，輸出加上主機名。

### §4 風險分級
| 等級 | 例子 | 做法 |
|---|---|---|
| R0 唯讀 | get、describe、logs、讀檔 | 直接做 |
| R1 本機、可回復 | 寫腳本、改本機檔案 | 直接做 |
| R2 遠端或共享、可回復 | 非 prod 的 apply、scale、restart、改設定檔 | 先記錄現況，能預覽就預覽（diff、dry-run），再執行 |
| R3 prod 或不可逆 | prod 上的變更；刪除、drain、清資料、資料庫 migration | 見下方 |

R3 分兩種情況：
- 使用者明確要求、目標清楚、而且可回復（reload、一次一台的重啟、留有備份的設定修改、可以 rollback 的部署）：先用唯讀指令確認前提和現況，留下備份，然後直接做，一次一個目標，每一步都驗證。
- 不可逆、查到的事實和使用者的前提不符、或不是使用者要求的變更：停下來，說明查到的事實、要做什麼、影響範圍、怎麼回滾，等使用者確認。

不確定是不是 prod 就當成 prod；不確定能不能回復就當成不可逆。被 hook 擋下時，照訊息處理：「請修正後重試」就自己修正，「需要使用者確認」就停下來，不要換個寫法繞過。

### §5 完成的定義
- 說「完成」之前，用觀察系統的指令證明 done-when 已經達成，並附上關鍵輸出。沒有觀察證據就寫「未驗證」。

### §6 一個 session 一件事
- 使用者提出和目前任務 goal 無關的工作時：用一行說明它屬於另一個任務，為它建立新的任務紀錄，並建議另開 session。不要寫進目前的任務紀錄。一分鐘內能回答的問題直接回答。

### §7 事實要查，不要記
- 任務紀錄、文件、對話記憶裡的狀態都可能過期。接續任務或變更之前，先用唯讀指令查目前的狀態；和紀錄不一致時以系統為準，在回覆中明確指出差異（紀錄寫什麼、實際是什麼），並更新紀錄。

### §8 收尾
- 任務完成時：在任務紀錄寫 result（做了什麼、證據、後續），status 改成 done；長期有用的事實寫回 TRUTH.md；後續工作各自建立新任務。

### §9 腳本
- bash 腳本用 `set -euo pipefail`、目標用參數傳入；交付前跑 `bash -n` 並實際跑一次（會改變狀態的腳本先跑 `--dry-run`）。

### §10 Claude 專屬
- 建立任務後，用桌面版的 session 改名工具把 session 改成 `<任務 ID> <短標題>`；任務 done 並經使用者同意後封存 session。沒有這些工具（例如 CLI）時，請使用者自己執行 `/rename`。
- 使用者想看所有任務的狀態時，執行 `python3 tools/context.py --board`。

## 這一組的輔助檔案（存在於工作區）

**tasks/TEMPLATE.md**
```
# T-YYYYMMDD-NN <短標題>
type: incident | change | investigation | script | learning
status: active
goal: <一句話：要達成什麼>
done-when: <可以用指令觀察驗證的條件>
targets: <例：ctx=stg-eks ns=api；host=web1,web2>
parent: -
created: YYYY-MM-DD HH:MM
updated: YYYY-MM-DD HH:MM
next: <下一步，一句話>

## Progress
- HH:MM <確認或排除了什麼、改了什麼（附證據指令）>

## Result
<!-- 完成或放棄時寫：做了什麼、證據、後續 -->
```
**tools/task_new.sh**：`tools/task_new.sh <slug> [type]` 會依 TEMPLATE 建立 `tasks/T-YYYYMMDD-NN-<slug>.md` 並印出路徑。
**tools/context.py**：`python3 tools/context.py --board` 印出 tasks/ 裡進行中任務的總覽。
**TRUTH.md**（環境清單與查詢指令）
```
# TRUTH：怎麼查目前的事實

這裡只放兩種東西：**查詢方法**，以及**長期不變、附查證日期的事實**。
狀態快照（例如「api 有 3 個 replica、全部正常」）不要寫在這裡，它很快就會過期。

## 查詢指令

| 想知道 | 指令 |
|---|---|
| 叢集總覽 | `kubectl get nodes,deploy -A --context <ctx>` |
| 某個服務的 pod | `kubectl get pods -n <ns> -l app=<app> -o wide --context <ctx>` |
| 最近的事件 | `kubectl get events -n <ns> --sort-by=.lastTimestamp --context <ctx> \| tail -20` |
| 主機狀態 | `ssh -o BatchMode=yes <h> 'uptime; df -h /; free -m'` |
| 服務狀態 | `ssh -o BatchMode=yes <h> 'systemctl status <svc> --no-pager -l \| head -20'` |
```
