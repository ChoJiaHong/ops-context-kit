# 第二次自我抽象：預先登記（方案產生前寫好）

問題：用「抽象後的骨架」（tool/skeleton.md）分析原模型，會不會比 Claude 自己的方式更好？

組別：
- S 組（新）：用抽象後的骨架當分析工具。Sonnet ×2、Opus ×2。
- C 組（沿用第一次實驗）：Claude 自己的方式，不准用原模型流程。Sonnet ×2、Opus ×2。輸入與指示和第一次相同。
- M 組（沿用第一次實驗）：用原模型的流程。Sonnet ×2（Opus 兩次被安全機制擋下，沒有結果）。

評分：與第一次相同的七面向（A–G，滿分 35）與六道遷移題，Sonnet 與 Opus 各一位評審盲評十份方案。
另由一位評審，對照第一次實驗得到的骨架，只評「新增內容」H（1–5）：方案有沒有超出已知骨架的新東西。

判定（同一模型內比較，兩位評審的平均）：
- S − C ≥ +2 分，且兩位評審同號 → 抽象後的骨架比較好
- S − C ≤ −2 分，且兩位評審同號 → Claude 自己的方式比較好
- 其他 → 看不出差別
同樣的規則也用在 S 與 M（原模型）之間。

已知混淆：抽象後的骨架本身含有第一次實驗最好方案的洞見（綁定假設、功能重述），所以 S 組的洞見分數可能來自工具帶進來的知識。H 用來檢查 S 組有沒有超出這些已知內容。
