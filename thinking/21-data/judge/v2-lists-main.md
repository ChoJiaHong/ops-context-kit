# Answer lists (main)

## L1

I1: Parallel sessions share mutable global CLI context (kubeconfig current-context, gcloud active config, AWS_PROFILE, terraform workspace). One agent's `use-context prod` silently retargets every other session's next command; kubie/direnv isolate interactive shells, not per-command agent shells. || Session context pinner. A SessionStart hook copies kubeconfig, gcloud config dir and AWS config into ~/.agentctx/<session>/ and exports KUBECONFIG, CLOUDSDK_CONFIG, AWS_CONFIG_FILE, TF_WORKSPACE, HELM_KUBECONTEXT via CLAUDE_ENV_FILE, pinned to targets declared in the worktree's .agent-target. PreToolUse denies switching to, or --context flags naming, undeclared targets until the human re-pins. Metric: commands whose resolved context differs from the declared target (goal 0). P*: agents sharing one workstation's CLI credentials; humans keep kubie.
I2: Agent-written Terraform/Helm changes produce plans containing changes the task never asked for (provider drift, forced replacements). Reviewers skim large plans; OPA/conftest policies check global rules, not whether this plan matches this task's intent. || Intent-plan gate. Before planning, the agent writes change-intent.yaml: expected resource addresses (globs) and actions. PreToolUse on terraform apply / helm upgrade / kubectl apply first converts terraform show -json, helm diff or kubectl diff into (address, action) pairs and denies on undeclared addresses or escalations (update→replace/delete); amending intent requires a reason that lands in the PR. Metric: undeclared changes reaching apply; review minutes per PR. P*: agent-authored changes with machine-readable plans; humans rarely write intents.
I3: Two sessions mutate the same live object (Helm release, namespace, Terraform root, host), or one applies between another's plan and apply. State locks last one command, Atlantis locks only PR runs; kubectl, helm, ssh have none. || Lease broker. PreToolUse parses each Bash command into resource keys (context/namespace/kind/name, helm release, terraform backend key+workspace, ssh host) and verb class. Reads take shared leases; mutations, including terraform plan -out held until apply, take exclusive ones in local SQLite with TTL renewed per call, released at SessionEnd. Conflicts are denied naming the holder session and task. Metric: overlapping mutations per key in transcripts (goal 0) vs false-block rate. P*: agent sessions sharing live systems; team-wide via Redis.
I4: With many parallel sessions, the engineer becomes the bottleneck answering near-identical permission prompts one window at a time; static allowlists are either too broad for prod or too narrow, and session managers only show who is waiting. || Approval inbox. A PermissionRequest hook posts each pending request (session, normalized command with pod hashes/timestamps stripped, read/mutate class, context) to a local daemon and long-polls for the answer. The inbox groups identical normalized requests across sessions, shows plan/diff for mutations, and one decision answers the group and can issue a scoped grant (pattern + context + TTL) that the hook honors until expiry. Metric: prompts resolved per human decision; median session wait time. P*: three or more concurrent sessions.
I5: Agents declare 'done' when the PR is open; in GitOps the real effect (Argo sync, rollout health, Atlantis apply) appears after human merge, when the session has ended. Argo notifications reach the human without task context. || Deferred acceptance. At task start the agent writes accept.yaml: read-only probes with predicate, timeout, trigger (now, after-merge, after-sync). A Stop hook blocks completion until 'now' probes pass; later ones go to a local queue. A daemon polls gh pr view and argocd app get until the synced revision includes the merge commit, runs the probes, and on failure calls `claude --resume <session> -p <failure>` in its worktree. Metric: merge-to-detection time for broken agent changes. P*: asynchronously-applied changes.
I6: Agents need secrets to work but read them in clear (kubectl get secret, terraform output, vault read), so values land in context and local transcripts. `op run` masks only pre-registered references; deny rules match paths, not command output. || Secret placeholders. PreToolUse rewrites known secret-emitting commands to pipe through a redactor that decodes base64 data and replaces values (plus high-entropy/known-format strings) with @@sec:hash8@@, storing them in a per-session 0600 tmpfs keyring. Commands containing placeholders are rewritten to `secsub -- cmd`, which substitutes values inside the subprocess and redacts its output again. Metric: gitleaks hits per week in ~/.claude transcripts, with secret-using task success unchanged. P*: any shell-capable agent touching credentialed systems.
I7: All sessions act under the engineer's single identity, so Kubernetes audit, CloudTrail, Teleport and auditd cannot tell which of eight sessions changed an object or host; finding the responsible transcript after an incident is manual. || Session stamping. PreToolUse fills native attribution fields with the session ID: kubectl mutations get --field-manager=agent-<sid8> (stored in managedFields), the per-session AWS config sets role_session_name=agent-<sid8> (shown in CloudTrail), ssh mutations are prefixed with `logger -t agent-<sid8>`, commits get an Agent-Session trailer. A `whodid` CLI maps an object, event or host log line back to the transcript excerpt. Metric: share of audited mutations traceable to a transcript. P*: multiple automated actors sharing one human credential.
I8: Several agents edit one infra repo in separate worktrees; edits to different files (base values vs overlay) change the same rendered Kubernetes field. Git merges cleanly; GitLive warns on text overlap in IDEs only; conflicts surface after deploy. || Rendered-overlap detector. PostToolUse on edits under infra paths re-renders affected environments (helm template, kustomize build) in that worktree, diffs against the merge-base render, and records changed (kind/ns/name, JSON pointer) keys per worktree in a local SQLite registry. Each session's next PostToolUse checks for keys also changed by another live worktree and injects a warning naming the other session's task. Metric: semantic conflicts caught at edit time vs after merge. P*: parallel edits to layered, rendered config on one machine.
I9: CLAUDE.md/AGENTS.md rules ('never apply without plan review', 'use --context explicitly') are silently ignored in long sessions; nobody knows which rules are violated or obsolete, so files grow and rules that matter stay unenforced. || Rule auditor. One-time, human-reviewed compilation of each imperative rule into a predicate over tool calls (regex/shell-AST on Bash, path globs on edits, ordering such as 'plan before apply'). A nightly job replays local transcripts (Claude Code JSONL, Codex sessions) against the predicates, reports per-rule violation and trigger rates, auto-drafts PreToolUse deny hooks for rules violated ≥N times, and proposes deleting rules never triggered. Metric: violations per 100 sessions per rule; instruction-file tokens. P*: any agent with local transcripts.
I10: Facts agents learn about environments (which ingress controller cluster X runs, which module needs -target) go into MEMORY.md, go stale as infra changes, are clobbered by parallel sessions, and are served without any freshness check. || Probe-backed fact store (MCP). Each fact = entity (cluster/namespace/host/module), claim, read-only probe command, expected predicate, verified_at. remember() merges transactionally in SQLite; recall(entities) re-runs probes older than a TTL and returns failures marked STALE with current output. A UserPromptSubmit hook matches entity names from the inventory in the prompt and injects their verified facts. Metric: share of served facts whose probe fails (unmeasurable with MEMORY.md). P*: facts about queryable live systems; code facts stay in code.

## L2

I1: Parallel sessions share ambient target state: kubectl current-context, AWS_PROFILE, gcloud config, terraform workspace. Worktrees isolate files, not these; one agent's `kubectl config use-context prod` silently retargets every other session's next command. || Session target pinner. SessionStart hook creates ~/.agent-sessions/<id>/, copies a kubeconfig containing only the declared cluster/context, and writes KUBECONFIG, AWS_PROFILE, CLOUDSDK_CONFIG, TF_WORKSPACE to CLAUDE_ENV_FILE (shell wrapper for Codex/Cursor). Target is chosen from the worktree's .agent-target file or asked once. A PreToolUse hook rejects `use-context`, `--context`, `--kubeconfig`, `workspace select` and profile overrides that differ from the pin; switching targets requires an explicit `pin set` command the human approves. Statusline shows the pinned target.
I2: Permission rules match command prefixes, so `kubectl` allows `kubectl delete`, and `ssh host '…'`, `kubectl exec`, `bash -c`, `make deploy` or generated scripts hide the real verb and target from both rules and hooks. || Semantic infra gate (PreToolUse). Parses the command into a shell AST, recursively unwraps ssh, bash -c, kubectl exec, xargs, env; expands make targets via `make -n` and inlines called scripts. Each leaf is classified by per-CLI verb tables into read/mutate/destroy, and its environment from the pin, host inventory tags or tfvars path. A policy matrix (verb class × env) returns allow, ask with a one-line risk summary, or deny. Unparseable commands that could mutate default to ask.
I3: Humans approve a `terraform plan` or `helm diff` shown in chat, but the agent then runs `apply`/`upgrade` which re-plans; edits, state drift or a different var file mean what executes differs from what was approved. || Plan-bound approval. The gate rewrites `terraform plan` to `-out=<session>/p.tfplan`, renders `terraform show -json` into a summary (counts, every delete/replace address) and asks the human; approval stores the planfile's sha256. `terraform apply` is then allowed only as `apply <that planfile>` with matching hash; Terraform itself rejects it if state moved. For Helm, approval hashes `helm diff upgrade` output; the upgrade runs only if a fresh diff hashes identically.
I4: Agents report 'deployed and healthy' from a successful command or merged PR. In GitOps the merge is not the deploy: Argo/Flux reconciles minutes later, after the session ended, so failures surface to nobody. || Evidence-checked completion. Stop hook requires .agent/claims.yaml with one claim per ledger subtask: a read-only check command and expected result (`argocd app get x -o json | jq .status.health.status` == Healthy). The hook re-runs checks through the gate in read-only mode and blocks Stop listing failures. Checks needing future reconciliation are queued with the commit SHA to a poller that waits until Argo reports that revision synced, then runs them and resumes the session headlessly (`claude -p --resume`) on failure.
I5: With 5–10 parallel windows, the human polls terminals to find which session waits on approval, asked a question, loops on the same error, or finished; approvals get granted without context, and blocked sessions idle for hours. || Attention router. All sessions' hooks (Notification, Stop, gate asks, PostToolUse errors) append events to a local SQLite bus. Gate asks become blocking: the hook writes a request row and polls for a verdict; a Stop hook can likewise wait and return the human's reply as its block reason, continuing the session. A TUI lists only items needing the human, ranked by risk and wait, each showing goal, pinned target, last actions, risk summary. Three identical command+error hashes flag a loop.
I6: Two agents working the same environment from different worktrees mutate the same live objects—Helm release, namespace, Terraform module, host config—concurrently. Terraform locks only one state during apply; kubectl, helm and ssh have no cross-session coordination. || Live-resource lease broker. The semantic gate derives a resource key for each mutating leaf command (cluster/ns/kind/name, helm release, tf state+address, host:path) and acquires a lease before allowing it: Kubernetes keys as coordination.k8s.io Lease objects in the target cluster (visible across machines), others in a shared DynamoDB/SQLite table. TTL renewed by PostToolUse, released at SessionEnd; a namespace lease blocks objects inside it. Conflicts are denied with holder session, goal and age; the human can break leases.
I7: Long multi-part tasks lose user constraints ('never touch prod-eu', 'keep CIDR 10.20/16') and pending subtasks at compaction or when handed to another session or tool; TodoWrite lives inside one session and is not enforced. || Task ledger. A UserPromptSubmit hook extracts constraint-like sentences (never/only/must/don't) and asks the agent to confirm them into .agent/ledger.yaml beside subtasks with acceptance checks and status. SessionStart (including source=compact and resume) re-injects the ledger; constraints that name targets compile into gate deny rules, so they are enforced, not remembered. Stop blocks while subtasks are open unless marked deferred with a reason. Because it is a plain file, Codex or Cursor sessions read the same ledger via AGENTS.md pointer.
I8: Agents routinely run `kubectl get secret -o yaml`, `terraform output`, `cat .env` or `helm get values` while debugging; secret values enter model context and local transcripts, and hooks generally cannot scrub Bash output after it runs. || Secret fingerprint filter. A PreToolUse hook uses updatedInput to pipe secret-emitting commands (kubectl get secret, terraform output, helm get values, env, .env/tfvars reads, vault read) through a redactor that keeps structure and keys but replaces each value with `<secret:sha256-8:len>` of the decoded value. The agent can still verify presence, cross-environment equality and rotation without seeing values. When a value must flow onward, a `secretref` helper pipes it straight into the consuming command, never to stdout.
I9: Agents debugging live systems make imperative changes—`kubectl patch/scale/edit`, `helm rollback`, editing files over ssh—outside Git. File checkpoints don't cover them, so nobody can list or revert what a session changed, or tell which session did it. || Mutation journal. Before each mutating leaf the gate allows, a PreToolUse hook saves a before-image (`kubectl get -o yaml` minus managedFields/status, current `helm history` revision, remote file copy) to <session>/journal/NNN and injects provenance: `--field-manager=agent-<session>` plus an annotation for kubectl, a commit trailer for git, a syslog line on hosts. `agent-undo <session> [--to NNN]` shows a diff, then restores in reverse order, refusing objects whose resourceVersion moved since; `agent-whodid <object>` maps managedFields to the session transcript.
I10: Infra outputs are huge and noisy—`terraform plan` on large states, `-o yaml` with managedFields, `kubectl get pods -A`, Helm renders—so they burn tokens and get truncated, often cutting the destroy summary or the failing line the agent needed. || Output shaper. A PreToolUse rewrite, applied after the secret filter, tees full output to <session>/out/NNN.log and pipes stdout through per-command reducers: plan → action list per address, deletes first, plus summary line; yaml → drop managedFields, last-applied annotation, status noise; pod lists → non-Ready rows plus counts; logs → deduplicated lines with counts, errors with context. Output ends with the log path for grep. Reducers are prioritized by measured tool-result tokens per command pattern in transcripts.

## L3

I1: Parallel sessions share global CLI state: kubeconfig current-context, gcloud active configuration, default AWS profile. When one agent switches context, every other session's next command, including destructive ones, silently goes to another cluster or account. || Session target pinning: a SessionStart hook reads the worktree's `.target` file (cluster, namespace, account). It writes a per-session kubeconfig containing only that context plus a per-session cloud config, and exports KUBECONFIG, CLOUDSDK_CONFIG and AWS_PROFILE via CLAUDE_ENV_FILE. A PreToolUse hook blocks `kubectl config use-context`, `gcloud config set` and profile switches, and tells the agent to start a new session for another target. PATH shims enforce the same for Codex/Cursor. The statusline shows the pinned target.
I2: Permission rules match command prefixes, so `terraform apply` or `kubectl delete` is either always allowed or always asked. They cannot see that the real target is prod, that the plan replaces a database, or that a variable hides the target. || Impact gate (PreToolUse hook plus PATH shim): it resolves the real target (kube context/namespace, cached `sts get-caller-identity` account, Terraform backend key) and computes the impact. For Terraform it forces `plan -out`, parses `terraform show -json` to count deletes/replaces per resource type, then allows only `apply <planfile>`. For kubectl/helm it runs a server-side dry-run or `helm diff`. A YAML policy maps (environment, action, resource class, count) to allow/ask/deny. "Ask" shows the computed summary, not the raw command.
I3: Agents run with the engineer's ambient admin credentials. Hooks only match strings, so an agent bypasses them by writing a boto3 script or curling the API. A confused agent can then do anything the human can. || Session credential broker: agents run as a separate OS user that cannot read the engineer's admin credentials. AWS credential_process and a kubeconfig exec plugin call a local broker that mints short-lived credentials for the declared task scope: STS AssumeRole with an inline session policy limiting accounts and actions, and a TokenRequest token for a ServiceAccount bound to namespace Roles. Both are read-only by default. Writes need a human-approved elevation that expires after N minutes. Role session names carry the session ID.
I4: Worktrees isolate files, not live targets. Two sessions on different branches apply to the same Terraform state or Helm release, and each apply reverts the other's unmerged change. State locks make applies take turns but never detect this. || Target lease broker: a daemon (SQLite locally, DynamoDB when shared) keyed by live target: Terraform backend+key, Helm release+cluster, namespace. A PreToolUse hook extracts the keys from mutating commands and takes a lease tied to session ID and branch. The lease lasts from the first apply until that branch merges or is rolled back. Conflicting applies are blocked with "held by session S, branch B; wait or rebase onto it". After the merge, the next holder's branch must contain that commit before it can apply.
I5: The human decides which session gets attention next. A dozen sessions across Claude Code, Codex and Cursor wait on prompts or questions in separate terminals. The engineer notices them late and approves without reading, because each prompt shows only a raw command. || Decision inbox: Notification, PreToolUse-ask and Stop hooks (and matching shims for other agents) post a record to a local queue: session, repo/branch, pinned target, impact summary from the gate, last assistant message. The PreToolUse hook waits for the answer and returns allow/deny, so the engineer never has to answer in the terminal. A TUI and a phone page sort items by environment risk and wait time, group identical requests for one-click approval, and offer "approve and add rule". They also list sessions that stopped on an unanswered question.
I6: Agents fix cluster issues by changing them directly (`kubectl edit/scale/patch`, `helm upgrade`) on resources that Argo CD or Flux manage. The next sync reverts the fix. With self-heal off, the fix becomes silent drift that the repo no longer describes. || GitOps ownership guard: for mutating kubectl/helm calls, a PreToolUse hook fetches the target objects and reads their tracking metadata (`argocd.argoproj.io/tracking-id`, `app.kubernetes.io/instance`, `kustomize.toolkit.fluxcd.io/name`, `helm.toolkit.fluxcd.io/name`). It finds the owning Application or Kustomization and its repo URL, path and values file, then blocks the command with "edit <repo>/<path>/values-prod.yaml instead". A break-glass flag lets the command run but opens a drift record. A Stop hook keeps blocking until a git commit touching that path exists.
I7: On long multi-part tasks, agents claim success from indirect signals ("manifests valid", "PR opened") or lose subtasks after compaction. In infrastructure, "done" means live state: rollout healthy, plan empty, alert cleared. Nothing checks that before the session stops. || Acceptance contract: the task is a `task.yaml` of subtasks, each with runnable checks (`terraform plan -detailed-exitcode` exits 0, `kubectl rollout status --timeout=5m`, `argocd app wait --health`, a PromQL query under a threshold). A Stop hook runs the checks for unfinished items and refuses to stop while any fail, showing the failing output. It writes pass evidence (command, exit code, output hash, time) back to the file. A SessionStart(compact) hook re-adds the remaining items after compaction. PreToolUse blocks agent edits to the checks.
I8: Live changes cannot be traced. An agent applies from an unmerged worktree branch, the PR is abandoned, and the next apply from main silently reverts the change. Cloud and Kubernetes audit logs show only the engineer's identity, not which session acted. || Apply ledger: hooks/shims record each mutating command (session ID, repo, commit SHA, resolved target, exit code) in SQLite. They also stamp the session's identity into each system: AWS role session name `agent-<sid>`, `kubectl --field-manager=agent-<sid>`, `helm upgrade --description <sid>@<sha>`, and the Terraform state serial before and after. Applies from uncommitted changes are blocked. A daily job flags applies whose SHA is not reachable from main after 24h. A query joins the ledger with CloudTrail and Kubernetes managedFields to answer "which session changed prod at 14:05".
I9: Agents work on remote hosts through `ssh host '...'` strings or heredocs, so hooks see one opaque command. There is no per-host policy, no host-side record of what the agent ran, and a shell loop can change the whole fleet at once. || Fleet exec MCP server: a hook blocks raw ssh/scp. Agents call `run(selector, cmd)`, where the selector matches inventory tags (env, role). The impact-gate policy applies per host class. Commands run through a dedicated agent key. Its authorized_keys forced command logs SSH_ORIGINAL_COMMAND and the session ID (passed via SendEnv) to journald, then runs the command. A mutating command aimed at several hosts runs on one host first, then a declared health check, then growing batches, stopping at the first failure.
I10: Each new session rediscovers the same environment facts (which cluster is in which account, bastion routes, naming conventions), wasting tokens and time. Meanwhile, hand-written MEMORY.md/CLAUDE.md facts go stale and confidently mislead agents about the current infrastructure. || Verified fact store (MCP server): each fact has text, scope tags and a `verify` command with a hash of its expected output (e.g. `aws eks describe-cluster --name prod-eu --query cluster.version`). After each session, a job scans transcripts for read-only lookup commands repeated across sessions and proposes facts from their outputs for one-click acceptance. A scheduled job re-runs the verify commands and marks a fact stale when its output changes. Agents query by topic and get fresh facts, with warnings on stale ones. CLAUDE.md keeps only a pointer to the store.

## L4

I1: An agent's real target is implicit: shared kubeconfig current-context, AWS_PROFILE, terraform workspace. One session's `kubectl config use-context` silently retargets every other session; deny-lists match command strings, not the cluster or account a command actually hits. || Session target pinning. A SessionStart hook copies kubeconfig to a per-session file and exports KUBECONFIG, AWS_PROFILE, TF_WORKSPACE (via CLAUDE_ENV_FILE) from a declared environment ('env: staging' in the task file). A PreToolUse hook blocks context/profile switches and resolves each mutating command (honoring explicit --context/--profile flags) to its concrete endpoint: API server URL, AWS account ID (cached sts), backend state key. Mismatches with the declaration are denied; prod writes need out-of-band approval showing the resolved target.
I2: Parallel sessions (separate worktrees or windows) mutate the same live resources: namespace, Helm release, Terraform state, Argo app. Worktrees isolate files, not live state; Terraform locks last one command, not the plan-then-apply window, and nothing locks kubectl/helm. || Live-state lease broker. A local daemon (SQLite) plus a PreToolUse hook on Bash parse kubectl/helm/terraform/argocd commands into resource keys (cluster/ns/kind/name, release, state key) after resolving the real target. Reads pass; mutations need an exclusive TTL lease tied to the session ID. Conflicts are denied with 'held by session X, task Y, since 12:03' so the agent waits or replans. SessionEnd or TTL releases leases; saved plan files are stamped with the lease and rejected at apply if it lapsed.
I3: Human review is the bottleneck and gets rubber-stamped: a 2,000-line terraform plan or helm diff does not reveal whether the agent changed more than asked, such as replacing a stateful resource, widening IAM, or touching an unrelated module. || Intent-scoped plan reviewer. The task declares scope in a small YAML: allowed resource address globs, namespaces, allowed actions (e.g. create/update only). A PostToolUse hook on `terraform plan -out` runs `terraform show -json` (per-object `helm diff`/`kubectl diff` for charts), deterministically classifies each change (replace, destroy, IAM/security-group widening, data-bearing resource) and checks it against scope. It returns a 10-line card (in-scope count, out-of-scope addresses) to the agent to fix, and attaches it to the PR.
I4: Agents declare 'done' at push or merge, but infra effects land later: Argo/Flux sync, rollout, cert issuance, DNS. By then the session has ended, so failures reach the human hours later, stripped of the agent's context. || Reconcile watcher with session resume. A PostToolUse hook on `git push`/`gh pr create` registers a watch: session ID, branch, changed objects, success predicates (Argo app Synced+Healthy at the merge SHA, rollout complete, no CrashLoopBackOff for 10 minutes). A daemon polls GitHub for the merge, then Argo/Flux and the cluster. Success annotates the PR; failure or timeout runs `claude -p --resume <id>` with the failing events and logs, so the original context diagnoses and drafts the fix.
I5: With 6-15 parallel sessions across terminals and tools (Claude Code, Codex, Cursor), the human cannot see which are blocked on a permission prompt, looping on a failing command, finished-unreviewed, or burning tokens; terminal bells don't prioritize. || Session switchboard. A daemon tails all transcripts (~/.claude/projects/*.jsonl, Codex session files) plus Notification/Stop hook events and classifies each session: working, awaiting-permission, awaiting-answer, finished-unreviewed, looping (same normalized command failing 3+ times), runaway (token rate far above its baseline). A tmux popup lists them ranked by human-blocked minutes, shows the pending question or last five actions, and jumps to the pane with one key. Looping sessions get paused via a flag file a PreToolUse hook checks.
I6: While debugging, agents run `kubectl get secret -o yaml`, read tfstate, print env or Helm values, so credentials enter model context, transcripts and logs. Deny-lists either block needed debugging or miss variants (jsonpath, go-template, cat of a state file). || Secret handles. Agent sessions get PATH shims for kubectl, terraform, helm and vault that redact output: Secret data fields, sensitive state attributes and known-pattern or high-entropy strings become stable handles like `secret://prod/ns/name/key#ab12` (short keyed hash so agents can compare values). A PreToolUse hook denies absolute-path bypasses and routes *.tfstate reads through the redactor. A `secret-use` wrapper resolves handles only inside the executed command's environment, so the agent can create or rotate secrets without the value entering context.
I7: Long multi-part tasks lose user constraints ('don't touch the prod module', 'keep chart 4.x', 'eu-west-1 only') through auto-compaction, subagent delegation and session handoffs; todo lists track steps, not prohibitions, and nothing checks compliance. || Constraint pin file. A UserPromptSubmit hook extracts imperative constraints (cheap model call, user confirms) into `.agent/constraints.yaml`, typed where possible: path deny glob, region/resource allowlist, version pin, or free text. SessionStart (including source=compact) re-injects them verbatim; a PreToolUse hook on the Task tool appends them to every subagent prompt; typed ones are enforced mechanically on Edit/Write/Bash. The Stop hook requires a per-constraint attestation for free-text ones. Handoff means passing the file.
I8: Agents SSH into many hosts and run ad-hoc commands; the transcript holds only the ssh string, with no per-host record of what changed, no dry-run, and no rollback for edited configs or restarted services. || SSH change journal. Agent sessions get an `ssh` shim that runs each remote command through `jexec`, a static binary copied to the host on first use. It classifies commands read/mutate (read-verb allowlist; package, service, redirect, sed -i, file-write patterns), snapshots touched paths (parsed targets, else /etc via git) and unit states before mutations, and appends a per-host journal entry (session ID, command, exit code, file diff). `hostctl undo <session>` restores snapshots in reverse order.
I9: CLAUDE.md, AGENTS.md and skills accumulate facts (cluster names, versions, endpoints, 'use module X') that go stale silently across dozens of repos with duplicated copies; agents trust them over live state and act confidently on wrong information. || Verified context facts. Facts live in one source file, each with an ID, repo scope, and a read-only check command plus expected pattern, e.g. `kubectl --context prod version -o json | jq -r .serverVersion.minor` expects `30`. A generator renders CLAUDE.md, AGENTS.md and Cursor rules per repo from it. A nightly job runs the checks; failing facts are rendered as 'UNVERIFIED since <date>, observed <value>' and opened as an issue, so agents see doubt instead of false certainty.
I10: One infra change often spans repos with ordering and data flow: Terraform creates a role and bucket, its outputs feed Helm values, then app config changes. Per-repo agent sessions don't share outputs or enforce merge order. || Change-set runner. A YAML change-set lists steps (repo, instruction, depends_on, exported outputs such as `terraform output -json` keys). The runner makes a worktree per repo and launches headless `claude -p` for a step once its dependencies are applied, injecting upstream outputs as a file and prompt section. PRs carry a shared change-set ID and a required status check that fails until predecessors merge. A failed step pauses its dependents instead of letting them guess values.

## L5

I1: Parallel agent sessions mutate the same namespace, Helm release or Terraform workspace; worktrees isolate files only, and Terraform locks cover just the apply seconds, not the plan-review-apply window. || Target-lease hook. PreToolUse parses kubectl/helm/terraform/argocd commands, resolves the target (context+namespace, release, backend key) and, for mutating verbs, takes a lease in local SQLite (or a Kubernetes Lease across machines) with session ID and task title, held from first plan/diff until verified apply or TTL. Other sessions' mutations on that target are blocked, naming the holder. P*: agent sessions sharing live targets. Measure: overlapping mutations per week from transcripts.
I2: Parallel sessions share ~/.kube/config and AWS profiles; one agent's `use-context` or a fresh shell silently retargets another session, so commands hit the wrong cluster or account. || Session environment pinning. A SessionStart hook reads a `.target` file in the worktree, writes a session-private flattened KUBECONFIG holding one context, and sets AWS_PROFILE and TF workspace through the session env file. PreToolUse blocks `config use-context`, `--context`/`--kubeconfig`/`--profile` flags naming other targets, and writes to the global kubeconfig.
