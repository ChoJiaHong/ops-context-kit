# 16 選出最好的模型版本

> **修正**：用 06 骨架跑 17 之後，發現它拿掉了最需要的部分（四種情境差異、六個縮窄維度、向下與向上迴圈、適用範圍）。改用原模型（00）重跑，見 [18](18-original-model-run.md)。結論改為：**用原模型，加上三件事（實際查證現有解法、實際量測優勢、連續兩次空轉才停）**；步驟順序交給 AI。

2026-11-07 與作者的討論整理。

## 需求釐清

作者要的是：**透過模型找出問題，再透過模型找出一個工具。不管範圍多小，至少要比現有的方法好，或改善現有的方法。**

（在這之前，誤以為作者要一個日常工作流，做了 `/start` → `/handoff` 的版本，放在 `workflow` 分支。它可以用，但不是這個需求。）

## 原模型能不能做到

能，而且比最終抽象模型（[11](11-double-loop-pure.md)）更直接：

| 需求 | 原模型裡對應的部分 |
|---|---|
| 透過模型找出問題 | 情境對比驅動的問題界定：需求當假設，拿情境和一般解比較 |
| 比現有方法好，或改善現有方法 | 基準解 Sₑ、瓶頸、優勢 = 新解 − 現有解中最好的 > 0；功能重述與局部修改 |
| 不管範圍多小 | 向下縮窄，直到現有解在某個情境不適用 |
| 至少在那個範圍裡成立 | 適用範圍 P\*，向上迴圈找出它到哪裡為止 |
| 工具也透過模型找出 | 情境差異（新增限制、缺少的限制、可用的資源、改變的假設）→ 調整或新造 |
| 不能是硬湊的 | 硬湊檢驗：拿掉差異，優勢要消失 |

最終抽象模型做不到：「和現有解比」「優勢大於 0」「在多小的範圍成立」都在抽象過程中被拿掉了。它能讓 AI 持續移動，但判斷不了產出有沒有比現有的好。

今晚自然產出的例子（[12](12-kit-loop.md)、[13](13-two-layer.md)）就是這個結構：現有解是指令黑名單 → 瓶頸是開放的指令語言補不完 → 可用的資源是任務檔本來就宣告了目標 → 新解是依任務宣告限制寫入目標和憑證 → 適用範圍是多 session、目標明確的 infra 工作。

**原模型還缺的三件事**（今晚的操作暴露出來的）：
1. 現有解要實際去查，不能憑印象（[14](14-full-delegation-gap.md) 查證太粗）。
2. 優勢要能實際量測，不能只靠模型評分（05–08 卡在這裡）。
3. 不能太早停（14 找到第一個就停；[15](15-full-delegation-redo.md) 改成連續兩次空轉才停）。

## 怕規則太死、泛化不夠

作者做最終抽象的原因，是怕規則定得太死。規則可以分三層：

| 層 | 內容 | 是否固定 |
|---|---|---|
| 判準：什麼算做好 | 有現有解可以比；在某個範圍內勝過它；拿掉差異優勢就消失 | 固定。任何領域都成立，不妨礙泛化 |
| 過程：怎麼做 | 往哪個方向縮、縮哪些維度、用哪種差異、何時轉向、何時停 | 交給 AI。變成必填清單才會綁死 |
| 動力 | 雙向迴圈 | 固定 |

只剩動力、沒有判準，會出現另一種失敗：AI 可以把任何東西說成「更好」。

## 「死規則就是模型的意義」的評估

**對一半，而且是比較重要的那一半。**

站得住的理由：
- 區分度在規則裡。雙向迴圈很普遍（Pólya、Lakatos、版本空間）；這個模型獨有的是四種情境差異、「現有解綁定了假設」的找瓶頸法、對最佳現有解的優勢加適用範圍、硬湊檢驗。
- 規則讓模型可以被檢驗：具體的規則會做出可能被推翻的預測。
- 規則逼 AI 離開「一般最佳實務」的預設，像 TRIZ 的價值就在固定的發明原則。
- 固定不等於不能泛化：四種情境差異本身是跨領域的。

只對一半的理由，在於規則有兩種「死法」：

| 死在哪裡 | 例子 | 證據 |
|---|---|---|
| 內容固定：要看哪些地方、什麼算贏 | 四種情境差異、優勢的定義、硬湊檢驗 | 還沒在主場被測過 |
| 程序固定：照順序一步步填 | 目標鎖定 → 基準解 → … | [08](08-results.md) 是負面的：固定步驟沒有比一般結構化提示好，數學題輸出長 2.7 倍 |

結論：**模型的意義在內容，不在程序。**

## 選擇：06 的收斂骨架，用 11 的方式跑

**內容**（06 §5）：
1. 目標鎖定。
2. 基準解：該類問題最好的現有解。
3. 綁定假設與瓶頸。
4. 違反預設的差異；找不到就採用基準解。
5. 功能重述與局部修改。
6. 接受條件：新解比基準好，而且拿掉差異後就不再比基準好。

**調整**：
- 六個環節是「要看的內容」，不是固定順序；順序和來回交給 AI，用雙向迴圈的方式跑。
- 「適用範圍 P\*」從選配改成必做，因為需求是「不管範圍多小，但要成立」。
- 加上今晚學到的三件事：基準解要實際查證、優勢要實際量測、連續兩次空轉才停。

**一句話：06 的骨架是內容，11 的雙向迴圈是動力。**

## 證據的現況（照實寫）

- 06 的正面結果，屬於它的前身（04 骨架），任務是分析模型本身，不是產生工具。
- 收斂骨架本身在 08 的結果：在 MacGyver 可解題上比直接解題好 5–12.5 個百分點，但沒有比一般的結構化提示好；「找不到就用現有解」也沒有讓模型更會判斷無解（0.30 對 0.40）。
- 這些都不是它的主場。

## 下一步要測什麼

在主場測：給一個有成熟工具的領域，要求「找一個範圍，做出比現有工具好的東西」，比較：
- **A**：只有雙向迴圈。
- **B**：雙向迴圈加 06 的內容和判準。

**判準**：查證現有工具之後，確實勝過它們的方案數量與明顯程度。B 穩定勝出，就證明具體的規則是這個模型的意義。
