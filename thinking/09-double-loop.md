# 09 雙迴圈：迭代「有範圍的主張」

## 為什麼重寫

05–08 測的都是把模型壓成「一次跑完的六步提示」，雙迴圈本身（多輪、每輪拿真實結果回饋）從沒被測過。作者判斷雙迴圈有用，只是還沒抽象好、缺了一些條件，尤其是有 agent 之後。這一篇把它重寫成 agent 能照著跑的流程，並在真實決策上試驗。

不走遺傳算法：族群、交配、大量評估都需要秒級的自動評估器，大部分場景沒有。這裡保留單線迭代，只借兩個想法：每一輪都要碰到真實結果；輸出的是範圍，不是單一答案。

## 迭代的對象：有範圍的主張

迭代的不是解法，而是一個主張：

> 在目標 **G** 下，解法 **S** 在條件 **C** 內勝過基準解 **Sₑ**，證據是 **E**。

| 符號 | 意思 | 例子（試驗 1） |
|---|---|---|
| G | 不准改的目標 | agent 的指令執行前，攔下 prod 變更與不可逆操作，但不打擾唯讀工作 |
| Sₑ | 現成的做法 | Claude Code 內建的權限規則（依指令前綴 allow／ask／deny） |
| S | 要檢驗的解法 | guard.py |
| C | 主張成立的條件 | 善意 agent 寫的 Bash 指令、目標名稱照 TRUTH.md、指令內容看得到 |
| E | 每個判斷的證據 | 執行 guard 的實際結果 |

## 兩個迴圈

- **向下（讓主張成立）**：主張還不成立時，加條件或修改 S，直到它在某個 C 裡成立。可用的動作就是原模型的四種情境差異：新增限制、缺少的限制、可用的資源、改變的假設。
- **向上（找邊界）**：主張成立後，一次放寬一個條件，找出 S 不再勝過 Sₑ、或違反 G 的具體反例。

每個反例只有三種處理方式：

1. **修 S**：範圍不變，解法變好（附回歸測試）。
2. **縮 C**：明白寫出「不涵蓋這種情況」。
3. **改判**：反例不算數（例如超出 G 的威脅模型）。這一項必須由人決定。

**目標鎖定**：不准靠改 G 來躲反例。**硬湊檢驗**：宣稱的優勢必須來自 S；把 S 換回 Sₑ、其他不變，優勢應該消失。

## 角色

| 角色 | 做什麼 | 不做什麼 |
|---|---|---|
| 提案者 | 寫主張、提出 S 或修正 | 不判定自己的修正有效 |
| 反駁者 | 只看主張與 S，一次放寬一個條件，交出可重現的反例 | 不看提案者的推理，不修 |
| 驗證者 | 自動重現每個反例、標證據等級與嚴重度 | 不產生反例 |
| 人 | 定 G；決定「改判」和「縮 C」 | 只看已重現的項目 |

人自己做向上迴圈通常很弱：沒人想推翻自己的點子。agent 讓「獨立的反駁者」變便宜，這是 agent 帶來的主要改變。瓶頸因此移到評估器與人的判斷，所以後兩個角色的規則最嚴。

## 證據等級

| 等級 | 來源 | 可以用來 |
|---|---|---|
| E4 | 自動可重現：執行程式、測試、重播真實紀錄 | 接受或推翻主張 |
| E3 | 受控實驗：staging、模擬 | 接受或推翻主張 |
| E2 | 人的判斷 | 改判、縮 C |
| E1 | 模型意見 | 只能提出候選，不能接受任何東西 |

05–08 卡住的原因就是只有 E1。

## 主張紀錄

每個主張一個檔案，跨輪保存（沒有紀錄，每一輪都等於重新想一次）：

```
主張：G / Sₑ / S / C
第 n 輪
  反例 x：輸入、預期、實際、證據等級、嚴重度、處理（修 S／縮 C／改判）、處理後的證據
不涵蓋（縮 C 的累積）：…
目前狀態：成立／待修／已停止（原因）
```

## 觸發與停止

- **觸發**：S 即將變成規則、預設值、共用元件；或 S 在新情境失敗。一次性的決定不跑。
- **停止**：某一輪沒有新的、在範圍內的嚴重反例；或滿 3 輪；或預算用完。

## 和既有做法的關係

這個結構很多領域各自發現過：Pólya 的特殊化與一般化、Lakatos《證明與反駁》用反例調整定理的範圍、Moore《跨越鴻溝》先攻小市場再擴到相鄰市場、property-based testing 產生反例再縮小。不同領域反覆得出同一結構，表示模式本身可靠；也表示新意不在模式，而在操作化：明確的基準解、反例的三種處理、靠 agent 分開角色、證據等級。

## 驗證計畫（預先登記，試驗開始前寫下）

**整體判準**：在 5 個真實決策上試驗。至少 2 次找到「在範圍內的嚴重反例，而且既有測試與先前審查都沒涵蓋」，且每次交給人判斷的項目不超過 5 個，就把流程做成正式 skill；否則停止，只留成個人習慣。

**試驗 1：guard.py**（觸發理由：v3 的 guard 即將決定是否併入 main 成為預設）

- 嚴重度：
  - **S1**：該攔沒攔（prod 變更或不可逆操作沒有 ask、改全域狀態或沒帶 --context 沒有 fix、災難指令沒有 deny）。
  - **S2**：唯讀或非 prod 的工作被打擾（多出 ask／fix／deny）。
- **在範圍內**：善意 agent 在一般維運工作中可能寫出的指令形式。刻意混淆（編碼後 eval、拼接指令名稱等）不在 G 的威脅模型內，只記為邊界。
- **先前沒涵蓋**：不在 evals/guard_test.py 的案例裡，也不在 method/round1–3 的發現裡。
- **對照**：第 1 輪同時派兩個反駁者，同模型、同工具、同上限（各最多 25 個案例）。
  - A 組拿到主張（G、Sₑ、S、C），被要求一次放寬一個條件找反例。
  - B 組只被要求「審查 guard.py，找出誤判」。
  - 比較兩組各自找到、經重現、在範圍內的 S1 數量。只有一次，結果只能看方向。
- **處理**：能用局部規則修、且不讓既有測試出現新的 S2，就修 S 並加回歸測試；否則縮 C，寫進 guard.py 的「不涵蓋」說明。
- **停止**：某一輪重現的新 S1（在範圍內）為 0，或滿 3 輪。第 2 輪起只派 A 組形式的反駁者，並給它目前的紀錄。
