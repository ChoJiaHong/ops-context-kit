### Analysis
Core observation: agent tooling isolates *code* (worktrees, branches, PRs, sandboxes) but infra work mutates *shared live state* (clusters, Terraform state backends, cloud accounts, hosts) that is not versioned or isolated per session. Most damaging failures therefore come from four gaps:
(a) what environment a command really hits: permission rules match command strings, so `kubectl apply` against kind and against prod look identical; kubeconfig/cloud profiles are global mutable files shared by all parallel sessions;
(b) two sessions touching the same thing: Terraform locks cover only the apply instant, not the plan-review-apply window; nothing coordinates Helm releases or namespaces;
(c) the human reviewing the agent's prose instead of ground truth: plan summaries, "fixed it" claims, kubectl hotfixes that GitOps silently reverts;
(d) unverifiable "done" on long tasks: TodoWrite is self-attested and in-context; compaction loses requirements.
Secondary gaps: verbose infra CLI output floods context; secrets from Secrets/tfstate land in transcripts and provider logs; instruction files state environment facts that go stale; nobody can reconstruct "what changed in prod today" across many sessions and vendors.

What exists and why it falls short: Claude Code allow/deny patterns (syntactic), OS sandboxing (filesystem/network, not cloud-API semantics), Terraform state locking (too narrow in time), Argo/Flux self-heal (reverts after the fact, agent loops), OPA/conftest (manifest-level, not agent-command-level), CI secret scanners (commits only), compaction summaries (lossy), multi-session managers (show status, not infra conflicts).

Design principles for the proposed tools: enforce deterministically outside the model (hooks plus PATH shims so Codex/Cursor get the same protection, not only Claude); resolve the real target instead of parsing intent; prefer evidence produced by the tool over agent self-report; keep state on disk so it survives compaction and spans sessions and vendors. Several items share one substrate (a shim layer that resolves targets), which makes them cheap to build together while remaining separate mechanisms.

Ranking: irreversible prod damage first (target gate, context pinning, leases, plan attestation), then correctness of outcomes (GitOps guard, task contracts), then auditability, security, efficiency and knowledge freshness.

### Items
I1: Permission rules match command strings, so `kubectl delete` or `terraform apply` against prod and a kind cluster look identical; allowlists end up too broad (risky) or too narrow (constant prompts across parallel sessions). || Target-aware gate: PATH shims plus a PreToolUse hook parse kubectl/helm/terraform/aws/gcloud/ssh invocations, resolve the real target (effective context to cluster server URL, TF backend key, AWS account via cached STS identity, host inventory group), classify the verb as read/mutate/destroy, and look up a YAML policy matrix (env x verb -> allow/ask/deny). Approval prompts show the resolved target ("DESTROY in prod-eu/payments"), not the raw command. Unresolvable targets default to ask.
I2: Kubeconfig current-context, gcloud/AWS profiles and Terraform workspace are global mutable files; one agent running `kubectx` or `terraform workspace select` silently redirects every other parallel session on the machine. || Session environment pinning: a SessionStart hook creates per-session copies (KUBECONFIG=~/.agentenv/<sid>/kubeconfig, CLOUDSDK_CONFIG, AWS_CONFIG_FILE, TF_WORKSPACE) and exports them through CLAUDE_ENV_FILE (wrapper script for other agents). Shims refuse writes to the shared originals. The pinned target is shown in the status line and injected into context; changing it requires `agentenv switch <ctx>`, which the I1 gate logs and can require approval for.
I3: Parallel sessions can mutate the same namespace, Helm release or Terraform root unaware of each other; Terraform's lock covers only the apply instant, so stale plans and colliding rollouts go unnoticed. || Local lease broker: a small daemon (SQLite behind a Unix socket) from which the gate acquires a lease keyed on the resolved target (cluster/namespace, release, TF state key) before any mutating verb. Leases carry holder session, task description, TTL and PostToolUse heartbeats. Conflicts are blocked with "held by session X: 'upgrading ingress', 12 min". At plan time the TF state serial is recorded; apply is refused if the serial changed since.
I4: Terraform/Helm plans are long, so humans approve the agent's prose summary ("only tag changes"), which can omit replacements, destroys or IAM widening; apply may also run a different plan than the one reviewed. || Plan attestation: a shim forces `terraform plan -out`, then deterministically parses `terraform show -json` (and `helm diff`) into a risk card: destroys, forced replacements, IAM/security-group/network changes, stateful resources, counts per action. The card, not the agent's summary, is shown at approval and its plan-file SHA-256 recorded. Only `apply <planfile>` with a matching hash is allowed; a Stop hook flags agent summaries contradicting the card.
I5: Agents fix incidents with `kubectl edit/patch/scale` on GitOps-managed resources; Argo/Flux reverts them or drift persists, and the agent loops or reports a fix that never reached Git. || GitOps ownership guard: before a mutating kubectl call, the hook reads the target object's ownership labels/annotations (argocd.argoproj.io/instance, kustomize.toolkit.fluxcd.io/name). If managed, it denies and returns the owning app's repo, revision and path, plus the exact source file from an index built by rendering each app (kustomize build / helm template) and mapping kind/namespace/name to file. Break-glass override requires human approval and auto-creates a backport-to-Git issue.
I6: Long multi-part tasks end with "done" while sub-steps were skipped, half-applied or lost in compaction; TodoWrite lists are self-attested and live only in context, so nothing checks claims against reality. || Evidence-gated task contract: at start the task is compiled into `.agent/contract.yaml`: each requirement with a verification command (`kubectl rollout status`, `curl -f`, `terraform plan -detailed-exitcode` exits 0). A SessionStart hook with the compact matcher re-injects it. The Stop hook runs unverified checks itself and blocks stopping with the failing list; items close only via passing checks or explicit human waiver, recorded with output hash.
I7: Nobody can answer "what changed in prod today, by which session and why": side effects are scattered across many local transcripts, several agent vendors and SSH sessions, and git history covers only what was committed. || Cross-session change ledger: shims for mutating infra commands (and an ssh wrapper that commits /etc via etckeeper before and after each sudo command) append JSONL records: timestamp, session id, agent vendor, task summary, resolved target, command, exit code, diff/plan hash. One machine-wide file is synced to a shared bucket; a CLI answers queries (`ledger --target prod/payments --since 6h`) and prints a rollback hint per entry (previous Helm revision, prior file version).
I8: Agents routinely read Secrets, tfstate, env vars and Helm values containing credentials; these land verbatim in model context, provider logs and local transcripts, while existing secret scanners only check commits. || Redacting exec wrapper: the hook rewrites infra commands to run via `agent-exec`, which pipes stdout through detectors (Kubernetes Secret `data:` fields, tfstate `sensitive` values, known token formats, high-entropy strings) and replaces values with stable placeholders (`<<secret:db-password:9f3a>>`). The wrapper substitutes real values back when the agent passes placeholders to later commands, so workflows still work. A nightly job scans transcript JSONL for leaks and names the leaking command.
I9: Infra CLIs emit huge outputs (`kubectl get -A -o yaml`, `helm template`, plan logs, pod logs) that flood context, trigger early compaction, raise cost and bury the relevant line; naive `head` truncation drops the error. || Output spill-and-digest shim: when output exceeds a token budget, the wrapper writes it to `.agent/out/<id>.log` and returns a digest: line count, error/warning lines with line numbers, resource-kind counts, first/last N lines, and the path for targeted grep. A weekly transcript analyzer ranks commands by tokens consumed and proposes per-command rules (force `-o name`, `--tail=200`) for the shim config.
I10: CLAUDE.md/AGENTS.md/Cursor rules across many repos state environment facts (cluster names, endpoints, versions, owners) that silently go stale or diverge, and agents act on them confidently. || Probed instruction facts: instruction files are generated per repo from a shared fragment repo, and each factual line carries a probe annotation, e.g. `<!-- probe: kubectl --context prod-eu version -o json | jq -e '.serverVersion.minor=="30"' -->`. A scheduled CI job (no LLM) runs all probes with read-only credentials, marks failing lines as STALE in every generated CLAUDE.md/AGENTS.md/.cursor/rules output, and opens a PR showing the observed value.
