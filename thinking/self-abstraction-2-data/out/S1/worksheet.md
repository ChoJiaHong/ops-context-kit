# 工作表：目標方法的核心骨架與最適問題

## 0. 目標方法的三個版本（分析前的整理）

| 版本 | 起點 | 主要移動 | 輸出 |
|---|---|---|---|
| 筆記一：創新縮窄法 | 大而模糊的問題 | 現有解法 → 限制 → 向下縮窄 → 在地差異 → 用差異突破限制；以「硬湊」檢驗 | 新方案 |
| 筆記二：縮窄法 | 一般問題 P0 | 向下 Loop 找「既有解非最佳」的情境 → Match(L, D) → Adapt → 向上 Loop 求 P* | (P*, Sn) |
| 筆記三：情境對比驅動的問題界定 | 具體問題 P0 | 向上抽象為類別 → 一般解 → 對比 ΔContext → 映射為限制／資源／假設 → 重寫表徵 → 驗證目標 | 重寫後的問題表徵與適配解 |

初步觀察：三版的移動方向不同（一、二由一般往具體縮窄；三由具體往一般抽象），但都在「一般層」與「具體層」之間建立對比，並以一般層的既有解作為比較基準。

## 1. 參照

| 代號 | 參照方法 | 核心 | 最擅長的問題 |
|---|---|---|---|
| R1 | 直接請 LLM 解題（含 Chain-of-Thought） | 把使用者的描述當成問題本身，用模型內化的一般知識直接生成解法；CoT 只是把推理展開 | 表述完整、情境典型、答案可由一般知識推得的問題（常見程式錯誤、教科書式設計） |
| R2 | TRIZ | 把具體問題抽象成技術或物理矛盾（通用工程參數），查矛盾矩陣與發明原則，再具體化 | 工程系統中「改善 A 就惡化 B」的明確參數矛盾 |
| R3 | 案例式推理（CBR） | 檢索相似舊案 → 重用 → 修正 → 保留 | 重複出現、有大量歷史案例、新題與舊案高度相似的問題（客服、維修、判例） |
| R4 | 設計思考 | 同理使用者 → 定義需求 → 發散發想 → 原型 → 測試迭代 | 以人為中心、需求本身尚不清楚的產品或服務問題 |
| R5 | 根因分析（5 Whys、魚骨圖、故障診斷） | 從症狀沿因果鏈追問到根因，修正根因使系統回到正常 | 有明確「正常狀態」、偏差由少數原因造成的故障 |
| R6 | 類比推理（含 Analogical Prompting） | 到其他領域找結構相似的已解問題，映射其解法 | 本領域缺解、但遠領域有同構解的問題 |
| R7 | 一般性問題重構（HMW、換個角度問） | 用通用提問模板改寫問題敘述以擴大解空間 | 思路卡住、需要發散的早期構想 |

## 2. 綁定假設

| 參照 | 為了通用而預設的條件 | 造成的瓶頸 |
|---|---|---|
| R1 直接 LLM | 情境是典型的（未提及的條件等於一般條件）；使用者表述完整且正確 | 答案趨向訓練分布中的「平均解」：阿里山搜救仍回答「固定基地 UAV」；錯誤框架照單全收（CPU 高 → 加機器）；即使特殊條件被提到，也多當作背景，不會重新詮釋其功能 |
| R2 TRIZ | 問題能化成通用參數之間的矛盾；通用原則足以覆蓋解空間 | 抽象時把情境特有資源化約成泛稱或丟掉；必須先把矛盾說清楚；不與既有最佳解比較，也不界定適用範圍 |
| R3 CBR | 相似問題有相似解；差異是要最小化的相似度誤差；修正只是小幅調整 | 差異被當雜訊，而非突破來源；案例庫沒有的資源組合想不到；情境越特殊越檢索不到 |
| R4 設計思考 | 洞見主要來自使用者需求；不需要既有解作為基準 | 產出多但缺乏與既有最佳解的比較，容易重新發明或貼標籤；對基礎設施、物理資源類的情境差異不敏感；成本高 |
| R5 根因分析 | 存在「正常狀態」，問題是偏離；目標是恢復而非改進 | 只找原因、不找資源；既有解可用但非最佳時（沒有故障）無著力點；不產生新解 |
| R6 類比推理 | 遠領域有同構來源，且找得到 | 來源選擇偶然、容易表面映射；不檢查本情境實際擁有的資源；與本地既有解脫節 |
| R7 一般性重構 | 換句話問就能鬆動框架；模板與情境無關 | 重構方向由模板而非情境資料驅動，產生泛泛的改寫；沒有判準決定哪個重構較好；可能悄悄改掉目標 |

參照方法共通的綁定假設：

- A1 情境典型：一般情況的資源與限制，就是本情境的資源與限制。
- A2 表述可信：使用者給的問題描述完整而正確。
- A3 差異是雜訊：情境細節在抽象或比對時應被去除或最小化。
- A4 功能固定：資源依它原本的用途被看待（鐵路就是交通工具）。
- A5 不必比較：不需證明新解勝過既有最佳解，也不需界定適用範圍。

| D7 | Adapt：新解 = 既有解 + 差異，而非從零生成 | 筆記一公式；筆記二 Sn = Adapt(Se, L, D) | R4、R7 從零發想 |

| D10 | 向上泛化：逐步移除情境條件，求優勢仍成立的最大範圍 P* | 筆記二第三部分 | 參照方法不界定範圍 |

## 4. 作用與功能重述

| 參照的瓶頸（來源） | 解掉它的差異 | 功能重述：這個差異對瓶頸做了什麼 |
|---|---|---|
| B1 回到平均解，情境資源被平均掉（A1；R1、R3） | D3 | 把被一般解平均掉的情境條件拉出來，變成可逐條檢查的清單 |
| B2 差異被當雜訊丟掉（A3；R2、R3） | D3 + D6 | 把差異從「誤差」改判為「訊號」，但只保留能動到瓶頸的那幾條 |
| B3 發散沒有方向、沒有判準（R4、R6、R7） | D1 + D2 | 以一般解的瓶頸作為搜尋座標，把無限多的情境差異收斂到與瓶頸相關的少數 |
| B4 功能固著（A4；全部參照） | D4 + D5 | 把差異從「它是什麼」改寫成「它能對瓶頸做什麼」，讓資源可以和瓶頸對接 |
| B5 只能處理失效，非最佳時無著力點（R5） | D2 | 把搜尋空間從「既有解壞掉的地方」擴大到「既有解還能用、但不再最好的地方」 |
| B6 換名式創新、貼標籤（A5；R4、R7） | D8 + D9 | 用反事實與相對比較，區分真正的改進與包裝 |
| B7 錯誤或不完整的框架被照單全收，或重構時偷換問題（A2；R1、R7） | D11 | 放寬表述、鎖住目標：允許重寫問題表徵，但不讓它變成解另一個較容易的問題 |
| B8 不知道新解能用多廣（過窄或過度宣稱）（A5） | D10 | 把單點發現轉成有邊界的問題類別 |
| B9 從零發想成本高、與本地既有解脫節（R4、R6） | D7 | 保留既有解已驗證的部分，只改被差異影響的部分 |

沒有對上任何瓶頸的差異：

- D12 六維度：只是提高 D3 找差異的效率，屬於檢索輔助。
- D13 循環：流程控制。
- D14 教學包裝：傳播用途。
- D15 方向：兩個方向都能建立對比，方向本身不解瓶頸。
- D9 的效用函數 U 本身在筆記二中未定義；發揮作用的是「與既有最佳解比較」這個要求，而非公式。

重述後的整體作用：目標方法做的事是**拆掉一般解的綁定假設**——找出一般解為了通用而預設的條件，檢查本情境違反了哪一條，再把違反之處當作資源、限制或假設改變，回頭改寫一般解。

## 5. 範圍

讓問題類型沿各軸往參照方法的擅長區靠近或遠離：

| 移動軸 | 靠近參照擅長區時 | 遠離時 | 邊界條件 |
|---|---|---|---|
| 情境典型度（靠近 R1、R3） | 情境越典型，差異越接近空集合，新解 ≈ 一般解，優勢歸零且多花成本 | 情境越特殊，可用差異越多；過度獨特只會讓推廣範圍變窄，不影響單題優勢 | 情境至少違反一般解的一條預設 |
| 差異的顯著度（靠近 R1） | 特殊條件已明寫、用途一望即知時，直接請 LLM 也會用上，優勢縮小 | 條件沒被提及、或用途需要重新詮釋時，優勢最大 | 差異未被表述，或其功能意義不明顯 |
| 既有解成熟度（靠近 R4、R6） | 沒有既有解或一般類別難以界定時，失去基準與瓶頸，方法沒有座標 | 既有解成熟、瓶頸可指名時，優勢最大 | 存在可指名的一般解與瓶頸 |
| 故障 vs 非最佳（靠近 R5） | 純故障、單一根因：因果追查更直接；本方法只在「通用修法的預設被情境推翻」時加值（如 CPU 高 → 加機器，預設是「負載真的上升」） | 既有解可用但非最佳：根因分析沒有著力點，本方法有優勢 | 既有解可用但非最佳，或通用修法的預設在本情境被違反 |
| 解的來源（靠近 R2） | 通用原則即可解時，TRIZ 更快 | 突破必須依賴本地特有條件時，本方法有優勢 | 解依賴情境特有條件 |
| 案例可得性（靠近 R3） | 已有近乎相同、且用過同一差異的舊案時，直接取用即可 | 沒有現成案例時，本方法有優勢 | 沒有已利用該差異的現成案例 |
| 目標明確度（靠近 R4、R7） | 目標本身待探索時，鎖定目標反而有害 | 目標固定、成功標準可陳述時，本方法有優勢 | 目標可固定 |
| 可比較性 | 新舊解無法比較時，優勢無從確認 | 至少能定性比較時，優勢可確認 | 新舊解至少能定性比較 |
| 領域（創新 vs 問題界定） | 兩類都適用：筆記一、二的搜救屬於創新；筆記三的 SRE、程式、客服例子屬於問題界定 | — | 由結構而非領域決定 |

**P\***：目標固定、已有成熟一般解，但具體情境違反了該解的某些預設（多出可用資源、缺少或新增限制、假設不同），使一般解雖可用卻非最佳，且這些違反沒有被表述、或用途不明顯的問題。

進入條件：
- C1 目標與成功標準可固定。
- C2 一般問題類別有成熟既有解，且瓶頸可指名。
- C3 本情境至少違反該解的一條預設。
- C4 該違反可改寫成作用在瓶頸上的資源、限制或假設改變。
- C5 違反沒有被明說，或其功能用途不明顯（否則直接解題即可）。
- C6 新舊解至少能定性比較。

## 6. 必要（逐一拿掉元素）

| 元素 | 拿掉後會怎樣 | 在 P* 上還有優勢嗎 | 判定 |
|---|---|---|---|
| M1 目標鎖定（表述當假設、目標不可變；D11） | 不把表述當假設，就不會去找未表述的條件，C5 下與直接解題無異；不鎖目標，可能把題目改成較容易的問題再宣稱優勢（Problem Drift） | 否 | 核心 |
| M2 一般解基準（D1） | 沒有參照，差異無從定義，退化為設計思考或一般重構式的發散 | 否 | 核心 |
| M3 綁定假設與瓶頸（D2） | 差異沒有篩選，全數羅列，不知道哪條有用；退化為一般重構 | 否 | 核心 |
| M4 情境對比找差異（D3） | 只剩一般解，退化為直接解題或案例檢索 | 否 | 核心 |
| M5 功能重述與對接（D4、D5、D6） | 差異列得出來，但停在「它是什麼」（鐵路仍是交通工具），進不了解法；方案變成貼標籤 | 否 | 核心 |
| M6 必要性檢驗（D8、D9） | 無法區分真改進與換名，輸出可能是一般解加上在地標籤；優勢無法保證 | 否 | 核心 |
| M7 在既有解上修改（D7） | 依差異從零生成，只要差異已對上瓶頸，仍可能勝出；但失去既有解已驗證的部分，風險上升 | 是（減弱） | 非核心，建議保留為預設做法 |
| M8 向上泛化求 P*（D10） | 單一問題的解不受影響，只失去可攜帶性；筆記三也因 Problem Drift 主動拿掉 | 是 | 非核心（推廣或研究定位時再加） |
| M9 縮窄方向（D15） | 改成具體 → 抽象（筆記三）仍成立；不變的是兩層對比 | 是 | 非核心 |
| M10 六維度清單（D12） | 差異較難找齊，但有對比仍找得到 | 是 | 非核心（可作為列預設時的提示清單） |
| M11 循環（D13） | 一次對比即可產生優勢；循環只是失敗時的重試 | 是 | 非核心 |
| M12 效用函數形式化（D9 的 U） | 以定性比較代替仍成立 | 是 | 非核心 |
| M13 教學包裝（D14） | 不影響解題 | 是 | 非核心 |

**核心骨架（6 項）**：
1. 目標鎖定：問題表述是可修改的假設，目標與成功標準不可改。
2. 一般解基準：把問題上提到一般類別，取其最佳既有解作為比較錨點。
3. 綁定假設與瓶頸：找出一般解為通用而預設的條件，以及它在本情境非最佳的瓶頸。
4. 情境差異：比對具體與一般情境，挑出本情境違反的預設。
5. 功能重述對接：把差異改寫成對瓶頸的作用（資源、限制、假設改變），據此修改一般解。
6. 必要性檢驗：新解須勝過最佳既有解，且拿掉該差異就不成立。

## 附註：本次分析的侷限

- 所用分析工具與目標方法結構幾乎同構（參照 ↔ 一般解；差異 ↔ ΔContext；作用 ↔ Match／Adapt；範圍 ↔ 向上 Loop；必要 ↔ 硬湊檢驗；綁定假設 ↔ 瓶頸來源；功能重述 ↔ 資源重新詮釋）。用它分析目標方法有循環確認的風險：骨架中的「綁定假設」「功能重述」措辭部分來自工具本身，而非筆記原文（筆記三的「Changed Assumption」與筆記一的資源重新詮釋是最接近的原文依據）。
- 各元素「拿掉後是否仍有優勢」是定性推論，未經實驗；筆記三建議的 ablation 才能實證。
- 筆記四無法讀取，未納入。
