# 工作表

## 步驟 1：參照
| 參照方法 | 核心 | 最擅長的問題 |
|---|---|---|
| 直接請 LLM 解題 | 依題目字面，輸出訓練中學到的典型解法 | 定義清楚、有標準答案的問題 |
| 思維鏈／分解規劃 | 把題目拆成步驟逐步推理 | 結構明確、可拆解的推理與計算 |
| 類比／案例推理（CBR） | 找相似的已解案例，再改寫套用 | 有相似先例、結構對應清楚的問題 |
| TRIZ | 把問題抽象成矛盾，查通用發明原則 | 技術性的工程矛盾 |
| 一般問題重新界定（How Might We、設計思考） | 換說法、換視角重述問題 | 問題模糊、需靠人實地訪查的前期探索 |
| 問題診斷／5 Why | 追查現有做法為何失敗的根因 | 系統故障、既有做法壞掉的情況 |

## 步驟 2：綁定假設與瓶頸
| 參照方法 | 預設 | 造成的瓶頸 |
|---|---|---|
| 直接 LLM／CoT | 使用者描述的問題就是真問題；典型解法適用 | 只回答表面問題；忽略這個情境特有的資源與限制；誤診（例：CPU 高就加機器）無人察覺 |
| 類比／CBR | 找得到結構相似的案例；改寫知道要改哪裡 | 案例與目標情境不同處沒有被系統化比較，改寫靠運氣 |
| TRIZ | 問題可抽象成通用參數；解法來自通用原則 | 抽象把在地資源丟掉了，產出通用而非貼合情境的解 |
| 一般重新界定 | 換個說法就能產生新視角 | 沒有指向「改哪裡」的錨點，容易漂移或只是換名字 |
| 問題診斷 | 現有解法已經失效 | 看不到「仍可用但已非最優」的情境 |
| 共通 | 為了通用，把情境視為雜訊或背景 | 情境中的差異（資源、基礎設施、限制）沒有被當成解題材料 |

## 步驟 3：差異（目標方法 vs 參照）
1. 先取「一般問題類別的一般解法」當基準，再與具體情境逐項比較（參照方法多半只看其一）。
2. 錨定在一般解法的「瓶頸」，包含「仍可用但非最優」，不限於失效。
3. 把情境差異分類成新限制、缺少的限制、可用資源、被改變的假設。
4. 資源重新詮釋：把既有事物換個功能看（列車→移動基礎設施）。
5. 使用者描述視為假設；最終目標固定，只改問題的表徵。
6. 差異要承重：拿掉在地特色方案仍成立就是硬湊。
7. 向上泛化，求優勢仍存在的最大問題範圍，輸出 (P*, Sn)。
8. 向下縮窄循環，尋找優勢出現的情境。
9. 對原目標回驗。

## 步驟 4：作用與功能重述
解掉參照瓶頸的差異，改寫成「對瓶頸做什麼」：
| 原本寫法（是什麼步驟） | 改寫（對瓶頸做什麼） | 解掉哪個瓶頸 |
|---|---|---|
| 先取一般解法 | 提供一個可被攻擊的靶：有了基準才知道哪裡可以更好 | 重新界定的無錨點；直接 LLM 的典型解不被檢視 |
| 找出一般解的瓶頸 | 把搜尋範圍從整個解空間縮到一個量（如往返距離） | TRIZ 抽象過度；類比不知改哪裡 |
| 比較具體與一般情境、列差異 | 把被通用設計當雜訊的情境，變成解題材料 | 共通瓶頸：情境被忽略 |
| 差異對接瓶頸（Match）／資源重新詮釋 | 讓差異去改變瓶頸背後的量（鐵路使基地靠近搜索區，往返距離縮短），而不是貼標籤 | 類比改寫靠運氣；TRIZ 丟失在地資源 |
| 非最優而非失效 | 讓「還能用但不夠好」的情境也進入搜尋 | 問題診斷只看失效 |
| 描述視為假設、目標固定 | 允許修正問題表徵，同時防止題目被偷換 | 直接 LLM 的誤診；重新界定的漂移 |
| 承重檢驗（拿掉特色是否仍成立） | 剔除不作用於瓶頸的差異 | 重新界定只換名字 |
| 向上泛化到 P* | 說明解法能搬到哪些情境 | 案例改寫無法界定適用範圍 |

## 步驟 5：範圍（找 P*）
讓問題往參照方法擅長的領域移動（優勢消失處）：
- 去掉具體情境，只剩一般問題：差異集合為空，目標方法退化為一般解法，與直接 LLM 同。優勢 = 0。
- 一般解法本身沒有瓶頸（已最優、問題小、直接執行即可）：無靶可打。
- 有情境差異，但與瓶頸無關（例：只是地名、人群標籤）：差異不承重，等於硬湊，與一般解法同。
- 找不到成熟的一般解法（全新問題）：基準不存在，類比／TRIZ／直接探索更合適。
- 問題定義清楚且正確、只需計算或拆解：CoT／分解已足夠。
- 目標本身不明、需要先釐清要什麼：目標無法固定，方法的回驗失效，設計思考／訪談較合適。

往目標方法擅長的方向移動（優勢增強）：情境越具體、越含有未被利用的資源或基礎設施、一般解法瓶頸越明確且由可被情境改變的量決定（距離、成本、時間、資源），優勢越大。

阿里山例的向上泛化：阿里山鐵路 → 有固定運輸路線深入搜尋區的搜尋 → 有可移動補給載具的廣域搜尋；到差異不再改變瓶頸（沒有任何可移動的補給來源）處停止。

P*：一般解法成熟、其瓶頸由某個可被情境改變的量決定，且問題情境中存在能改變該量、且在原本做法中未被利用的資源或限制變化，同時任務目標已固定。進入條件即此三項同時成立。

## 步驟 6：必要（逐一拿掉）
| 元素 | 拿掉後在 P* 還有優勢嗎 | 判定 |
|---|---|---|
| 一般問題類別與一般解法基準 | 沒有靶，退成一般重新界定／直接 LLM；失去優勢 | 核心 |
| 找出一般解的瓶頸（含非最優） | 差異失去對接對象，只能盲目找；退成類比／重述；失去優勢 | 核心 |
| 具體情境與一般情境的差異比較 | 沒有新材料，解法只能來自一般解；失去優勢 | 核心 |
| 差異→瓶頸的功能對接（含資源重新詮釋） | 差異停在標籤，等於硬湊；失去優勢 | 核心 |
| 差異承重檢驗 | 不承重的差異混入，方案變成一般解換名；優勢縮水至無 | 核心 |
| 目標固定與回驗 | 在 P* 上可能產生看似更好卻已偷換題目的解，無法算優勢（任務成功是主要指標） | 核心 |
| 使用者描述視為假設 | 在已有明確一般解與瓶頸的 P* 內，優勢仍在；它只在誤診情境擴大範圍 | 非核心（擴展用） |
| 向上泛化求 P* | 對單一情境的優勢仍在；它決定範圍，不產生優勢 | 非核心（輸出） |
| 向下縮窄循環 | 已有具體情境時不需要；只用在尚未有情境時的搜尋 | 非核心（搜尋策略） |
| 不夠特別就再縮窄的循環 | 單輪已可得到優勢；屬迭代 | 非核心 |
| 十步中的下游執行 | 與優勢無關 | 非核心 |
