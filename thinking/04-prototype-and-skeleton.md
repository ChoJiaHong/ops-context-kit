# 04 原模型當原型：可替換的槽位與核心骨架

結論：原模型可以當成一個「比較式問題重構」的範本，衍生不同用途的版本。每次轉換只要重新決定三件事：參照情境是什麼、差異從哪裡來、優勢怎麼判斷。骨架本身可以再抽象成兩層：上層是通用的對比式推理，下層是專門「改造通用解」的版本。

## 1. 固定的骨架與可替換的槽位

原模型真正固定的是一副骨架：

> 參照的一般情境 → 那裡的既有做法 → 它的瓶頸 → 你的情境和一般情境的差異 → 差異能不能解掉瓶頸 → 新做法 → 它在多大範圍內仍有優勢 → 硬湊檢驗

換用途時，只替換幾個槽位：

| 槽位 | 創新縮窄法（原型） | [02 失敗驅動縮窄法](02-failure-driven-narrowing.md) | [03 人機差異設計法](03-human-agent-design.md) |
|---|---|---|---|
| 參照的一般情境 | 一般化的大問題 | Claude 的預設行為加上現有設定 | 人類團隊怎麼做 |
| 差異從哪裡來 | 縮窄到特定地點、族群 | 一次真實失敗的觸發條件 | 工作者從人變成 agent（固定清單） |
| 差異的主要類型 | 資源 | 偏好、事實、限制 | 資源居多 |
| 向上泛化的用途 | 新方案的優勢範圍 | 一條規則的適用範圍 | 新工作方式的適用範圍 |
| 硬湊檢驗問的是 | 拿掉在地特色還成立嗎 | 拿掉你的情境還成立嗎 | 換回人類還成立嗎 |
| 產出 | 新方案 | 範圍剛好的修正 | 新的工作方式 |

## 2. 轉換會不會成功，看三件事

1. **有沒有清楚的參照情境**，而且那裡有既有做法可以比較。找不到，骨架就沒有起點。
2. **差異是不是資源型，而且能列成清單**。資源型差異才會產生新東西；清單固定的話，每次套用都很便宜。人機差異設計法兩點都成立，所以轉換後很順。
3. **有沒有辦法判斷「優勢」**。原型把它留成未解問題。失敗驅動縮窄法用你給的權重加真實事件補上；沒有判斷方法，向上泛化就只是猜。

要注意：骨架可以沿用，「資訊從哪裡來」不能照抄。原型的資訊來自分析者已知的情境描述，所以擅長產生點子；用途一旦變成優化，輸入就必須換成真實資料，否則只是在重新排列已知的東西。

## 3. 上層骨架：參照、差異、作用、範圍、必要

去掉「創新」「在地」「提案」這些外衣後，剩下五個動作：

1. **參照**：找一個已經有答案的參照情境 R。
2. **差異**：列出目標情境 T 和 R 的不同。
3. **作用**：判斷哪些差異會改變 R 的答案，依這些差異修正，得到 T 的答案。
4. **範圍**：讓 T 往 R 靠近或遠離，找出修正後的答案仍比 R 的答案好的最大範圍。
5. **必要**：反事實檢驗。拿掉那些差異，答案還成立嗎？成立的話，這個答案只是 R 的答案換了名字。

這副骨架不只適用於提案：

| 用途 | 參照 R | 差異 | 修正後的答案 | 必要性問的是 |
|---|---|---|---|---|
| 創新（原型） | 一般問題的既有解法 | 在地資源 | 新方案 | 拿掉在地特色還成立嗎 |
| 除錯 | 上次正常的系統 | 最近改了什麼 | 故障原因 | 撤掉那個改動，問題會消失嗎 |
| 預測 | 同類案例的歷史結果 | 這個案例的特殊之處 | 調整後的預估 | 不做調整，預估會差多少 |
| 學新東西 | 已經懂的相近概念 | 新概念哪裡不一樣 | 對新概念的理解 | 只靠舊概念能不能解釋 |
| 調 agent 設定 | Claude 的預設行為 | 你的情境 | 範圍剛好的規則 | 拿掉你的情境，規則還需要嗎 |

這些用途各自都有成熟的做法，例如除錯先查最近的改動、預測先看同類案例的基準再依個案調整。骨架和它們吻合，代表抓到的是共通結構。

## 4. 下層骨架：改造通用解

[05 自我抽象實驗](05-self-abstraction-experiment.md)裡，六份獨立方案都收斂到：**基準解 → 瓶頸 → 情境差異 → 配對 → 改造 → 檢驗**。評分最高的方案多抓到兩點：

1. **綁定假設**：通用解是為一般情境最佳化的，所以一定預設了某些條件，瓶頸就從這些預設來。具體情境的價值，在於它違反了其中某條預設。
2. **功能重述**：把差異從「它是什麼」改寫成「它能對瓶頸做什麼」，例如林業鐵路變成「能深入目標區的移動補給載具」。三份筆記的步驟清單都沒有這一步，但例子裡的突破全靠它。

這兩點也回答了原筆記自列的未解問題「下一次往哪個維度縮窄」：從瓶頸反推通用解預設了什麼，再照那張清單去查情境，不必盲目縮窄。

**最適合的問題 P\***：目標固定，已有成熟的通用解，它在某個具體情境仍可用但不是最佳。成立條件：

- 瓶頸來自通用解對一般情境的預設，不是技術本身的極限。
- 情境有看得到、穩定、常被忽略的特殊資產或條件。
- 新舊方案可以用同一個指標比較。

不適用：沒有基準可比較的全新問題、瓶頸是物理或理論極限、多因的行為或制度問題、沒有特殊條件的標準化情境。

## 5. 兩層的關係

- **上層**（參照、差異、作用、範圍、必要）：通用的對比式推理。除錯、預測、學習都適用。
- **下層**（加上綁定假設與功能重述的「改造通用解」）：專門用來在已有成熟解的領域做出更好的方案。診斷型問題（例如服務變慢找原因）不適用，因為它的關鍵是蒐證，不是改造。

自我抽象實驗裡唯一沒有定論的「診斷算不算 P\*」，就來自這兩個層次的差別：抽到下層時不算，抽到上層時算。
